# Mote 0.0.62 DEV

本版集中修复跨端上传、检索响应、实时界面刷新及后台执行恢复，继续发布 Mac DEV ZIP 和 Android DEV APK；中央端从源码部署。

- 文件批量确认按条结算，永久拒收项单独显示，成功文件和后续笔记继续同步；修复旧接口降级及导入创建重试的幂等性。
- 本地来源队列、目录 checkpoint 改为增量写入，避免单条上传复制十万项目录。网页上传支持暂停、恢复和离开页面取消。
- 向量全范围扫描和大文件最终校验移至有界工作进程。检索超时明确降级，保留历史范围及长文本编码覆盖说明；64/100/512 MiB 文件提交期间前台请求可继续处理。
- 实时刷新合并普通失效事件，慢请求仍可展示；保留认证、作用域切换的取消隔离，完善上传失败、预算和 Memory 操作反馈。
- 删除或修改证据时，按实际读取证据及派生祖先失效有关回答和摘要，保留无关对话。预算按每次请求的 UTC 日期计量，操作总额跨日累计。
- 过期租约不能提交结果、失败状态或迟到进度。Memory 超时保留明确原因，显式重试最多两层拆批，并保留原始范围、检查点和失败历史。
- 补充社区插件示例与接入文档，验证加载、卸载、缓存、派生失效和重装恢复。

发布前一轮验证累计 1,208 项自动化测试通过，1 项 opt-in 跳过；Android 188 项 JVM、26 项专用模拟器检查，以及跨端集成和界面演练通过。详细范围与性能数据见[项目复查报告](https://github.com/utopiafar/mote/blob/v0.0.62/docs/review-2026-09-23.md)。本次发布仅额外核对版本一致性，不重复本地大规模测试；安装包由 GitHub CI 构建和验证。

**已知限制：长周期 Memory 尚未通过整体验收。** 指定 Luna Max 的 45 天合成 Persona 测试完成 41/45 篇日志抽取，形成 7 条具体候选记忆，但抽取/汇总仍有 300 秒超时，旧、新评审安排仍可能同时活跃。独立评审 5/7 通过，不能将一次正确问答当作整条整理流程稳定。详见[真实模型评估](https://github.com/utopiafar/mote/blob/v0.0.62/docs/validation/2026-09-23/persona-memory-results.md)。未进行真机长期后台或续航测试。
