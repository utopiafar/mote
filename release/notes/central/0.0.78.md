# Mote central 0.0.78 DEV

- Coding 对话的 AI 读取面剔除工具调用参数、工具输出与完整宿主上下文，保留用户/助手文字及来源时间、channel、说话人依据；私有原始归档与模型读取授权分离。旧工具正文及其派生产物在清洁重建前不作为查询或 Memory 输入。
- 既有已授权 Memory 任务在后台统一理解清洁对话，产出摘要、工作记录、可选事件及 Memory 候选，再独立评审 Memory。自动处理依赖来源/recipe 的 Memory 开关与接收授权；升级、重建或后来开启 Memory 不为历史输入自动补发模型权限。所选 extract policy 指导候选，其指纹进入统一理解任务身份。
- 摘要、工作记录与事件进入可读检索正文，保留 actor、status、sourceTime、精确原文引用、范围与不确定性；Memory 候选正文只供独立评审。助手报告不冒充独立验证，不从消息间隔推算劳动时长。Ask 和洞察继续通过只读工具按需展开证据。
- 包含尚未发布的中央变化：资料库优先的工作区导航与浏览交互（#51），DeepSeek Harness / Cordis 升级及原生 Messages 回归覆盖（#52），以及独立组件发布与协议兼容边界（#50）。
- 新建 profile 默认使用已登录的 Codex `gpt-6.1-sol`；现有 profile 的模型配置不因此重置。DeepSeek 官方接口迁移至原生 Messages 地址，自定义网关保持其配置路径。
- 首次使用 `central-v*` 发布流，公开附件为中央源码包。此前统一 DEV Release 仅附客户端安装包，中央通过源码更新；旧 `v0.0.53` 是最后附有 server 源码包的统一 Release，本包也包含其后中央源码的累计变化。

本地 `npm run check:local`、`npm run build:central` 和 `npm run release:verify -- central` 均通过。自动验收使用生成 fixture；未进行真机或真实在线模型验证。GitHub 维持现有 MVP 检查暂停策略，发布工作流仍执行构建、版本、源码包结构和附件完整性校验。

从源码包部署，沿用现有 profile、配置、凭据与模型；历史中央版本是否可直接升级仍由后端 epoch 校验决定，本包不新增数据迁移或自动清空流程。不包含个人资料或新的在线签名更新通道。安装与回退见 `docs/updating.md`，Coding 链路见 `docs/source-pipelines.md`。
