# 客户端设置与图片保存位置

Android 和 Mac 在保存设置后应用新的采样间隔、画质、隐私规则、OCR 与同步策略。更新时会结束旧配置下尚未完成的采集，按新配置恢复任务；原本停止的采集不会因为保存设置而自动开始。需要重新加载的本地识别组件由应用协调处理。

设置草稿只属于当前子页面。返回上级菜单、切换页面或离开页面后，未保存的修改会丢弃，设置菜单不保留底部保存栏。随手记草稿仍按原有规则单独保存。扫码或导入邀请成功后，设置页重新读取已保存连接；旧表单不能覆盖新的节点地址或凭据。

## 图片在哪里

客户端“采集与存储”中的保存位置用于本机截图队列，同时包含对应记录、未完成的 OCR 和上传确认状态。它不是手机相册，也不决定中央节点的归档目录。

Android 默认在上传与 OCR 最终确认后继续保留本机副本 7 天，可在「设置 → 本机存储」调整为 0–365 天，0 表示确认后立即清理。每条记录按最终确认时的设置确定到期时间；更改设置影响后续确认的记录。启动时和每小时后台任务清理到期副本，系统可能推迟执行。未上传、未完成 OCR 和冲突记录不会自动清理，共用图片直到最后一条引用清理后才删除。Mac 仍按原有上传确认策略处理本机队列。“采集记录”中的“本机”查看尚留在客户端的数据，“中央已归档”查看已经上传的记录。需要长期保留或迁移中央资料库时，使用中央节点自己的存储与备份设置。

Mac 可通过系统文件夹选择器选择位置，应用在所选文件夹下创建独立的 Mote 目录，并提供当前位置与打开文件夹入口。队列目录迁移不会移动模型权重、访问令牌或中央资料库。

Android 可选择应用内部空间，以及系统提供的本机或存储卡应用专用空间。界面显示实际位置与可用容量；记录默认明文保存，可在开发者选项开启本地内容加密。外部介质断开后会报告存储不可用，不会自动改到一个新的空目录。可选位置取决于设备实际提供的存储卷。

## 更改保存位置

Mac 选择新位置并保存设置后，或 Android 点击“迁移并应用”后，应用暂时协调采集、OCR 与上传，将现有队列复制并校验，再持久保存新位置。待 OCR 图片、随手记和活动记录、上传确认及原节点归属一并保留。迁移失败时保留已有资料，并显示错误；不会通过重建空队列把失败显示成成功。

Mac 的图片位置和节点连接需要分别保存。如果提示提交状态需要恢复，请使用“重新打开 Mote”入口；应用会读取持久配置并验证所选队列，再清理旧副本。重新打开后采集保持停止，可确认状态后开始。

打开文件夹可用于定位数据，不应在应用运行时手工移动、编辑或删除队列文件。Mac 的队列使用应用私有文件权限，截图文件本身未启用应用层加密；Android 本地内容加密可选；连接凭据始终通过设备密钥保护。磁盘加密及中央图片加密属于各自独立设置。

## 图片压缩预览

Mac 在「开发者选项 → 图像与资源优化」进入独立压缩预览页；Android 在开发者选项打开「图片压缩预览」。调整 JPEG 质量（40–95）与最长边（640–2560），界面用实际编码结果显示原始与输出像素、边长缩放比例、PNG/JPEG 文件大小，以及输出占原图的百分比。JPEG 质量参数不等于文件压缩百分比；某些参数下文件也可能变大。

Mac 支持适应窗口、100%、200%、400% 对照查看与同步滚动；Android 可点击任一图片进入缩放查看器，双指缩放、拖动、双击复位。点击应用将参数带回设置草稿，保存设置后才用于采集。

预览样张由文字、渐变和细线生成，只在内存中编码，不读取当前屏幕或历史截图，不进入上传队列。它用于比较编码和缩放效果，不能预测每一张真实截图的文件大小。

## 系统授权边界

Android 普通设置变更在已有投屏会话内应用。切换到需要新投屏会话的采集方式，或系统已结束原授权时，应用引导系统授权流程；不能绕过系统确认。Android 14 及以上的投屏授权不能重复创建会话，现有会话的尺寸变化应更新原虚拟显示与输出表面。[Android 官方投屏说明](https://developer.android.com/media/grow/media-projection)

Android 应用专用外部空间可能随存储卡卸载而不可用，卸载应用也会删除应用专用文件。目录选择不会改变系统的这些存储规则。[Android 官方应用文件说明](https://developer.android.com/training/data-storage/app-specific)

### Android 图片去重

在「采集与存储 → 图像与文字识别」中选择关闭（默认）、精确、保守、均衡或激进。使用 SHA-256、dHash 和缩略图像素/块/行列差异，参考截图去重算法的四档阈值。比较隐私处理后、JPEG 编码前的画面；近似档位最长边采样为 96px，精确档使用完整输出像素。没有额外裁剪系统栏。

与当前应用最近成功入队的非重复画面比较；重复帧不推进基准。应用、尺寸或配置变化、暂停、服务重启会重建基准，签名仅留在内存。命中时仍记录本次时间、应用和采样时长，保存去重档位标记，省略图片与 OCR 文本，不安排延迟 OCR。关闭可选设备元数据时仍保留最小去重标记。隐私检查照常执行。此设置当前适用于 Android，服务端需同步升级以接收纯元数据截图记录。

联合回归：构建 Android development 与 developmentAndroidTest APK、共享包/服务端/Web 和桌面 TypeScript 后，启动专用 `mote_fixture_api35` 模拟器，运行 `node_modules/.bin/electron scripts/dedupe-cross-e2e.cjs`。可用 `MOTE_FIXTURE_SERIAL` 指定模拟器序号。测试使用生成画面并关闭模型审查，经过真实 Android 上传队列、临时本地服务端、桌面客户端和 Web 页面；报告位于 `apps/android/app/build/reports/dedupe-cross/`，不纳入版本控制。

### 图片去重调试预览

Android 在「设置 → 关于与更新 → 开发者选项」提供「临时保留图片去重对比记录」开关，默认关闭。保存开启后，还需要在采集设置中选择一个去重档位；关闭去重时不会生成对比记录。

调试记录显示被去重画面和它实际比较的基准画面、各自采集时间、采集记录 ID、去重档位和算法判定依据。基准是同应用最近成功入队的非重复画面，连续重复不会推进基准。两张预览均来自通过隐私检查、遮罩及缩放后的图像，以 JPEG 临时保存；不会保留隐私处理前的原图。

界面显示 64 位 dHash 距离及其换算的哈希相似度，同时列出变化像素比例、变化区块、行列数量与当前阈值。相似度不是模型置信度；去重由这些指标共同决定。近似档位的「哈希完全一致」指采样图像，不表示原尺寸图像逐像素相同。

对比记录存放在应用私有、排除系统备份的加密目录，与上传队列分开，不上传中央节点或进入诊断导出。最多保留 20 组、32 MiB；24 小时后不再展示，读取、采集及后台维护时清理过期文件，系统可能延后后台清理。支持删除单组和全部清空；保存关闭调试选项也会清空。调试仍开启时，后续新采样可以产生新记录。

## Android 配置与本机数据导入导出

「设置 → 导入与导出」通过系统文件选择器保存和打开文件：

- **配置 JSON**：版本化的采集、应用规则、遮罩、画质、OCR、同步、模型与诊断设置。默认不携带节点令牌；可显式选择包含令牌，文件为明文。导入时先校验类型、范围、格式版本并预览，再应用；不同地址且未携带令牌时会清空旧令牌，避免发往新地址。设备 ID、采集开停状态、Android 权限及文件/日历授权不会从配置文件复制。更新渠道设置仍在更新页单独管理。
- **记录 ZIP**：包含本机仍保留的截图、活动、通知、媒体、随手记及已完成的延迟 OCR 结果，按记录 ID 和图片 SHA-256 存放。导出逐条读取一致的记录与图片，不阻塞整份资料库；导出期间已到期清理的条目可能不在备份内，完成时显示实际条数。ZIP 为明文，不含中央资料库、来源文件原件、未提交草稿或模型权重。
- **导入记录**：先在缓存目录校验全部路径、重复条目、总量、图片散列与记录结构，再合并到当前队列。备份必须属于同一中央节点，已有同 ID 内容冲突会在写入前拒绝。重复导入不产生重复记录，已有资料不会覆盖。同步切为手动，恢复的新增记录使用原 ID 等待确认。若实际写入遇到空间不足，已导入部分保留，可释放空间后重试同一备份。

保存普通设置不检查远端服务，也不重复解密未变更的令牌。持久保存并恢复采集状态后即返回成功，后台继续安排同步。存储迁移、节点切换及尚未结束的采集处理仍需完成必要的协调，界面显示对应进度。

## Android 队列与原始日志

概览的「待上传队列」打开独立子页面，按采集/随手记或日历/文件来源每页显示 30 条，包含时间、应用或文件名、待上传/待 OCR/冲突状态，以及当前网络或电量等待原因。已完成同步但仍在本机保留期内的记录不计入待上传队列。

日志查看器读取本机 `mote.log` 原文件，格式为 `UTC时间 LEVEL [线程] 模块 - 事件 数值字段`，支持 DEBUG/INFO/WARN/ERROR 筛选和复制。原始运行日志独立于上传正文及可选数值诊断，最多保留 1000 行，轮转时丢弃最旧一批。仅记录固定事件码、阶段和数值，不记录截图、OCR、笔记、令牌或异常正文。
