# 上传审查与中央感知

端侧负责应用范围、固定遮挡、轻量去重、可选文字审查和可靠上传。完整 OCR、图片语义理解在中央运行。查询先读派生文字，只有模型显式请求、用户开启原图披露时才发送对应图片。

## 端侧设置

Mac 和 Android 的隐私页面集中显示应用采集范围、固定遮罩、上传文字审查与失败策略。

- 文字审查默认开启、规则为空；空规则或关闭开关不会调用 OCR。每行规则按原文精确包含匹配，不做语义分类或隐式黑名单。
- 明确命中规则：不保存、不上传。审查异常：默认暂存待复核，也可选择不保存或允许上传。
- 待复核截图计入本机容量，普通同步重试、重启和关闭审查都不能放行。Mac 在隐私页查看原图并逐条允许上传或丢弃；Android 在同步恢复页查看本机副本并明确放行，记录页可删除。
- 应用范围和固定遮挡仍按用户设置执行，不受文字审查开关影响。应用身份无法满足已配置限制时，截图前就停止，无法暂存尚未取得的像素。
- 本机 OCR 只为文字规则服务，识别出的文字不写入新事件，不作为中央 OCR 上传。本机 VLM 与附加审查 URL 暂停执行，代码保留 `VisualReviewProvider` 接口。没有提供 NSFW 语义审查保证。
- 新截图不创建本机补识别任务。旧版已存在的 OCR 队列保留兼容处理代码；它们不是新链路的一部分。

## 中央设置与 Worker

中央设置 → 模块与模型 → 中央感知。配置 OCR Worker、语义 Worker、模型/配置版本及调度。新截图默认使用受管理的本地 PP-OCRv5 OCR Worker（默认 `http://127.0.0.1:9010/ocr`）。Native profile 启动时在后台自动准备独立运行时（首次需网络），Docker 构建包含依赖；模型需在设置页显式下载或用 CLI 导入。模型缺失时任务显示 `model_missing`，原件仍可靠归档，安装后继续；Worker 尚未就绪时等待，不消耗识别重试次数。旧截图不自动回扫，需预览确认（每批最多 100 张）或单条重试。详见 [安装与验收边界](ocr-asr-implementation-plan.md)。

两类 Worker 复用现有常驻 Cordis `image.http` 处理接口。OCR Worker 返回识别文字，语义 Worker 返回图片理解与不确定性。服务应常驻运行，不能每张图重复启动模型。HTTP 请求为图片二进制，包含 `X-Mote-Media-Type`；返回现有 Transcript JSON：

```json
{"durationMs":0,"segments":[{"startMs":0,"endMs":0,"text":"识别文字或模型描述"}]}
```

空 segments 表示成功但没有文字，与失败或尚未处理区分。返回文字最多 100,000 字符，处理超时 120 秒；禁止重定向。受管理 OCR 请求使用 profile 派生的内部 Bearer 令牌；中央感知设置不提供任意自定义 Worker API key 输入，外部服务需自行配置部署层保护。非回环地址必须 HTTPS，且单独开启允许外部处理；不自动改用外部服务。

语义处理支持手动（默认）、实时后台、分批等待。分批按每张输入最短等待时间与每轮条数调度，不把相邻截图硬编码成同一主题。后台每 5 秒检查，最多处理配置条数；工作完成时间受 Worker 吞吐影响。最近任务可单独重试或重处理。换引擎/模型时修改配置版本，使缓存失效；已有成功结果不会自动全部重算。

## 持久性、结果与证据

- SQLite 插入截图的同一事务通过触发器创建 OCR 和语义任务，可靠保存后即可确认上传。
- `perception_results` 保存独立版本、输入哈希、引擎/版本、配置指纹、生成时间和处理产物，不改写 captures 原始 JSON 或上传指纹。
- 完全相同图像和处理配置可复用结果；不同观察事件保持各自时间。近似去重不借用旧图识别结论。
- 处理失败退避重试，最多 4 次，之后等用户重试。重启将运行中任务恢复待处理。配置改变中止旧任务，提交前复查配置与原图存续；删除后禁止写回。
- OCR 就绪立即更新全文索引并触发中央变化流；语义理解独立完成。重算使依赖记忆需要重验。JSON 导出/恢复包含派生版本，原始事件仍保持不变。
- Android 在现有同步期间有界拉取 `/api/capture-browser/updates`，复用中央游标，缓存文字预览和处理状态；不新增高频轮询。Collector 仅能拉取本设备，删除仍走已有 reconcile。完整文字在中央记录页读取。Mac 上传确认后释放本地发送队列，通过中央记录页按需读取处理结果。

## 模型渐进披露

搜索和时间线不包含图片字节；显示 OCR、摘要、可用层级与处理状态。`evidence` 可分页读取 OCR 或 `layer=semantic` 的理解结果。二者分别属于 L1 机器提取与 L2 模型解释，均不是独立客观事实。现有长期记忆属于 L3。

`read_image` 只接受本轮已发现并展开文字的记录 ID，不接受路径或 URL；重查时间/设备范围和删除状态，每轮最多 4 张，每张至多 8 MiB 输入。独立的“允许查询模型按需读取原图”默认关闭，开启后图片可能发往所选查询模型服务。需要支持图像的模型；不支持的模型会报错，不以图片地址冒充模型已看图。Harness 使用隔离会话附件，Codex App Server 使用图像内容项。查询工具保持只读。

## 验证边界

0.0.42 的生成图片与模拟 OCR/模型服务验证覆盖入库、缓存、检索、幂等、删除与多模态传输。后续 Native macOS arm64 真实本地 OCR/ASR 的生成素材检查另见 [运行时验收](ocr-asr-implementation-plan.md#验收边界)；这些不是个人截图、物理手机功耗或识别质量基准。本次文档复查没有重新执行真实模型测试。
