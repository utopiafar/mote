# 采集、保存与上传

Mote 的采集和上传是两个独立过程。Android 与 macOS 都可以在未填写服务端 URL、未保存令牌或网络不可用时，先把采集记录、随手记和已选择的本地来源保存到本机。连接中央节点是上传的前提，不是本地记录的前提。截图仍需系统权限，并经过应用规则、固定遮挡与可选的文字规则审查；不要求端侧 Qwen 模型。

## 从要做的事开始

两个客户端的一级导航为「首页 / 内容 / 问一问」。首页与「添加」入口提供相同的四个动作：同步文件夹、导入文件、记录屏幕、随手记。来源管理从首页进入；发送记录和失败原因属于内容状态与首页状态详情，不再占用独立主导航。完整交互决策与被取代的旧入口见 [行动优先 ADR](adr-client-action-first.md)。

文件夹默认持续检查所选范围。新导入的单个文件默认只保存一次；勾选「以后修改，也自动同步」才持续检查。已有来源继续采用原有持续同步方式。单次导入固定本机快照之后，重启、失败重试和发送恢复继续使用同一待传版本，不因源文件后续修改生成新版本。尚未完成读取或快照保存的任务不能显示导入完成。客户端和中央不按累计来源数量拒绝新增任务，已完成的一次性导入不会耗尽来源名额；当前队列容量、授权、扫描调度和单输入传输约束继续生效。

任务确认保留所选范围、已有文件是否纳入、中央地址和原件保留方式。「中央提取正文，不保留原件」仍需要发送完整文件供中央处理；它不表示只发送摘要。引用模式不读取正文；原件归档与内容索引仍是不同的保存选择。采样频率、画质、去重、OCR、打包与诊断留在高级设置，隐私范围和数据去向不能被高级设置折叠隐藏。

暂停操作分别说明范围：「暂停屏幕记录」只停止新增屏幕/应用记录；「暂停这个来源」停止该来源的读取与发送，已有待传版本保留；「暂停全部发送」保留当前同步策略，暂停记录、来源和设备状态的发送，本机记录与来源读取继续。恢复发送沿用原策略；暂停期间明确同步也不会越过暂停。完全退出仍停止本机进程。

## 四种上传方式

在客户端设置中选择上传方式。macOS 的入口为「设置 → 上传与同步」，Android 的入口为「设置 → 连接与同步」。模式共用 `syncMode`、`syncIntervalMinutes`、`syncBatchSize`，新安装默认积攒一批、最长等待 1 分钟、100 条，并开启打包上传；已有显式保存的设置保留。

| 方式 | 自动上传条件 | 适用操作 |
| --- | --- | --- |
| 实时 | 本机保存后尽快发送；失败保留并退避重试 | 希望中央仓库及时更新 |
| 定时 | 到达设定间隔后发送积存记录 | 15 分钟、30 分钟、1 小时等；支持 1–1440 分钟 |
| 积攒一批 | 达到记录数，或最早待传记录达到最长等待时间，取先满足者 | 默认 100 条 / 最长 1 分钟；数量支持 1–500 |
| 仅手动 | 不自动上传记录或发送设备状态；显式点击上传时执行 | 希望自己决定每次同步时机 |

“积攒一批”控制发送时机，传输可用 bundle、batch 或单条接口，仍逐条校验服务器确认，不能把 HTTP 200 当作整批成功。截图、应用活动、随手记、本地文件与日历的待传内容共同参与调度；空来源注册等需要同步的来源状态也不能无限等待新正文。来源扫描频率与上传频率分别配置。

「立即上传」以及来源页明确标注的检查并上传操作会提前触发一次同步，不会把保存的上传模式改为实时。Android 仍遵守用户选择的联网限制，例如仅使用非计费网络；“立即”不保证绕过系统节电或任务调度。

## 状态如何解释

| 情况 | 本地采集 | 上传 |
| --- | --- | --- |
| 没有节点 URL 或凭据 | 可以手动开始；本机规则照常生效 | 显示仅保存在本机，不循环尝试缺失的连接 |
| 已连接但暂时断网 | 继续保存，直到队列上限 | 保留原记录；自动模式重试，手动模式等用户触发 |
| 尚未到定时 / 批量条件 | 正常记录 | 显示待传数量与计划时间 |
| 停止采集 | 不再产生屏幕或应用活动记录 | 已有记录仍按所选策略处理；随手记与来源可独立工作 |
| 隐私过滤、缺少权限或文字审查异常 | 跳过对应内容或暂停，并说明原因 | 已有合规记录仍可上传 |
| 本地队列达到上限 | 暂停或停止新增，保留已有数据 | 上传仍可释放容量，不静默覆盖最旧记录 |
| 服务器未返回匹配确认 | 原 UUID、版本、时间与正文保留 | 不显示成功，不清除待传内容 |

首页分别显示屏幕记录状态和发送状态。待传总量包含本地来源；截图/随手记队列的容量限制与来源缓存限额分别显示。内容详情区分本机已保存、中央已收到和中央整理/索引状态；匹配的 ACK 只证明收到，不能证明已经可以检索或提问。中央未提供足够状态或当前无法联网时显示未知/待确认，不补造进度。服务端只能展示最后收到的状态与时间：离线、休眠、仅手动模式都会让状态变旧，“最近联系”不等于设备此刻正在采集。旧客户端未报告上传状态时显示未知，不推断为实时同步。

## OCR 节能与采集预览

新截图的完整 OCR 在中央运行。端侧仅在文字规则审查开启且规则非空时调用本机 OCR，识别文字不写入新截图事件；新截图不创建本机补识别任务。中央新截图默认安排 OCR，Worker 或模型缺失时先保存原件并等待。具体安装、旧截图回填和结果状态见 [中央感知](central-perception.md)。

当前本机格式 3 不读取旧 OCR 队列，不补写旧事件。完整图片识别由中央处理，本机 OCR 只服务明确的隐私文字规则。

客户端采集记录区分本机副本与中央归档，可按日期、Session 或应用相册浏览，图片和文字按需加载。新本机截图没有正文不代表上传失败；中央 OCR 是独立派生产物，上传确认也不代表识别已经完成。当前设备邀请签发 owner 凭据，供采集同步和中央归档/问答共用；设备筛选限定当前阅读视图，授权仍由中央身份与能力决定。

## 第一次连接与换节点

尚未绑定节点的新本机积存记录，需要明确确认目的地后才能归属第一个中央节点。邀请确认页面沿用明确地址确认；手动地址配置另有积存记录确认。编辑目标地址或凭据后需重新确认。

已绑定的待传记录不会因为清空 URL、编辑令牌或重启而变成“未绑定”。更换到其他节点前，应完成同步或备份处理旧队列；同节点重新授权仍走独立的确认流程。无法确定目的地的旧版本积存数据不会自动重新归属。备份与导入是明确的数据迁移操作，队列与来源缓存应分别按对应客户端说明备份。

## 配置交互

- Android 与 Mac 保存设置后自动协调运行中的采集、OCR 与同步，再按原开停意图应用新配置；不需要手动暂停后重新开始。图片队列可通过“采集与存储”中的位置设置迁移，具体目录范围与系统授权见 [客户端设置与图片位置](client-settings-and-storage.md)。
- 常用频率、电量阈值、容量、画质和上传参数使用预设选择；已有自定义值完整保留。
- 应用隐私规则通过已安装应用选择器添加，再选择完整内容、仅活动或不记录。找不到的应用仍可在高级入口填写精确 ID。
- 屏幕遮挡提供常用预设和可调整的区域示意。示意图不读取真实屏幕；需要按自己的屏幕布局调整位置和比例。高级矩形参数仍可编辑。
- macOS 本地来源支持文件类型勾选、原生路径选择和保留方式选择。自定义排除路径与遮盖原文由用户明确指定，不由关键词或语义猜测生成。
- 服务端按日常使用、设备与来源管理、设置分层。可用选择器生成部署配置变更；当前配置与未生效草稿分别展示，部署变量修改后仍须重启服务。

## 平台调度边界

macOS App 驻留运行时检查队列，停止采集不等于退出 App。完全退出、系统休眠时不能保证执行计划，恢复运行后根据持久队列与同步检查点继续判断。

Android 使用 WorkManager 和系统网络、电量约束。计划时间是最早符合策略的时间，不是精确闹钟；Doze、后台限制、网络条件可能延迟执行。强制停止应用或系统限制后的恢复遵循 Android 行为，不能保证在指定秒数内上传。

本轮回归使用生成资料、隔离配置、本机 HTTP fixture 与专用模拟器；不以真实个人屏幕、个人日历或真实模型调用作为测试素材。具体已执行结果记录在客户端导航文档与对应测试脚本中。
