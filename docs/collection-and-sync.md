# 采集、保存与上传

Mote 的采集和上传是两个独立过程。Android 与 macOS 都可以在未填写服务端 URL、未保存令牌或网络不可用时，先把采集记录、随手记和已选择的本地来源保存到本机。连接中央节点是上传的前提，不是本地记录的前提。截图仍需系统权限，并经过已启用的隐私规则与本地模型审查。

## 四种上传方式

在客户端设置中选择上传方式。macOS 的入口为「设置 → 上传与同步」，Android 的入口为「设置 → 连接与同步」。模式共用 `syncMode`、`syncIntervalMinutes`、`syncBatchSize`，默认实时、15 分钟、20 条。

| 方式 | 自动上传条件 | 适用操作 |
| --- | --- | --- |
| 实时 | 本机保存后尽快发送；失败保留并退避重试 | 希望中央仓库及时更新 |
| 定时 | 到达设定间隔后发送积存记录 | 15 分钟、30 分钟、1 小时等；支持 15–1440 分钟 |
| 积攒一批 | 达到记录数，或最早待传记录达到最长等待时间，取先满足者 | 默认 20 条 / 最长 15 分钟；数量支持 1–500 |
| 仅手动 | 不自动上传记录或发送设备状态；显式点击上传时执行 | 希望自己决定每次同步时机 |

“积攒一批”控制发送时机，传输仍逐条校验服务器确认，不是一个不可分割的批量 HTTP 请求。截图、应用活动、随手记、本地文件与日历的待传内容共同参与调度；空来源注册等需要同步的来源状态也不能无限等待新正文。来源扫描频率与上传频率分别配置。

「立即上传」以及来源页明确标注的检查并上传操作会提前触发一次同步，不会把保存的上传模式改为实时。Android 仍遵守用户选择的联网限制，例如仅使用非计费网络；“立即”不保证绕过系统节电或任务调度。

## 状态如何解释

| 情况 | 本地采集 | 上传 |
| --- | --- | --- |
| 没有节点 URL 或凭据 | 可以手动开始；本机规则照常生效 | 显示仅保存在本机，不循环尝试缺失的连接 |
| 已连接但暂时断网 | 继续保存，直到队列上限 | 保留原记录；自动模式重试，手动模式等用户触发 |
| 尚未到定时 / 批量条件 | 正常记录 | 显示待传数量与计划时间 |
| 停止采集 | 不再产生屏幕或应用活动记录 | 已有记录仍按所选策略处理；随手记与来源可独立工作 |
| 隐私过滤、缺少权限或模型不可用 | 跳过对应内容或暂停，并说明原因 | 已有合规记录仍可上传 |
| 本地队列达到上限 | 暂停或停止新增，保留已有数据 | 上传仍可释放容量，不静默覆盖最旧记录 |
| 服务器未返回匹配确认 | 原 UUID、版本、时间与正文保留 | 不显示成功，不清除待传内容 |

概览分别显示采集状态和上传状态。待传总量包含本地来源；截图/随手记队列的容量限制与来源缓存限额分别显示。服务端只能展示最后收到的状态与时间：离线、休眠、仅手动模式都会让状态变旧，“最近联系”不等于设备此刻正在采集。旧客户端未报告上传状态时显示未知，不推断为实时同步。

## OCR 节能与采集预览

Android 与 macOS 的采集设置提供“仅充电时 OCR”。默认关闭以保留原识别行为；开启后，未接电时仍保存经过隐私审查和遮挡的图片，标记为待 OCR，接电后在本机补做文字识别。接通外部电源并已充满也可以处理；Mac 关闭整个 OCR 功能时不执行识别。补做读取已保存图片，不重新截图。

图片可先按上传策略进入中央；在文字补写获得对应记录 ID 的确认前，本机会保留图片和处理任务，计入原存储配额并保持原节点绑定。待处理图片会预留有界的 OCR 结果空间，避免队列满后无法完成识别和释放容量。补做结果单独提交，原始摄取重试仍使用同一份不可变记录，网络中断不会造成同一 ID 的正文冲突。手动同步模式下，识别结果也等待明确同步操作。中央删除的记录不会通过重试复活；单条记录的永久冲突会保留为可查看的失败状态，不阻塞其他记录上传。

客户端“采集记录”区分本机记录与中央已归档记录，可按本地日期查看缩略图并展开原图和文字；中央 Web 的采集记录页提供日期、设备与 OCR 状态筛选。图片和完整文字按需加载，列表分页。旧记录没有明确处理状态时显示未知；“识别完成但没有文字”与“尚未识别”分别显示。采集专用凭据仅能浏览本设备归档，不获得其他设备或管理权限。

停止采集后仍可处理已有 OCR 任务。Mac 需保持 App 运行，休眠或退出后等恢复运行；Android 受 WorkManager、充电约束和系统后台限制调度，不能保证插电即刻完成。

## 第一次连接与换节点

尚未绑定节点的新本机积存记录，需要明确确认目的地后才能归属第一个中央节点。邀请确认页面沿用明确地址确认；手动地址配置另有积存记录确认。编辑目标地址或凭据后需重新确认。

已绑定的待传记录不会因为清空 URL、编辑令牌或重启而变成“未绑定”。更换到其他节点前，应完成同步或备份处理旧队列；同节点重新授权仍走独立的确认流程。无法确定目的地的旧版本积存数据不会自动重新归属。备份与导入是明确的数据迁移操作，队列与来源缓存应分别按对应客户端说明备份。

## 配置交互

- Android 与 Mac 保存设置后自动协调运行中的采集、OCR 与同步，再按原开停意图应用新配置；不需要手动暂停后重新开始。图片队列可通过“采集与存储”中的位置设置迁移，具体目录范围与系统授权见 [客户端设置与图片位置](client-settings-and-storage.md)。
- 常用频率、电量阈值、容量、画质和上传参数使用预设选择；已有自定义值完整保留。
- 应用隐私规则通过已安装应用选择器添加，再选择完整内容、仅活动或不记录。找不到的应用仍可在高级入口填写精确 ID。
- 屏幕遮挡提供常用预设和可调整的区域示意。示意图不读取真实屏幕；需要按自己的屏幕布局调整位置和比例。高级矩形参数仍可编辑。
- macOS 本地来源支持文件类型勾选、原生路径选择和保留方式选择。自定义排除路径与遮盖原文由用户明确指定，不由关键词或语义猜测生成。
- 服务端按日常使用、设备与来源管理、设置分层。可用选择器生成部署配置变更；当前配置与未生效草稿分别展示，部署变量修改后仍须重启服务。

## 平台调度边界

macOS App 驻留运行时检查队列，停止采集不等于退出 App。完全退出、系统休眠时不能保证执行计划，恢复运行后根据持久队列与同步检查点继续判断。

Android 使用 WorkManager 和系统网络、电量约束。计划时间是最早符合策略的时间，不是精确闹钟；Doze、后台限制、网络条件可能延迟执行。强制停止应用或系统限制后的恢复遵循 Android 行为，不能保证在指定秒数内上传。

本轮回归使用生成资料、隔离配置、本机 HTTP fixture 与专用模拟器；不以真实个人屏幕、个人日历或真实模型调用作为测试素材。具体已执行结果记录在客户端导航文档与对应测试脚本中。
