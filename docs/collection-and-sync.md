# 采集、保存与同步

本机记录和上传是两个过程。未连接或断网时，Mac/Android仍可保存获准记录、随手记和来源快照；连接是发送的前提，不是本机记录的前提。当前入口见[设计](design.zh-CN.md)，平台权限见[Mac](desktop.md)和[Android](android.md)。

## 范围与暂停

文件夹默认持续检查；单文件默认一次导入，可选择以后修改也同步。确认页显示范围、是否包含已有资料、完整文件的目的地、来源说明和保留方式。“提取正文不保留原件”仍要发送完整文件；仅引用不读正文。首次选择、规则保存或系统授权都不自动开始屏幕采集。

- 暂停屏幕记录：停止新增屏幕/应用记录，已有队列、其他来源与发送按各自策略继续。
- 暂停单个来源：停止该来源读取与发送，保留待传版本。
- 暂停全部发送：本机记录和来源读取继续，保留原发送策略；明确同步也不越过该暂停。
- 退出应用：停止本机进程。恢复时依持久状态继续，屏幕记录仍需手动开始。

屏幕时长、截图、结构化内容独立选择。字段提取只处理实际采到的可见范围，不上传新的原始Android UI树；本机轻量重叠合并不能变成语义总结。新v3具名字段按自身证据和接收授权进入资料与Memory，不依赖截图OCR，也不因重建历史取得新的模型权限。

隐私检查在持久保存前运行。规则命中丢弃；审查异常按所选失败策略处理，默认待复核。待复核记录不能因普通重试、重启或关闭审查自动放行。[隐私](privacy-and-metadata.md)区分显式精确过滤与模型语义判断。

## 四种发送方式

新安装默认100条或最长等待1分钟，先满足者触发，并开启打包上传。已有显式值保留。

| 方式 | 自动条件 |
| --- | --- |
| 实时 | 本机保存后尽快发送，失败保留并退避。 |
| 定时 | 到设定间隔发送积存记录；间隔1–1440分钟。 |
| 积攒一批 | 达记录数或最早待传记录的最长等待时间；数量1–500。 |
| 仅手动 | 不自动发送记录或设备状态，由用户明确触发。 |

立即上传提前触发一次，不修改保存模式，也不承诺绕过网络、充电、电量或系统后台限制。截图、字段、独立时长、笔记、本地文件和日历共同参加调度；来源扫描频率另行配置，空来源注册也不能无限等新正文。飞书等云连接器由Central同步，不计入本机发送队列。

打包只是传输优化，逐条UUID、revision、散列与ACK仍须匹配。错误确认、失联或部分成功保留未确认项及原始时间/内容，不能仅凭HTTP 200清整批。启动恢复不制造新版本。

## 状态与目的地

本机保存、Central收到、资料发布、索引和Memory分别显示。无节点时说明只在本机，缺配置不循环制造失败请求。断网/策略等待说明条件；本机容量满时保留已有数据并暂停新增，不静默覆盖。当前容量与ACK清理尚未对齐长期保留，见[架构差距](architecture.zh-CN.md#产品方向与实现差距)。

Central只能知道最后一次设备报告与时间；最近联系不等于此刻正在采集。缺少处理状态时显示未知，不补造进度。独立活动整理默认关闭，启用后只处理之后接纳的授权原件；它与Memory授权独立，关闭不会停止原件保存和按需查询。

未绑定积存记录在第一次发送前需确认目的地。绑定后，清空地址、改令牌或重启不会使它变成未绑定。同节点重新授权保留队列与版本；不同节点先处理原队列，不能静默改投。范围收窄后停止超范围待传的方向已确认，当前屏幕队列仍有待调整部分。

## 浏览、媒体与时间

截图Session按同设备/应用的连续观察分组，切应用、未知身份或超过5分钟的间隔分组；恰好5分钟仍属原组。日期与存储范围先限定视图，分页前完成分组。卡片起止是观察跨度，不是连续使用时长或模型话题。App相册按固定15分钟桶；无图记录仍是记录。

网格先显示占位，只加载当前页缩略图；正文和原图按需展开。派生浏览索引/缩略图可由当前原始记录重建，损坏原件不能当缓存删除。Mac图片页当前30项，Web/Android20项；具体字段见[协议](protocol.md#screenshot-albums)。

媒体是独立来源。Android需明确启用并授予通知使用权；可在锁屏时观察系统媒体会话，不录音、不控制播放。播放器应用规则仍生效；仅活动不保留曲目等正文。缺权限、不可用、没有读到会话和未记录分别表示。系统报告的playing不证明用户听到或集中注意力。

只有独立时长/媒体记录累计相应观察区间，截图或心跳快照不重复计时。同设备重叠取并集，不同设备分别相加；分项可能重叠，跨设备总和可以超过钟表时间。计划日历、来源访问时间和播放位置差都不能代替人的实测投入。停止、断连、权限变化或采样缺口不补算空白时间。

## 平台边界

Mac驻留时协调队列；休眠或退出不能保证按时执行。Android的WorkManager服从Doze、OEM后台、网络和电量限制，计划时间是最早符合策略的时间，不是精确闹钟。屏幕停止不等于媒体停止；总停止与各来源开关分别按实际范围生效。

保存设置自动协调运行任务并保持原开停意图。采样、画质与诊断在高级项，隐私范围和数据去向保持可见。前台或旧响应不能覆盖新配置/页面。生成夹具验证协议和调度，真实设备、权限与长期后台行为需各自证据；见[测试操作](testing-runbook.md)。
