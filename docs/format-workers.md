# Bounded format work

ZIP expansion and UTF-8 decoding run in short-lived child processes. The coordinator admits at most two processes and 32 queued requests, with a 120-second deadline that includes the admission wait. Only file identities and private workspace paths cross IPC; credentials and source text are not command-line arguments or logs. File extraction passes its execution cancellation signal through materialization and decoding.

ZIP input remains in the canonical asset store before expansion starts. Workers check the central directory, duplicate/traversal paths, declared and actual sizes, completion and CRC. They stream decompressed chunks to private files rather than returning a whole expanded archive to the HTTP process. The host publishes each file through AssetStore using 4 MiB reads. Partial staging persists its original list and completed archives, reuses existing child identities after interruption, and preserves originals when an archive is invalid. An interruption before every supplied original is archived is explicitly blocked and cannot be mistaken for a complete input set.

File processing and direct UTF-8 imports use the same decoder and Unicode boundary handling. Direct imports generate at most 10,000 records and 32 MiB of JSONL in the worker; the host retains confirmation, identity assignment and database commits. Decoder `utf8-v2` has a versioned source revision, so fixing a Unicode boundary cannot overwrite or conflict with a legacy `utf8-v1` record under the same revision. Original byte hashes and historical source versions remain unchanged.

Directory enumeration is asynchronous. Originals are streamed and their inode, size and high-resolution modification/change times are rechecked before and after reading. Symlinks and files changed after enumeration are rejected. Each successful original is referenced durably before yielding, so expiration of an old upload cannot remove it during staging.

Reviewed manifest parsing, complete validation and original-file hashing now run in the bounded format worker. Import prepare/commit phases are shared execution steps; confirmation remains an explicit user-review boundary. PDF, DOCX and XLSX decoding is shared with Desktop Copy/indexing and central document processing, with explicit locations, coverage limits and unknown authorship/times. See [document and import integration](operation-import-insight-closure.md).
