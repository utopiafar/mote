# Client scheduling and status validation (0.0.61 worktree)

This records the focused client batch, not a release or a full-suite result.

## Implemented

- Desktop managed source scanning and upload now have separate tasks and abort controllers. Source state mutations are serialized, while network waits do not hold that serialization queue. A scan can stage the next revision while an earlier revision waits for its ACK; existing resumable scan checkpoints and deletion rules remain intact.
- Android source dispatch rotates after the last served source. Each source has a 4 MiB / 64-request / 15-second cooperative slice, and a dispatch has an 8 MiB / 128-request bound. A single admitted body may finish beyond the byte/time threshold. Capture uploads have their own bounded slices, give recent capture records a bounded 16 MiB priority burst, then admit historical records. OCR updates yield to captures after four updates, including across continuations with a one-record batch size. Existing source scan and upload workers were already independently scheduled and share a connection read lock; this was preserved.
- Web file import rotates one part (at most 4 MiB) per file. Each file retains its upload ID and verified part hashes on retry. Completed results retain selection order, even when smaller files finish first.
- Shared `native-status` projections keep archive acknowledgment, central processing, source synchronization, and scan coverage separate. Native collector credentials cannot query owner-only Operations; native views explicitly retain unknown central processing. Web evidence reads prove archive presence without claiming that OCR, indexing, or Memory completed. A local scan or registration alone does not establish archive acknowledgment. ACK timestamps are bound to the originating central node.
- Source, Memory, file and evidence reads use authenticated resource identities with cancellation/generation fences. Model selectors now share configuration/catalog reads; file-processing drafts survive refresh and clear after permission revocation; connector calendar reads no longer silently swallow errors. Generic evidence links retain pinned references, origin filters and focus; budget editing preserves draft revisions on conflict.

## UI closure follow-up

- Conversations, Insights, Connections, Lark, diagnostics, storage statistics, runtime/perception/model/module settings, server/advanced configuration, Memory settings and Memory progress now use the authenticated resource cache. Event-driven pagination and post-command reads share a cancellable resource generation; mounted readers share visible-page polling. Sensitive draft model-catalog POSTs keep their own abort controller rather than entering a global cache.
- Conversation restoration cannot replace a later explicit selection, and older-turn requests are cancelled when switching conversations. Settings refresh preserves owner drafts and their original revision; permission revocation removes protected details and editable drafts. Completed Memory jobs stop polling, while active jobs and transient read failures retain bounded shared refresh.
- Provider failures now use the protocol code/reason through `failure-message.ts`, with correlation IDs preserved. Unknown codes produce a generic localized notice plus a diagnostic code. External engine messages are not used as the task failure display. New translation candidates are handed to the root integration pass.

It follows conversation Memory and insight artifact citations into the original, also opens the archive capture, tests Escape, browser forward/back, preserved origin filters and the exact opener at desktop/mobile sizes.
