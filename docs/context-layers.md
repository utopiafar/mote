# 资料分层与渐进式记忆

Mote 将原始资料、来源快照、检索索引和模型推断分别保存。查询 Agent 通过只读工具决定需要展开哪一层；程序不按“待办”等关键词分类用户意图。中央页面的导入、预览确认、分批提取和报告流程见[中央导入、记忆与洞察](central-memory.md)。

## 存储层

| 层 | 保存什么 | 行为与边界 |
|---|---|---|
| 原始资料 | 作者提交的日记正文、采集图像、上传文件与附件字节 | 正文不被模型输出覆盖；图片与文件按内容散列去重 |
| 事实 / 来源快照 | 某来源在某时刻报告的文本、事件和元数据 | “来源报告”不等同于客观事实；模型需保留说话人、时态和不确定性 |
| 引用 / Shadow | 原件定位 URI、标题、类型、版本与观察时间 | 不收集正文，不在查询时自动打开 NAS、磁盘或任意远程 URL；无法回答原文中尚未采集的内容 |
| 正式资料 | 一份文件、会话或片段的稳定身份、不可变修订、内容块、成员定位、覆盖与保真状态 | 上传后由组织器另行发布；长内容按块和偏移展开，详见[接入与正式资料架构](material-architecture.md) |
| 索引 | SQLite FTS5 与可选向量索引 | 可重建的检索结构，不是独立事实来源 |
| Memory | 模型提取的标题、陈述、不确定性、证据 ID、精确引句与偏移 | 候选、已确认、证据已变更三种状态；不冒充原始输入 |
| 洞察 | 指定范围中的 Markdown 回顾、引用与静态 HTML 报告 | 根据本次可见证据生成；删除或修订证据会使旧派生结果失效 |

中央数据库位于 `MOTE_DATA_DIR/mote.sqlite`，新图像及文件原件统一位于 `files/objects/<sha256>/` 的分片对象中，旧 `blobs/` 与 `files/<hash>` 兼容读取（见 [资产存储](asset-storage.md)），解析任务工作产物位于 `imports/`。中央“导入”支持原件归档、ZIP/目录输入及模型驱动的通用解析；PDF 读取已有文本层，不执行扫描件 OCR。来源的 Shadow 引用仍然只有定位元数据，不会因为文件扩展名是 PDF 就自动读取正文。客户端文本同步与中央通用导入是不同入口，支持格式和上限见[中央导入说明](central-memory.md#支持的输入和当前上限)。

## 原件在哪里

一个来源有独立 `sourceId`。原件以 `externalId` 标识，例如日历实例 ID、客户端选定目录内的相对路径或 MCP 资源 URI。`revision` 表示一次不可变版本，`observedAt` 表示客户端实际看到该版本的时间，`modifiedAt` 可记录上游修改时间。

- `reference` 仅允许空正文。外部原件不可用时，模型应明确说明只有引用。
- `snapshot` 保留当次文本，不保证与外部原件持续一致。
- `original` 表示通过来源明确归档的原始文本。
- `derived` 标记外部 Agent 写回的派生内容，不能作为独立原始事实。

导入记录另有 `document` 元数据：原件/附件 ID、相对路径、原文记录时间 `recordedAt`、明确发生时间 `occurredAt`、时间依据、内容角色和原始元数据。源记录时间与中央观察/接收时间分别保留；不能把今天导入的旧笔记当成今天发生的事。

改变来源的保存策略只影响后续同步；已保存版本不会被静默重写。需要移除历史内容时，应显式删除相应证据。

## 同步、版本和删除

每个外部条目有一个当前指针和多个不可变版本。默认查询、全文检索和向量检索只读取当前版本；历史版本可通过版本入口与 `source_history` 工具展开。

相同 revision 和内容可以重复提交；同一 revision 对应不同内容会被拒绝。旧观察晚到时保留在历史中，不回滚当前指针。客户端使用内容变化和前一版本生成版本链，因而“原内容 → 删除 → 恢复原内容”是三个版本；重试使用已持久化的同一版本。

来源删除上游条目时提交删除版本。中央节点保留历史记录，默认检索隐藏已删除当前项。隐私删除中央证据则移除正文并留下防重试复活的墓碑。只有一次完整、成功且覆盖对应范围的扫描，才可将缺失项判断为删除；日历实例滚出扫描窗口不算删除。

## 日历与实际活动

日历的 `start/end/allDay/timeZone/status` 与观察时间独立。查询日历时按计划时间重叠匹配，可以查未来安排；全天事件和带时区偏移的边界均保留。会议时长不会加入屏幕采样计时，日历状态也不能证明实际出席。

## Memory 的逐层展开

1. 概要只返回标题、状态、生成时间和证据数量。
2. 展开某条记忆，读取模型陈述、不确定性和来源列表。
3. 打开支持它的原始证据，必要时分页读取长文或比较历史版本。

提取操作使用已配置模型和 DeepSeek Harness 的只读工具。新的持久任务按原文偏移精确分批；每批检查内容指纹、引用 ID 和原文引句，记录成功检查点并支持失败重试。无模型时等待配置。程序不会用语义关键词兜底生成记忆，也不会把原件归档完成当作记忆完成。

新记忆默认是模型候选，用户可确认或删除。来源当前版本变更后，旧记忆标记为需要重新验证，默认 Agent 检索排除它们；删除原始证据会清除可能依赖它的派生记忆。已确认不代表它经过客观事实验证。

## 导出与迁移

HTTP JSON v1 资料导出保留正文、来源、版本、当前指针、记忆、原始文件字节/元数据和附件关系，并兼容旧 v1；它受导出大小限制；包含二进制文件同步归档的资料库会拒绝旧 JSON 全量导出，需使用完整离线备份。JSON 不包含对话或正式资料修订历史。恢复时校验文件散列与引用，并按目标密钥重新加密文件对象。导入工作目录、转换脚本和批处理任务不在便携导出中，需要迁移运行状态时使用离线备份，具体范围与恢复步骤见[部署文档](deployment.md)。恢复来源默认暂停，恢复记忆标记为需重验，防止换机器后自动接入原来的外部账户或信任过期推断。模型及第三方授权凭据不进入 JSON 资料导出，迁移后应重新配置或授权。

## 离线可用与删除范围

手机、端点 MCP 或外部 NAS 离线时，中央仍可使用已归档的原件与快照；未同步变化保持未知。只有引用的资料不能补出缺失正文，查询不会自动唤醒原设备或访问任意 URI。中央本身停机时，中央查询不可用；端点按已有队列机制继续保存允许采集的记录。

删除 Memory 只移除推导结果；删除单条证据会清理依赖记忆，但导入任务仍可能持有原件和解析产物。删除整次导入才会移除任务、工作目录及不再被其他导入/证据引用的资料和文件。同一来源或原件被多个导入共享时，需要保留其他导入的有效引用。详细行为见[删除与重试](central-memory.md#删除与重试)。
