# ADR：问答覆盖、简化上下文与录音证据

> **状态：历史。** 本文记录当时的决定与验证范围，不再描述当前实现；当前设计见 [Memory 当前设计](memory-current-design.md)。

日期：2026-10-14。状态：已采用；自动验证、生成语料模型对照和部署分别报告。

## 决定与责任

普通问答仍使用一个入口，由模型解释问题、选择只读检索工具和判断证据。宽范围问题先形成与用户目标有关的状态、变化及未解决点，结合实际来源和时间范围检查覆盖；独立缺口可以使用现有一层研究委派。不开关键词路由，不要求逐条遍历全库，也不以引用数量作为质量指标。Memory 是导航，不是所有相关事实的全集；已可读原文不等待 Memory 完成。

概括近期或当前状态前，模型还需查找并阅读所选范围内最新的相关原文，比较较早、较晚阶段是否延续、限定或改变先前判断。一个来源的早期查询未命中，不覆盖该来源在所选区间的后期。新近度按原文发生、作者或录制时间解释，不使用 Memory 生成、发布时间代替；有依据的变化须进入最终回答。该责任由归档研究、表达和审核共用，不增加关键词判断、固定工具顺序或每个来源必读的规则。

取消内部问答工具结果的字符/token近似配额、默认工具总调用次数、初始 input/task 字符容量门槛，以及材料/声明/上下文结果因配额缩页的机制。直接 Memory 提取入口也移除旧的 100 条与 100,000 字符拒绝条件，保留与手动任务相同的 API 身份合同。页面按明确请求范围读一次，正常返回后续游标/偏移。宿主继续记录实际字符、token、耗时和模型用量；观测不再决定读取额度。调用者显式声明的有限测试合同可保留，但不成为普通问答默认。

取消 Memory 因宿主字符额度、候选容量、覆盖不足或超时而自动二分的恢复路线。实际模型输入/输出容量失败明确留下失败范围，不能缩小输入后伪称原目标完整。来源授权、精确范围、分页schema、实际传输字节边界、模型自身上下文与配置的输出限制、取消、总期限和有界格式修正继续存在。它们不是新的字符近似预算。

Codex 原生输入容量拒绝按结构化 `input_too_large` 分类为 `processing_limit`，只记录供应商给出的安全字符数；不解析原始错误文案，不截断或分片绕过，也不自动重试。重复的材料、来源、时间和声明元信息只在模型输入中交付一次，各原文范围使用精确引用；完整指纹、授权、覆盖和检查点仍留在宿主。表示去重不减少目标、可读范围或正文，也不增设 Mote 额度。

新 range-evaluation@1 的初始打包只使用已有配置的分段大小，移除每批 20 段、覆盖 100 段、提取 seed 100 个身份及原件读取 200 个身份的额外裁剪。已保存批次保留其实际范围，不静默改写完成记录。显式历史续跑可通过宿主入口分别冻结剩余目标和整份原文的上下文读取范围；上下文可以帮助解释，但不因此成为待生成目标、完成覆盖或独立 Memory。精确授权与依赖身份保留全量，导航展示不决定读取权限。

钉钉原始导出 JSON 完整留存，模型阅读的规范转写仅采用一份段落主正文；结构冗余不成为两次发言。真实重复段落保留，片段坐标、原件版本与说话人来源标签可核验。未知非空结构明确失败并保留原件，不当成空正文。录音配方 v3 使用已有 range-evaluation@1，完整范围评估与独立审核后择要，不承诺枚举每个事实。

飞书、钉钉适配器使用来源创建/开始时间作为语料时间锚点。适配器保存 provider 提供的毫秒时间，并经 document.recordedAt/timeBasis=recorded 进入正式资料、Memory与问答。这里的 recordedAt 是本产品选择的语料时间，不宣称独立验证了设备按键时间。正文回忆、计划或描述的往事仍由模型结合语境解释，不能全部转成当天 occurredAt。保留已有时间与归属抽象，不增加多时间轴、逐条日期填写或身份确认。

历史资料可在显式授权后使用新解码与时间策略重建版本并重新生成受影响的 Memory，不需要新旧解码并行兼容。原件仍保留；新版本撤销旧依赖和迟到结果。安装代码不自行扩大来源或启动全库收费重算；历史重算保留独立范围与执行回执。

明确 transient 的模型故障复用共享 ExecutionEngine 的现有有界恢复；结构错误和未知供应商失败不变成无限重试。保留有效提取草稿、成功检查点、授权/版本复核和未知外部写作对账。重试入口先给出明确受理或拒绝，再由后台执行，不吞掉受理阶段错误。

创建但尚未启动的手动 Memory 任务在重启后保持未激活。现有显式运行入口持久记录启动，再允许未完成工作自动恢复；启动与恢复前的资料核对不能一边阻塞线程、一边占用模型执行租约。取消、暂停与撤权仍阻止恢复。MVP 旧记录可以显式重跑，不新增通过历史尝试次数猜测所有者授权的兼容分支。

## 质量方案与实验

普通默认采用覆盖与表达基础改进。生成语料质量实验可对照独立审核、研究后表达及二者组合。它们通过可信实验注入运行，不新增产品模式或用户步骤：

| 方案 | 模型责任 |
| --- | --- |
| base | 当前只读研究入口，加覆盖检查与表达自检 |
| review | base 后独立模型重新查证、修正并输出答案 |
| research-writer | 持久研究入口先形成证据报告，再由表达会话读取并重新取得可引用原件 |
| both | research-writer 后独立审核 |

各阶段保留相同问题、模型配置、归属与时间/设备范围。报告/审核结论是不可信解释，不携带原件引用资格；新会话必须实际读取当前允许的原句。整次 operation 汇总所有父子研究、恢复片段、表达、审核与失败调用，分别报告实际token、缓存、完整性、耗时和可得费用。未知费用不是零，累积线程用量不能按增量重复相加。

已完成阶段保存在现有研究工作日志，重启只恢复未完成阶段；恢复前复核当前证据、来源声明、执行授权及冻结的模型配置。配置变化不能把不同参数的阶段混成一组对照。来源目录中的配置元数据使用私有宿主读取收据及现有来源依赖类型，和来源说明版本分别核验；目录不会授予原文引用资格。正常同步进度按观察时点记录，不因后台心跳更新就撤销一次普通问答。

大范围续问的依赖校验按同一次授权检查中的 Material、文件及来源复用元数据查询，不反复解析同一份全文。异步准备阶段让出事件循环供续租、取消及其他请求运行；外联与发布前仍精确复核当前授权、版本及执行栅栏。不能通过提高租约、裁掉依赖或降低隐私校验解决续问中断。

Memory 也在模型准入和实际传输入口复核初始正文及随后实际读过的原件。输入已披露的范围目录、来源说明和 Material 归属须保持当前有效；即使对应正文尚未读取，说明变化、更正归属或删除也阻止旧元信息进入下一次发送与发布。该复核仅查询元信息，不为检查而读取未读正文；未读正文的独立内容变化不阻断当前目标。已披露的正文被删除、更正或撤权同样阻止后续发送与发布。同步批量读取可以在一次检查内部复用材料元信息，不能跨模型调用缓存权限。HTTP 适配器可检查每次请求；Codex App Server 的可观察边界是每次 `turn/start`，内部供应商请求不在宿主的逐次观测范围内。自定义模型工厂必须接入相同的可信准入与授权 hooks。

Activity 的 Memory 进度映射一次展开任务范围与授权身份，保持原数组顺序、身份优先级及完整数量；旧触发器事务替换。不逐条重扫整个大任务，也不以裁剪范围来降低索引成本。

生成 fixture 验证真实入口、续问、范围、引用、传输、恢复及清理。模型语义质量另使用固定生成语料，不启用个人截图读取或采集；先通过正常整理入口完成当前代码的确定性启动补齐，确认无待整理输入，再冻结、核对各组共同指纹与运行前后指纹。不同方案从同一冻结副本开始。失败的问答与数据变动分别保留，不能相互遮蔽。个人资料、相关推断、模型输入输出与凭据不进入公开验证材料。一次对照不是延迟分布或语义完备性的证明。

## 网上调研与采用边界

[Anthropic 的上下文工程实践](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)描述轻量标识与按需读取，长任务结合上下文压缩、记录和独立研究。这里采用按需读取及已有研究分支，不照搬外部工具权限或额外预算层。

[OpenAI 的 Memory/compaction 示例](https://developers.openai.com/cookbook/examples/agents_sdk/building_reliable_agents_memory_compaction)将运行上下文、后续 Memory和可核验产物分开，建议压缩保留后续工作状态。[Responses compaction 文档](https://developers.openai.com/api/docs/guides/compaction)提供服务端压缩能力，[Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)提供线程压缩协议。此改动不等于将 Mote 迁移到 Responses，也未增建手动压缩调度器；是否发生运行时压缩只按实际事件记录。

Codex 0.162.1 有自身的输入容量检查。[对应版本的校验代码](https://raw.githubusercontent.com/openai/codex/rust-v0.162.1/codex-rs/app-server/src/request_processors/turn_processor.rs)在生成前检查整次输入的 Unicode 字符数；这不是已删除的宿主 UTF-16 近似预算。不能用多条 text 输入规避合计限制，失败输入的安全计数也不能代替实际 token 或账单。

## 取代检查

| 类别 | 处理 |
| --- | --- |
| KEEP | 单一入口、模型选择工具和解释语义、只读授权、原件、精确引用、当前归属、独立 Memory 审核、正常分页、实际传输容量、取消/期限和有界修正、来源选择范围。 |
| CHANGE | 宽问题的覆盖责任、工具与初始上下文交付、录音规范正文和语料时间、Memory失败恢复、可信质量实验及整 operation计量。 |
| REMOVE | 48,000/16,000及其他字符近似工具配额、初始字符容量拒绝、默认24工具调用、结果缩页、新范围评估的额外段数裁剪、Memory自动二分与候选容量决定完成、重复全文授权查询、重试受理错误吞没。不增加新的自定义字节额度代替它们。 |
| EXCEPTION | 明确测试调用合同、当前格式schema与传输边界、真实资源失败、不可读/被撤权原件、缺语境/本人问题及外部未知结果仍保持具体状态。外部 Context API、MCP 和网页引用详情的既有响应分页合同保留；它们未参与内部问一问工具读取，其自定义响应大小不能称为供应商原生边界。旧定义可识别已有固定记录，不为本次路径新增旧行为兼容分支。 |
| UNKNOWN | 各质量组合收益、最佳延迟/费用、真实设备未上传内容与厂商时间语义；生成fixture不能证明模型遵守覆盖或自然表达。 |

本决定取代[统一查询 ADR](adr-system-refactor.md)中的工具近似预算和本次 Memory二分部分，以及[范围评估 ADR](adr-memory-range-evaluation.md)的自动资源二分恢复责任。录音正文和时间细化[录音接入设计](recorder-connectors-design.md)，v3组合保留[本人对应](adr-recording-coverage-and-owner-context.md)的语义边界。既有带日期的验证记录保持其历史含义，不改写为新机制已通过。
