# Android 大资料库性能与当前本机格式

当前本机格式为 3；下方 0.0.25 / Android versionCode 36 的性能数值是历史记录。

2026-10-04 本次清理验证：54 个 JVM 测试类、245 项测试全部通过（0 失败、0 错误、0 跳过）；instrumentation Kotlin 源码编译与 debug APK 构建通过。未运行模拟器或物理设备 instrumentation、真实模型或个人数据检查。下方历史验证不能视为本次重新执行。

## 启动与后台维护

之前，启动恢复把文件扫描、孤立文件清理与采集入口放在同一条等待路径上。图片增加后，首页即使已经显示，也要等待整库处理完成。

现在先连接并确认用户选择的存储位置，再开放采集；浏览索引补全和孤立文件清理随后在后台执行。维护按文件或小批记录释放队列锁，首页直接反映开始／暂停状态，不等待库存统计完成。正在进行的存储位置迁移仍要安全恢复，丢失的存储介质不会被自动替换成空目录。系统截图权限、投屏重新授权、隐私检查与空间限制保持原有规则。

统计尚未得到有效快照时显示加载或上次结果，不把未知当作零。完成维护后再发布校准结果。上传和来源工作继续后台调度；本机 OCR 仅服务当前隐私审查，不调度延迟识别补传。初次维护避免多个消费者竞争重建同一份当前派生索引。

## 统一元数据与分页浏览

`QueueBrowseIndex` 是由记录文件派生的元数据索引，保存记录 ID、时间、应用、图片哈希以及 OCR、上传、阻塞和预留空间字段。库存、相册和图片分页复用这一索引，避免各页面分别打开全部事件正文。索引可从原记录重建，不保存 OCR 正文或图片像素。

记录、含图记录和独立图片文件采用不同计数：多条记录可以共用同一张图片；采集区和待决定区分别计数，再汇总本机图片记录。移动到待决定区不增加总记录数，累计采集计数也不会因清理而倒退。中央归档数量独立计算。

采集记录先显示占位和当前页，再逐张加载缩略图。后台记录变化未影响当前页时保留已有视图和缩略图；切换日期、相册或页码时丢弃尚未执行的旧请求。缩略图写入缓存使用独立后台队列，不挡住已经解码的预览显示。冷库首次缺少索引时仍需要读取记录元数据，不能把首次派生索引重建宣称为常数时间。

## 批量相似图片扫描与删除

旧删除路径每处理一条记录，就打开所有剩余事件来判断图片是否还有引用；大批量删除会重复执行整库读取。新的共享图片引用计数随每次提交更新。批量操作合并派生索引的写盘，每条记录的原子提交、引用保护和取消边界保持独立。

参考图片验证在文件未变化时复用；移动时不再反复写入相同共享图片，仍在删除源记录前核对目标记录及图片。WorkManager 的进度更新限制为每 250 ms 一次，并在阶段切换与结束时更新，避免每张图片都等待进度数据库落盘。

扫描按内容哈希最多缓存 64 项紧凑特征，内存不保留整个图库的像素。精确模式按 8 KiB 块计算当前 v2 签名的哈希；旧 `WxH:hash` 签名不再解析，比较时直接使用特征，避免反复编码和解析签名。去重阈值、应用／尺寸边界和“与上一张保留图比较”的规则保持不变。

结果每页 10 个候选；全选只改变选择状态，不重建图片。扫描与删除可以留在后台，已有结果仍可翻页预览。取消在记录之间生效，已经完成的处理保留，尚未处理的记录留在原处。实际执行始终重新检查候选与参考图身份，旧报告不能绕过这些检查。

## 当前本地文件边界

- 格式 3 的本机截图、事件、缩略图、元数据索引、待决定区、扫描报告/操作计划、本机草稿和来源内容保存原始字节；不再提供可选内容加密、旧 AES-GCM reader、明文前缀消歧或批量解密工具。
- 旧数据缺少 `.mote-local-format` 标记、标记非 3、旧设置缺字段、旧 transport checkpoint 或版本不符时明确拒绝，要求用户清除应用存储后重新设置；不自动读取、转换或删除旧数据。
- 当前格式中可重建的 browse/index 与孤立文件恢复仍保留；存储位置变更继续复制、校验和安全提交当前记录，不能把失败当作空目录。
- 访问令牌、连接恢复、中央私有草稿及操作 ledger 继续使用 Keystore `SecretBox`。这是当前凭据与私有状态保护，与截图/队列内容格式分开。操作系统应用目录权限、隐私过滤及 `FLAG_SECURE` 继续生效。
- Desktop 与中央内容存储由各端当前规范定义，见 [内容存储设置](content-storage.md)；不能用本页历史混存记录推定当前支持旧格式。
