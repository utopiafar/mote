# Android 大资料库性能与可选内容加密

适用版本：Mote 0.0.25，Android versionCode 36。

## 启动与后台维护

之前，启动恢复把文件扫描、孤立文件清理与采集入口放在同一条等待路径上。图片增加后，首页即使已经显示，也要等待整库处理完成。

现在先连接并确认用户选择的存储位置，再开放采集；浏览索引补全和孤立文件清理随后在后台执行。维护按文件或小批记录释放队列锁，首页直接反映开始／暂停状态，不等待库存统计完成。正在进行的存储位置迁移仍要安全恢复，丢失的存储介质不会被自动替换成空目录。系统截图权限、投屏重新授权、隐私检查与空间限制保持原有规则。

统计尚未得到有效快照时显示加载或上次结果，不把未知当作零。完成维护后再发布校准结果。上传、OCR 和来源工作保持原有后台调度，初次维护期间避免多个消费者竞争重建同一份旧索引。

## 统一元数据与分页浏览

`QueueBrowseIndex` 是由记录文件派生的元数据索引，保存记录 ID、时间、应用、图片哈希以及 OCR、上传、阻塞和预留空间字段。库存、相册和图片分页复用这一索引，避免各页面分别打开全部事件正文。索引可从原记录重建，不保存 OCR 正文或图片像素。

记录、含图记录和独立图片文件采用不同计数：多条记录可以共用同一张图片；采集区和待决定区分别计数，再汇总本机图片记录。移动到待决定区不增加总记录数，累计采集计数也不会因清理而倒退。中央归档数量独立计算。

采集记录先显示占位和当前页，再逐张加载缩略图。后台记录变化未影响当前页时保留已有视图和缩略图；切换日期、相册或页码时丢弃尚未执行的旧请求。缩略图写入缓存使用独立后台队列，不挡住已经解码的预览显示。冷库首次缺少索引时仍需要读取记录元数据，不能把首次旧数据升级宣称为常数时间。

## 批量相似图片扫描与删除

旧删除路径每处理一条记录，就打开所有剩余事件来判断图片是否还有引用；大批量删除会重复执行整库读取。新的共享图片引用计数随每次提交更新。批量操作合并派生索引的写盘，每条记录的原子提交、引用保护和取消边界保持独立。

参考图片验证在文件未变化时复用；移动时不再反复写入相同共享图片，仍在删除源记录前核对目标记录及图片。WorkManager 的进度更新限制为每 250 ms 一次，并在阶段切换与结束时更新，避免每张图片都等待进度数据库落盘。

扫描按内容哈希最多缓存 64 项紧凑特征，内存不保留整个图库的像素。精确模式按 8 KiB 块计算兼容旧签名的哈希，比较时直接使用特征，避免反复编码和解析签名。去重阈值、应用／尺寸边界和“与上一张保留图比较”的规则保持不变。

结果每页 10 个候选；全选只改变选择状态，不重建图片。扫描与删除可以留在后台，已有结果仍可翻页预览。取消在记录之间生效，已经完成的处理保留，尚未处理的记录留在原处。实际执行始终重新检查候选与参考图身份，旧报告不能绕过这些检查。

## 本地文件与旧版本兼容

- Android 新保存的本地截图、事件、缩略图、元数据索引、待决定区、扫描报告／操作计划、草稿和来源内容默认使用明文，可手动开启后续写入的加密。正常 JSON、JPEG、PNG 原样存储；任意二进制如恰好与旧加密格式前缀重合，使用可逆的明文前缀消歧。
- Android 保留旧 AES-GCM 内容的认证解密能力。开发者页面手动启动一次性批量解密后，在后台逐个读取、验证并原子替换旧文件，过程中允许明文和旧密文混存；读取或校验失败保留原文件，不能把损坏内容当作明文。旧内容尚未完成迁移时，仍需要原安装的 Keystore 密钥。
- 保留已有记录 ID、内容哈希、存储位置和文件命名约定。文件名可能仍有 `.event`、`.blob`、`.enc` 或旧索引前缀；扩展名不代表新内容仍加密。
- Desktop 的事件 JSON、JPEG、草稿与来源索引继续默认明文；新增可选内容加密和开发者批量解密，兼容明密混存。
- Android 的访问令牌继续由 Keystore 保护，Desktop 的访问令牌继续使用系统加密存储。中央节点内容加密同样默认关闭，配置 `MOTE_DATA_KEY` 本身不再隐式开启加密；旧内容保持可读，提供一次性批量解密。详见[内容存储设置](content-storage.md)。操作系统应用目录权限、隐私过滤和 `FLAG_SECURE` 仍生效。
