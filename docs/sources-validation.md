# Mote 0.4.0：来源与记忆验收记录

日期：2026-09-14。本轮验证本机日历、文件快照与引用、不可变版本、中央查询、记忆及其原始证据展开。所有本轮模型输入、文件、日历和界面内容均为生成的合成资料，没有读取个人日历、文件或屏幕。

使用方法见 [连接器](connectors.md)、[上下文分层](context-layers.md) 和 [Android](android.md)。本页区分协议与状态机测试、真实模型测试、模拟器测试；某一层通过不代表其他层已经验证。

## 真实 DeepSeek：三轮结果

测试调用 DeepSeek 官方 API，模型为 `deepseek-v4-pro`，推理强度为 `high`，通过实际 DeepSeek Harness 只读工具循环检索隔离中央节点。每轮仓库包含 16 条生成记录，其中包括文件的历史版本。合成场景覆盖当前版本更正、长文尾部、只有 URI 的 NAS 引用、未来日历和取消日程、原话归属、计划与完成的区别、正文中的伪指令、来源范围及无屏幕采样的计时边界。

数量依据本机忽略目录中的三份 `summary.json` 核对；以下仅保留汇总。完整回答、测试节点数据与凭据不随文档或源码发布。

| 轮次 | 实际请求 | HTTP 结果 | 结论与限制 |
| --- | --- | --- | --- |
| 第 1 轮 | 8 次查询、1 次记忆抽取 | 6 次 200、3 次 500 | 运行中的旧 Agent bridge 与重新编译的工具插件不兼容，影响来源范围、计时查询及记忆抽取。没有把这三次失败删除或计为模型回答通过。 |
| 第 2 轮 | 8 次查询、1 次抽取、1 次渐进展开 | 10/10 为 200；抽取 8 条记忆 | 冻结运行时工具插件并修复历史版本读取后，协议链路通过；人工审查仍发现把“没有采样证据”表述成“工作 0 分钟”，以及把 UTC 观察日期当作原文事件发生日期。 |
| 第 3 轮 | 3 次查询、1 次抽取、1 次渐进展开 | 5/5 为 200；抽取 8 条记忆 | 收紧证据、计时和日期约束后的定点复测，三次查询分别覆盖引用正文不可见、取消日程及计时。不是完整重跑第 2 轮全部问题。 |

HTTP 200、引用 ID 存在、抽取数量和工具调用成功是协议证据，不能直接换算成语义准确率。人工核对关注：只引用已读取内容；计划不代表参加或完成；引用元数据不代表读过原件；没有屏幕观测不能推导工作为零；作者没有明确日期的事件不能被强行安上观察日期。没有用答案关键词命中来代替语义审查，也没有在代码里按关键词生成结论。

第 3 轮三个查询实际耗时约 8.3–40.2 秒，记忆抽取约 62.9 秒；渐进展开的汇总未记录耗时。这些是该模型、网络和合成样本的一次测量，不是响应时间承诺。8 条抽取结果表示模型生成的候选记忆数量，不表示 8 条已经由用户确认的事实。

渐进展开还实际验证了记忆概要不携带完整正文、按 ID 展开详情和原始证据，以及模型通过只读工具继续核对证据。引用的可用性与记忆声明分别校验；它们不能保证模型对证据的解释永远正确。

## 客户端输入到真实模型的联测

上述三轮之外，又正常停止任务专用合成中央节点，离线复制 Android 仪器测试与 Mac 原生同步测试实际上传的仓库，对两个设备分别调用同一真实 DeepSeek 模型。Android 查询约 55.2 秒，12 条引用；Mac 查询约 81.5 秒，6 条引用。两次均返回 200，全部引用均属于所选设备，未跨设备混入材料。

人工查看结果确认：Android 的初始文件、删除墓碑和恢复文件能沿历史串联；Mac 能区分当前引用与过去保存的原文，识别恢复的是较早正文而非最后一次更新；两者都把日历计划与出席证据分开，Mac 在无屏幕采样时明确实际耗时未知。这份副本包含开发期间旧测试节点写入的引用/删除占位文字，因此也覆盖了读取历史记录的兼容情形；最终协议的新引用和删除版本正文严格为空，已另有存储回归校验。

这些调用使用客户端实际提交的生成资料，未使用个人屏幕、系统个人日历或用户文件。真实模型联测的临时凭据文件已在结束后移除。

## 合成协议、存储与界面验证

本页独立回归文件 `apps/server/test/source-regressions.test.ts` 的 8 项测试全部通过，输入仅为临时 SQLite 仓库中的生成资料：

- 并发提交相同来源版本返回同一记录和重复 ACK；冲突版本失败后，后续正常版本仍可继续提交。
- 空文件、纯空白和 Unicode 原文经存储、导出与导入保持一致。
- 伪造当前指针的时间/删除状态或版本校验和被拒绝，整个导入事务回滚。
- 删除再恢复形成独立版本，归档往返后重试旧版本不会倒退当前指针。
- 每条记忆正文和不确定性里的行内引用必须属于该条声明的证据；即使别的记忆读取过同一条证据也不能混用。代码块和行内代码中的字面 UUID 不作为引用误判；校验失败不部分保存记忆。
- 导入较新的当前版本会让旧记忆失效、清理旧洞察并发出证据变更；重复同一归档不重复失效。
- 相同观察时间却指向不同当前版本的合并返回 409，并回滚新增记录；不能确定先后时不默默选择一个版本。
- 导入容量计算包含来源与记忆元数据；超出目的仓库配额时整笔回滚，不留下部分记录、来源或变更通知。

归档回归来自实际复现的问题：最初合并已经改变当前资料，但旧记忆仍显示已确认，进行中的查询也看不到证据变更；新增记忆元数据还可能绕过总容量检查。修复后上述回归通过。版本事务与引用校验均为确定性的完整性约束，不涉及内容主题判断。

Web 已完成构建，使用独立 Electron 配置、临时真实中央服务和 **fixture Agent** 执行 UI 验证：当前版本、历史展开、NAS 引用写入、记忆概要/详情/证据链接、确认记忆、桌面和移动布局均通过。实际截图经过人工查看；移动端引用表单标签与输入框错行已修复并重拍，未出现横向溢出。这里的 UI 记忆响应是预设合成结果，不能算真实模型质量测试。

最终工作区测试共 **221 项通过**：Mac 88、服务端 72、Web 13、Agent 28、诊断 5、本地推理协议 13、共享协议 2。全部 TypeScript 检查、中央与 Web 构建通过；另有 22 项隐私 fixture 检查、真实 Harness 配合合成模型的截图/笔记归档往返，以及实际 MCP SDK 经 stdio → HTTP 的读写隔离联测通过。本地推理协议测试与实际模型运行分别记录。

Mac 的最终回归覆盖三个修复：更改隐私规则后不从旧状态发送未过滤的标题和 URI；已有离线队列达到上限时恢复网络仍可先排空再处理新扫描；同 URL 更换凭据时，CLI 不复用旧节点绑定的待上传正文。最终安装包与原生界面验证记录见 [电脑端](desktop.md)。

Mac 0.4.0 最终打包后，ad-hoc 签名验证通过；包内 Qwen 原生运行时实际处理生成白图，约 4.05 秒，返回允许。原生界面使用合成文件选择器完成来源配置、离线来源状态和随手记检查。该模型输入只是功能性白图，不能说明 NSFW 分类准确率，也没有读取真实屏幕。Android 本轮没有重复运行本地模型。

服务端配置与诊断另以实际 Electron 页面运行通过：配置路径与凭据状态展示、刷新、请求编号关联、诊断包下载，以及桌面/430 像素宽度布局；导出的支持包不包含合成日记正文、令牌、模型凭据或私有目录。隔离 profile 的启动/备份/恢复/升级回滚，以及 Tunnel 生命周期 fixture 测试通过；公网 Tunnel 连通性仍见下方未测范围。

## Android 最终安装包与模拟器

0.4.0 / versionCode 5 的日常 debug 和开发版 APK 已构建，开发版显示为 `0.4.0-dev`。36 项 JVM 测试通过；两种构建的 lint 均为 0 error / 48 warning；两种 APK 均通过 16 KiB ZIP 对齐。最终文件位置、大小和 SHA-256 见 [Android 产物记录](android.md#040-来源同步验证与产物)。

最终开发 APK 在任务专用 `mote_fixture_api35`、API35 / Android 15 模拟器中运行 `LocalSourcesInstrumentedTest` 的 3 项仪器测试，全部通过且无跳过，耗时 1.338 秒：

1. 生成的私有 Calendar/Documents Provider 验证日历计划时间与观察时间分离、Unicode 文件正文、引用模式不读取内容、隐藏/不可用提供者与不完整扫描不误删。
2. 原生来源页面的连接入口可用，打开页面不会提前申请日历权限。
3. 使用生产 `HttpJson` 连接隔离的真实中央节点，完成文件和日历注册/配置更新、故意丢 ACK 后重建加密状态并重试、删除后恢复、三版本历史及当前正文回读。

传输和状态机测试使用本机生成 Provider，未连接系统中的个人 Calendar Provider，也没有通过截图来测试文件内容。本轮没有重新运行 Qwen；已有图片审查与本轮来源同步是不同验证路径。仪器测试中的真实中央步骤需要显式提供隔离节点连接文件，默认缺失时会跳过该项；仅看到仪器运行结束不能推断真实传输步骤执行过。
