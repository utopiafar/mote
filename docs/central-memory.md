# 中央导入、记忆与洞察

> 0.0.44 更新：新产物须经过 admission 分层与独立审核；自动提取采用有上限的连续窗口轮次。旧版候选不自动进入整合。当前规则与迁移行为见 [记忆准入设计](memory-admission.md)。

本文的通用导入与 [文件原件同步](files.md) 是不同入口。当前已共享 PDF/DOCX/XLSX 解码，已知文档可直接提取；需要模型映射的资料仍走预览确认。自动记忆调度与审核以 [生命周期](memory-lifecycle.md)、[准入](memory-admission.md) 和 [版本化更新](memory-updates.md) 为准。


Mote 的中央节点保存可追溯的资料，并让模型按需使用这些资料。原始文件、可检索记录、候选记忆和洞察报告是不同的产物，有各自的处理状态。文件上传成功不等于全部内容已解析，记录入库成功也不等于记忆提取完成。

中央网页提供独立的 **导入、记忆、洞察** 入口。来源同步和引用见[来源与 MCP](connectors.md)，存储分层见[资料分层](context-layers.md)，模型配置见[Agent 文档](agent.md)。

## 从一份资料开始

1. **提交资料**：选择多个文件、ZIP，或中央服务器可以读取的目录。用自然语言说明资料的来历、人物、时区和保留要求，例如“这是聊天导出，张三是我，时间为北京时间”。
2. **先保存原件**：中央节点保存文件字节、散列和相对路径。ZIP 展开或模型解析失败时，已经成功归档的原件仍可下载。此时尚未写入可检索记录。
3. **解析**：已知文本/PDF/DOCX/XLSX 可走内置直接解码，不需要模型选择作者或时间；其他需要映射的输入由 `document-import` Skill 检查样例，调用通用解析辅助程序，必要时编写转换脚本。页面展示解析说明、记录数量、正文样例、附件数量、歧义和文件处置清单。
4. **确认模型映射**：需要预览的输入先核对预览；有问题时修改说明并重新分析。确认后，服务校验预览清单未被改动，再逐条写入带版本的原始记录。已经开始保存记录的任务不能直接重新解释，失败后继续原任务，或另建一次导入。
5. **独立提取记忆**：归档产生增量，由生命周期策略准入后建立 Memory 任务，也可在记忆页手动提取。导入完成本身不立即调用记忆模型；旧任务可能仍有关联 Memory ID，进度按各自实际状态展示。
6. **查看与使用**：在记忆页核对候选、查看原文、下载原件或附件，再决定确认或删除。在洞察页选择时间范围和关注方向，生成带证据的 HTML 报告；也可以在问一问中直接检索。

文件处置状态是 `parsed`（解析为记录）、`attachment`（关联附件）、`container`（容器）、`excluded`（未纳入）或 `unsupported`（暂不支持）。缺少处置清单时会提示覆盖范围不明；没有可用记录时不会报告可检索导入成功。

## 原件、记录与来源时间

| 对象 | 保存内容 | 位置或关联 |
|---|---|---|
| 原件与附件 | 上传字节、相对路径、MIME、大小、SHA-256 | `MOTE_DATA_DIR/files/objects/<sha256>/` 分片资产，内容去重；文件 ID 关联记录和导入任务 |
| 导入任务 | 用户说明、预览、文件处置、计数、错误、关联 Memory 任务 | SQLite；`imports/<job-id>/` 保存解析工作产物，处理结束清理 `inputs/` 临时副本 |
| 归档记录 | 原文、来源 ID、外部 ID、不可变 revision、元数据 | SQLite，可通过检索和证据接口展开 |
| Memory | 标题、陈述、不确定性、状态、模型/Skill 版本、精确证据 | SQLite；不替换原文 |
| 洞察 | Markdown、引用、检索过程、运行编号、可选静态 HTML | 中央保存的回顾记录 |

内容加密默认关闭；显式开启内容加密后文件和图片对象才加密，单独配置 `MOTE_DATA_KEY` 不会开启加密；SQLite 和解析工作产物仍需依赖宿主磁盘权限及磁盘加密。模型运行时需要读取本次文件的临时明文副本。

每条来源记录保留 `sourceId / externalId / revision`。宿主分配文件 ID 和附件 ID，并验证它们来自本次提交的文件；模型不能用任意服务器路径作为导入依据。原文位置、引用偏移和散列可以一起追溯到当时的资料。

时间字段不能互相代替：

- `observedAt` / 归档记录的 `capturedAt`：采集器或导入过程观察到该版本的时间。
- `receivedAt`：中央实际接收记录的时间。
- `document.recordedAt`：原始资料明确提供的记录时间。
- `document.occurredAt`：原始资料明确提供的事件发生时间。
- `document.timeBasis`：来源明确采用的时间依据；未知时保持未知。
- `modifiedAt`：上游文件或条目的修改时间，不能证明事件发生或用户阅读。

普通来源记录的内容时间优先采用明确标记为 `occurred` 的发生时间，否则采用原文记录时间，最后才回退到观察时间。日历按计划起止时间匹配；它不能证明实际参加。导入时间、文件名和“今天”之类的原文不能单独建立真实事件日期。

`contentRole` 区分作者原文、逐字记录、摘要、引用文章和其他内容。AI 摘要属于派生资料；参考文章也不能直接当作用户的亲身经历。原始元数据保存为有大小和深度限制的 JSON，查询时仍属于不可信证据。

## Memory 如何分批并保留进度

生命周期自动提取和记忆页手动提取都使用持久任务。手动提取按选择的时间/设备范围取证据，也可通过 API 显式传入证据 ID。

- 正文按 UTF-16 偏移划分；默认每批最多 **12,000 个字符单位、20 个片段**，避免切断代理对。这是输入字符预算，不是 token 预算。
- 每批有独立的证据范围、尝试次数、状态与候选 ID。任务保存引用和范围，不另复制整份私人原文。
- Agent 只能读本批授权的证据范围，不能把搜索结果第一页当作整份导入。每次模型调用最多提出 8 条候选，也可以返回零条。
- 保存前校验引用 ID、原文精确引句及偏移、来源当前版本和内容指纹。模型运行期间原文变更或删除时，不能把旧结果当作当前记忆写入。
- 成功批次与完成检查点在同一事务中落库。相同证据、指纹、偏移和 Skill 版本已经完成时，不重复提取；失败批次可以重试。
- `skippedChunks` 同时包含已处理片段和没有可用原文的记录。仅有引用、派生摘要或空正文不会作为独立原始证据进入提取。

这些检查保证引用可定位和任务可恢复，不保证模型归纳在语义上正确，也不保证每个重要事实都会成为记忆。记忆默认 `proposed`；用户确认后为 `published`。来源变化会使相关记忆变为 `stale`，默认 Agent 检索排除旧记忆。确认状态不等同事实认证。

## 洞察是一个 Skill 和一份报告

`personal-insight` 使用同一个只读查询运行时，自主选择来源、时间线、统计、记忆和原始证据工具。它生成完整 Markdown 后备文本与静态 HTML，报告可以有卡片、表格、时间线和 CSS 图表。

宿主验证结果结构和 Markdown 引用，清理 HTML 的脚本、事件处理器、表单、框架、外部链接等内容。网页使用空 `sandbox` 的 `iframe srcDoc`，并固定 CSP 阻止脚本和外部资源请求。访问令牌、应用状态及数据接口不会传入 iframe。原文按钮、报告/文字切换和生成信息由宿主界面提供；报告不能执行日历、发消息或修改记忆等操作。

HTML 布局由模型生成，展示失败时仍可查看文字和引用。引用校验不能证明报告中的每句话都被证据充分支持；必要时应回到原文核对。旧版只有 Markdown 的回顾仍可打开。

## 支持的输入和当前上限

“原件可保存”和“正文可解析”分开处理。未知格式可以保留原件；模型可以使用会话中已有的工具编写解析转换，但不保证任何格式都能成功。

| 通用辅助程序 | 当前能力与限制 |
|---|---|
| TXT、Markdown、LOG | UTF-8 文本；不自动猜测其他编码 |
| JSON、JSONL/NDJSON、YAML | 保留结构，由模型决定字段含义；结构过大时要求明确分区，不静默解析截断结构 |
| CSV、TSV | 解析带引号的字段和换行；最多 20,000 行、500 列 |
| PDF | 读取已有文本层和页号；最多 500 页，不执行扫描件 OCR |
| DOCX | 提取段落文字；不保留完整页面布局，不识别内嵌图片文字 |
| XLSX | 读取工作表、单元格、公式及缓存结果；不重新计算公式；最多 100 张表、20,000 行、500 列 |
| ZIP | 保存容器并展开文件，再分别解析或关联附件；不提供任意深度的递归解包承诺 |
| 图片、音视频及其他二进制 | 可保存原件/附件；该通用导入解析器不自动执行图片 OCR、音视频转写或旧版 Office 解码；截图 OCR 与文件音频处理属于独立入口，见 [中央处理](file-processing.md) |

通用辅助程序通常最多输出约 2,000,000 个字符；达到限制会报告截断或无法完整提取。解析预览及模型说明仍须披露实际覆盖范围。

| 限制 | 当前值 |
|---|---|
| 单文件原件 | 64 MiB，包括 ZIP 展开的单项 |
| 单次输入字节总量 | 256 MiB；JSON Base64 会增加传输体积，入口代理也可能有更小上限 |
| 上传文件数量 | 请求最多 2,000 个；服务器目录/展开后总文件数最多 4,000 |
| ZIP 展开总量 | 512 MiB |
| 服务器目录深度 | 最多 30 层，不跟随符号链接，不允许导入 Mote 数据目录或其父目录 |
| 解析清单 | 最多 32 MiB、10,000 条记录；单条正文最多 100,000 个字符 |
| 自然语言导入说明 | 12,000 个字符 |
| Memory 单任务 | 最多 20,000 个证据 ID、10,000 个待处理片段 |
| Memory 总条数 | 100,000 条，达到后拒绝新增或校正；需移除不再需要的记忆 |
| 洞察关注方向 | 8,000 个字符 |

上述是实现上限，不代表建议一次处理到上限；总存储配额、模型输出预算和运行期限仍然适用。旧 `import:files --watch` 命令是独立的文本同步器，仍有每文件 100 KB 的限制，不具有中央通用导入的解析预览能力。

## 来源离线时能做什么

中央节点可部署在持续运行的服务器或 NAS。手机没电、端点 MCP 未启动或外部 NAS 离线时，中央仍能读取已经同步的原件、快照、记忆和报告。任务不需要在问答时重新唤醒原设备。

如果中央只有 Shadow 引用，则只能说明原件位置、最后观察时间和已知元数据，不能读取未同步的正文，也不会自动访问任意远程 URL。离线期间发生但尚未上传的变化属于未知；设备最后状态也不证明它现在在线。恢复连接后，由已有连接器或用户发起的导入带来新版本。

这不是端点间的对等记忆系统。中央节点停机时，中央界面、查询和后台任务不可用；采集端可按已有离线队列机制保留尚未上传的记录。

## 两种 Harness 会话，按能力区分

| 会话 | 能力 | 宿主负责什么 |
|---|---|---|
| 问答、Memory、洞察 | Mote 只读上下文工具，以及原生 `skill` 工具 | 固定工具清单、范围与引用授权、结果校验、派生结果持久化 |
| 通用导入 | 独立 Harness 会话；原生 `skill`、文件读写和 `bash` 等工具，可生成转换脚本 | 原件归档、输入/清单验证、预览确认、版本与幂等写入；随后启动独立 Memory 任务 |

查询运行时禁用 shell 和文件工具，并在工具表中拒绝未授权能力。导入运行时没有查询 Agent 的中央资料桥，也不直接获得“写入归档”工具；它输出清单，由宿主确认后保存。

**导入没有新增操作系统沙箱。** 独立工作目录、临时 Harness home、精简环境、输入文件校验，以及“只读取所选文件、不联网、不执行文档指令”的 Skill 提示，是工作约定和结果约束，不是对原生 shell 的文件系统或网络强制隔离。原生工具仍受运行服务的操作系统账户权限约束；模型传输的目标检查也不能限制 shell 自行启动的进程。不要把这套流程描述为不可信代码的安全执行平台。

格式解码、大小/路径验证、版本与幂等规则由确定性代码处理；资料的含义、人物、主题、任务与记忆价值由模型判断，没有应用名或语义关键词分发规则。

## 扩展一个 Skill

编码 Agent 对话另有按证据领域分流的 `coding-memory` Skill，采集、适用范围和验证口径见[编码经验设计](coding-agent-memory.md)。

内置 Skill 在 [`packages/agent/skills/`](../packages/agent/skills/)：`document-import`、`memory-extraction`、`personal-insight`。Harness 使用原生 Skill 注册与加载；Skill 是可复用任务说明，不是每个主题独立运行的常驻 Agent。

1. 在 `packages/agent/skills/<id>/SKILL.md` 写明输入、工作过程、输出结构、证据要求和失败时如何表达。资料内容始终作为不可信证据。
2. 在 [`src/skills.ts`](../packages/agent/src/skills.ts) 的 catalog 注册 ID、名称和说明，更新版本。当前 catalog 在模块加载时读取，部署修改后需重启。
3. 为入口选择能力。只读分析可沿用 `createAgent().query({skill, ...scope})`；如果使用现有报告结构，可复用洞察的 HTML/Markdown 宿主。新的副作用需要单独设计宿主 API 与授权，写在 Skill 中不会自动获得权限。
4. 若输出需要持久化，增加对应结构与引用验证；若需要不同网页控件，再扩展宿主组件。当前不是动态上传任意 Skill 或插件的平台。
5. 用合成记录测试工具范围、原始证据引用、结构错误、重试和旧结果兼容。修改 Memory 提取规则时更新其版本，避免错误复用旧检查点。

无需为每个分析方向复制 Harness 或任务队列。只有能力和运行生命周期确实不同，才需要像导入这样独立的运行入口。

## API 入口

以下是中央所有者管理接口，使用当前服务的 Bearer 认证，不应把管理令牌放入 URL。

| 接口 | 用途 |
|---|---|
| `POST /api/imports` | `{name?, processing?: "automatic"|"preview", sourcePackId?, instruction?, files:[{name,mimeType?,dataBase64}]}` 或目录导入；返回 202 和任务。指定 Source Pack 时不能同时传自由文本指令 |
| `GET /api/import-source-packs` | 列出部署节点已安装的受信 Python Source Pack 的 `id`、`version`、`description`；不返回本机脚本路径或哈希 |
| `GET /api/imports`、`GET /api/imports/:id` | 导入历史、预览、文件处置、`reviewDecision` 与宿主 `reviewGate`、进度、错误及关联 `memoryJobId` |
| `POST /api/imports/:id/prepare` | 可带 `{instruction}`；确认前重新理解资料 |
| `POST /api/imports/:id/confirm` | 确认预览并后台保存记录，返回 202 |
| `POST /api/imports/:id/retry` | 重试解析，或继续已经确认的记录保存 |
| `DELETE /api/imports/:id` | 删除整次导入及不再被引用的资料、原件 |
| `GET /api/archived-files/:id`、`GET /api/archived-files/:id/content` | 文件元数据和经认证的原件下载 |
| `GET /api/captures/:id/archived-files` | 某条原始记录关联的文件 |
| `POST /api/memory-jobs` | 按 `{after?,before?,deviceId?,timeZone?}` 或显式 `evidenceIds` 建立批处理任务 |
| `GET /api/memory-jobs`、`GET /api/memory-jobs/:id` | 任务历史、批次进度、候选 ID 和错误 |
| `POST /api/memory-jobs/:id/retry` | 继续未完成或失败的批次 |
| `GET /api/memories`、`GET /api/memories/:id` | 记忆概要与详情；`includeStale=true` 可包含待重验项 |
| `POST /api/memories/:id/publish`、`DELETE /api/memories/:id` | 确认或删除单条派生记忆 |
| `POST /api/insights` | `{after?,before?,deviceId?,timeZone?,prompt?}`；返回带引用的报告，可能有 HTML `artifact` |
| `GET /api/insights`、`GET /api/skills` | 已保存的报告与内置 Skill 目录 |

导入和 Memory 的 202 只表示任务已接收；应轮询任务状态。洞察接口仍等待模型完成后返回，不是持久的后台报告队列。

## 删除与重试

| 操作 | 实际影响 |
|---|---|
| 删除一条 Memory | 删除这条推导记忆，保留原始证据和文件；不清除已完成的批处理检查点 |
| 删除一条原始证据 | 删除该条可检索正文，清理依赖记忆并使相关派生回答失效；导入任务持有的原件与解析工作产物仍可能保留 |
| 删除整次导入 | 删除任务和工作目录；没有其他导入共享来源时删除对应记录及依赖记忆；仅清理没有其他导入或证据引用的文件对象 |

重复提交可能共享原件，甚至共享同一来源的记录。删除一个任务不会清除另一个任务仍持有的数据。若需要完整移除某次输入，不应只删除一条候选记忆或一条记录；应检查相关导入和共享引用。正在解析或保存的导入不能同时删除。

失败恢复遵循已保存的状态：

- **模型未配置或解析失败**：原件仍保留；需要模型映射的输入在缺配置时进入 `needs_configuration`，可补充配置和说明后重试。内置支持的直接文本/文档解码不依赖模型。
- **ZIP 展开受限**：原件保留；损坏压缩包或超过解包限制需要修复、拆分后新建导入，反复重试不会绕过限制。
- **保存记录中断**：服务保存逐条进度，重试继续未完成部分。不能修改已确认且开始保存的解析方案。
- **Memory 失败**：重试失败批次；成功的检查点保留。无模型时进入 `waiting_for_model`。
- **来源已变化**：失效批次不能继续使用旧指纹；应针对当前证据新建提取任务。
- **中央重启**：正在解析/导入的任务标记为需要重试；未开始的队列任务可重新准备。Memory 正在执行的批次恢复为待处理并继续排队，完成的批次不会重跑。

## 当前限制与验证口径

- 通用导入的解析效果取决于输入结构、模型及工具调用；扫描 PDF、图片文字、音视频和未知格式没有完整解析保证。
- 队列持久化在 SQLite，导入、Memory 等步骤通过共享执行器和资源池并发准入；没有多租户分布式任务平台。
- Memory 的精确引句校验是出处约束，不是自动事实核验、矛盾裁决或持续自我学习；用户可做版本绑定的记忆校正，生成独立原始笔记与确认版本；矛盾、替代和有效期通过模型提议及宿主确认维护，不会自动裁决全部矛盾或推断遗忘策略，见 [记忆更新](memory-updates.md)。
- 原件不会因为单条记录到期就自动从导入归档中删除。当前需显式管理整次导入；不要把记录保留期限理解成全部文件的清理期限。
- 旧 JSON v1 资料导出可包含通用导入原件字节、文件元数据/ID 和证据附件关系，但有二进制文件同步归档时会拒绝全量 JSON 导出，应使用完整备份；恢复会校验散列与引用，并按目标节点密钥重新加密，兼容没有文件字段的旧 v1。导出文件包含私人原文，应自行保管。导入工作目录、转换脚本、任务/批处理进度和模型凭据不在这份便携导出中；需要保留完整运行状态时使用离线备份，范围与恢复步骤见[部署文档](deployment.md)。恢复的 Memory 标记为需要重验。
- 原生 Harness、通用解析、任务恢复及报告展示有合成 fixture 测试。测试包含真实 Harness 子进程与模拟模型响应；这不等同真实模型语义效果、真实私人资料完整覆盖或物理设备验收。实网模型和真机结果应单独记录，不能从构建或 fixture 通过推导。

关键实现入口：[导入服务](../apps/server/src/imports.ts)、[解析辅助程序](../apps/server/src/import-parser.mjs)、[Memory 流水线](../apps/server/src/memory-pipeline.ts)、[报告处理](../apps/server/src/insights.ts)、[导入 Harness](../packages/agent/src/import-agent.ts)、[查询 Harness](../packages/agent/src/index.ts)。

## 后台任务独立推进与工具修复

提取、整合、工作记忆与洞察分别持有运行状态、增量游标、检查点和退避时间。同一种任务不重入，不同任务可同时推进，仍受全局 Agent、LLM 和批次并发配置约束。每个任务内部等待执行成功后才提交游标；慢洞察不会挡住提取的下一窗口。启动时恢复脱离生命周期检查点的 queued 整理任务；关闭自动提取时不自动恢复这类任务，paused/cancelled 不会被恢复。仍被活动窗口引用的任务由该窗口按退避时间接管。

洞察先查看精选 Memory，再按需查看 observation、segment 和原始证据。`memoryCoverage` 标明全库待处理/失败批次及最近保存时间，不能代表当前窗口的完整覆盖率。增量 `changes` 在洞察中默认返回 overview（ID、时间、来源、字符数），不会授权正文引用；需要时用 evidence 读取原文，或显式选择 text。最终事实仍须核实原始证据，预算不足应明确报告覆盖范围，不能把没有整理出的记忆当成没有发生的事件。

只读工具失败会在当前 Agent 对话返回 `toolError`：code、message、recovery 和 details。范围错误包含允许的绝对 UTF-16 区间，预算错误给出剩余预算。宿主生成的参数错误可以反馈，底层异常原文不会成为模型指令。同一错误和参数重复三次或继续超出工具调用预算会终止运行；原始证据已删除或修订时也停止使用旧授权。成功保存前原有引用和版本校验仍然生效。

普通 NDJSON 日志增加 `agent.tool_rejected`，保留受控错误码、运行/批次关联和剩余预算；开启 agent trace 后，同格式日志还记录允许范围、修复反馈及调用过程。普通日志不包含引用正文或任意底层错误文本。
