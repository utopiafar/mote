# 客户端统一登录

## 登录契约

Mac、Android 和 Web 客户端在选定的中央节点登录一次，即可使用该客户端的所有中央功能。客户端登录与节点访问 Token 拥有相同权限。设备身份用于记录来源、同步绑定和连接管理，不再限制已登录用户只能访问自己的设备数据。

未登录时可使用一次性配对邀请、手动访问令牌或浏览器授权。已经登录后，问答、资料库、设置或从客户端打开的中央网页不会另行要求输入 Token。退出、过期或撤销后统一停止访问；重新登录属于恢复中央连接，不是单个功能的第二次授权。

## 原因与修复

旧版存在两层分裂：中央把配对客户端作为受限 `collector`，拒绝问答和管理 API；Mac 的问一问、Android 的中央页面又各自保存了一份管理会话，无法接续已有采集连接。因此，只修补问一问的登录提示无法覆盖其他功能。

中央现在把新客户端凭据签发为 `owner`，并直接赋予历史 `collector` 凭据相同权限，无需更换已有 Token。所有中央 API 和连接器管理使用同一权限判断。独立的有效性检查仍在采集、随手记和来源数据提交前执行，防止撤销期间的迟到写入。

Mac 使用主进程的统一配置，问答不再保存单独的管理 Token。Android 原生中央页面与后台任务共同读取加密 Settings；旧管理会话仅在同节点、主连接为空且仍有效时迁移一次，随后删除旧文件，退出后不会回退。已登录界面隐藏节点 Token 输入项，更换节点或退出后才显示连接入口。

## 影响范围

| 范围 | 统一登录后的权限与行为 |
| --- | --- |
| 问一问 | 查询、会话历史、恢复运行、取消、引用读取共用当前连接 |
| 资料库 | 资料、截图、媒体、来源、文件及其原文访问使用完整客户端权限 |
| 管理 | 模型、运行设置、连接器、设备与连接授权等使用同一登录 |
| 导入与导出 | 导入、备份、导出和恢复相关 API 不再因配对身份被拒绝 |
| 后台 | 截图、随手记、来源、文件上传、心跳及日历动作使用相同的有效凭据 |
| 浏览器 | Mac 打开中央页面接续登录；未登录的 Mac/Android 可经浏览器确认授权 |
| 现有连接 | 历史 `collector` 凭据自动获得完整权限；原有撤销状态仍有效 |

完整权限包含跨设备资料读取、管理设置、连接签发以及 Token 原本允许的删除与导出操作。配对邀请也因此授予完整客户端权限；连接页面明确显示这一点。原来的“配对设备仅能访问自身来源”不再是人类客户端的权限边界。

MCP 读权限与指定来源写权限仍独立受限，不能进入客户端管理 API、批准登录或签发完整客户端凭据。模型服务商 API key、外部 OAuth 和操作系统采集权限仍由对应服务管理，不是重复的中央节点登录。

## 生命周期、传递与队列

- 客户端会话支持本次应用/标签页、1 天、7 天和 30 天。定期会话具有服务端有效期；本次会话由本地进程或标签页限制使用，服务端凭据可通过退出或连接管理撤销。
- Mac 不落盘保存本次应用会话的 Token；Android 以进程标识限制加密凭据恢复。来源检查点保留哈希绑定，使应用重启后仍能恢复原节点的待同步版本。
- 退出先在本地停止使用凭据，再尝试服务端撤销。节点离线时本地退出仍生效；其他持有同一凭据的客户端要等服务端可用并完成撤销后才受影响。
- 服务端撤销立即拒绝后续请求；Mac 定期验证连接，Android 及后台请求通过统一的 401 处理失效，页面恢复或下一次请求也会检查。浏览器重用原生凭据，撤销同样作用于它。
- 迟到的请求、授权结果和旧节点响应不能覆盖新登录。Mac 在网络返回及串行配置提交时检查代次，放弃的新签发凭据会撤销。Android 和浏览器也校验当前会话。
- 退出不删除已归档资料、待同步队列或本地草稿。同节点重新授权保留待处理版本；更换节点继续遵守队列绑定，不能把旧节点资料静默送往新节点。

原生到浏览器的跳转只携带 60 秒、一次性代码；服务端内存保存交换材料，URL 不含长期凭据。浏览器到原生授权使用 10 分钟请求、随机 verifier 的 SHA-256 challenge 和用户确认；轮询只向持有 verifier 的客户端交付凭据，确认接收后删除请求。票据、请求、并发批准与轮询均有容量或频率限制。

## 升级与回退

先部署中央，再更新 Mac、Android 和 Web。新客户端需要新的会话和授权交换 API；旧中央不会提供完整客户端权限，登录检查会要求升级。中央升级已放宽历史配对凭据权限，但旧客户端自身的独立登录界面需要随客户端更新才能消除。

捕获资料和归档数据库无需迁移；连接注册文件新增 `owner` 范围和可选过期时间。旧版中央使用严格解析，不能读取这些新条目，因此回退前应备份注册文件，并在安全停机、按原版本恢复连接配置后重新授权客户端。不要直接用旧版中央打开新连接注册文件。回退也会恢复旧权限限制。
