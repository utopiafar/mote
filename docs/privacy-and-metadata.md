# 应用分级与元数据

从 0.7.0 起，Android 和 macOS 采集器支持按应用选择采集级别。先升级中央节点，再升级客户端；旧中央节点不认识活动事件及新增字段，会拒绝上传，客户端保留队列并显示错误。

## 设置采集范围

| 级别 | 保留什么 | 端上处理 |
|---|---|---|
| 采集内容 `content` | 允许的截图、可选 OCR、应用标识与名称、采样时间及启用的元数据 | 识别应用与可见窗口，再截图；固定遮罩、可选文字规则审查、编码、入队；完整 OCR 在中央生成 |
| 仅应用活动 `activity` | 前台应用标识与名称、采样区间、启用的设备状态 | 不请求该次截图，不读取窗口标题、正文、OCR，不运行视觉模型 |
| 不记录 `off` | 不为该应用产生采样记录 | 在获取画面前跳过；不会把跳过的时间补算给下一个应用 |

在采集 App 设置中选择默认级别，再添加应用例外。规则匹配 Android package ID 或 Mac bundle ID，不按应用名称、内容关键词或模型推断的主题匹配。旧版排除列表继续生效，优先于默认级别和应用例外；Android 新安装默认仅应用活动；从旧版升级默认仍为采集内容，不会清空既有遮罩或审查配置。

例如，默认设为“仅应用活动”，再把编辑器设为“采集内容”，把密码管理器设为“不记录”。这些应用由你明确指定，Mote 没有内置工作、娱乐、敏感应用等语义黑名单。随手记、文件和日历属于单独主动授权的来源，不跟随屏幕应用规则开关。

选择默认完整内容采集时允许系统桌面、启动器和无明确前台应用的画面，不因缺少应用身份自动停采；应用身份未知时不伪造名称或活动时间。已识别的可见窗口仍执行用户配置的分级规则，遇到仅活动或不记录的窗口时跳过整张画面。若存在显式排除或限制级别且无法确认窗口身份，仍保守跳过，以免绕过用户规则。Android 键盘和内容浮层仍遵守规则；经系统身份与窗口几何校验的导航栏有窄范围豁免，包括已验证的 Xiaomi 导航面板，见 [采集恢复](android-capture-recovery.md)。这不豁免启动器 Activity 或任意系统浮层。仅活动分支仍需可靠的单一应用身份，且不读取窗口正文。屏幕切换期间的帧不进入队列。

macOS 的纯活动分支不申请屏幕录制权限，不枚举窗口内容。Android 纯活动模式需要已授权的无障碍服务来识别应用；无需为纯活动申请 MediaProjection。混合策略使用 MediaProjection 时，系统仍要求每次会话确认，画面输出 Surface 只在该次内容采样获准后短暂挂接。停止、锁屏、规则变化或身份变化会取消待处理帧。系统权限和后台存活约束见 [Android](android.md) 与 [macOS](desktop.md)。

修改应用规则和设备元数据开关影响后续采样；已经按旧策略保存的屏幕、活动或笔记队列继续按原事件上传。需要清理既有数据时，应处理本地待上传记录与中央归档两处。文件/日历同步另有来源策略：变更选择、过滤或保留方式会废弃旧策略下尚未发送的来源正文，重新扫描授权范围；中央已归档的历史版本保留。

## 上报的元数据

原始记录中的应用标识 `appId` 必须同时携带应用名称 `appName`，截图、应用活动、通知及媒体会话均适用。名称来自采集时系统提供的应用标签，不受设备元数据开关影响；系统无法提供名称时标记为“未知应用”，仍保留原始包名或 bundle ID。中央节点会拒绝只有标识、没有名称或名称为空白的上传；已归档的历史记录不会被改写。无应用归属的设备状态事件不添加应用名称。

设备元数据开关默认开启，可在客户端关闭。关闭后保留传输与时间统计必要的设备 ID、应用标识与名称、采样时间、时长和隐私级别，不再附带额外设备状态；不会取消你对文件来源本身的授权。

采集、笔记和心跳可附带 `metadata`，版本为 1。每个字段都可独立缺省，只有 `version` 和本次元数据的 `observedAt` 必填。元数据观察时间可能晚于截图开始时间，例如模型审查完成后才测得电池状态；不得将两者互换。

| 字段组 | 可上报内容 | 边界 |
|---|---|---|
| `collector` | 客户端版本、实际采集方式 | 不包含模型提示词或访问凭据 |
| `device` | 系统版本/构建、厂商、型号、架构、地区、时区 | 不包含序列号、IMEI、硬件 MAC 地址 |
| `state` | 电量、是否充电/使用电池、省电模式、温度状态、网络类型/计量状态、屏幕交互/锁定、空闲秒数、可用存储 | 各端仅发送系统实际提供的字段；不含 SSID、网络密码、IP 列表、定位或通知正文 |
| `capture` | 采样间隔；内容采样可带像素尺寸、缩放、是否 OCR、遮罩数 | 活动事件只允许采样间隔，不接受尺寸、OCR 或遮罩字段 |
| `media` | 系统提供的播放应用、状态、位置、前后台、本机／远程播放与允许保留的曲目／章节信息 | Android 单独开启并授权；沿用播放器的应用隐私规则，媒体快照保留独立观察时间，不录音或采集普通通知正文 |

Android 支持仅屏幕、仅媒体或同时采集。锁屏结束截图会话后，已开启的媒体采集继续运行；总停止、关闭媒体或元数据、充电／电量限制均影响后续媒体观察。独立媒体记录使用 `source: "media"`，与截图附件去重计时；“仅活动”播放器不会在截图、心跳或独立媒体记录中泄漏曲目等内容。详见 [媒体采集模式与边界](media-context.md)。

心跳只表示最近存储的设备报告（首次上传也可能初始化此报告），不是完整状态历史，也不证明历史期间一直采集；其中上次采集时间不代表归档中最新一条记录，报告状态也不等于实时在线探测结果。Agent 收到的健康报告与归档证据分开表示。每条活动/内容记录保留自身元数据，可按观察时间回看。配置关闭某些元数据不等于系统能力不存在；缺失不是 `false`、零或“从未发生”。

中央节点保存元数据原始结构，在证据详情、设备页和来源详情中可展开查看。活动记录明确标注“仅应用活动”，不显示“缺少 OCR”或“截图失败”。诊断支持包继续保持无正文、无应用名称和无令牌的固定字段，不能把原始归档当作可公开的诊断日志。

截图的顶层 `ocr` 字段记录 `pending` / `completed` / `disabled` / `failed` 及可选原因与更新时间，不受设备元数据开关影响。旧记录没有该字段时，界面根据已有明确证据展示状态；没有文字和处理证据的记录显示未知。该字段仍兼容旧版本机 OCR 补写；新截图上报 `ocr.status=disabled`，完整 OCR 保存为中央独立派生产物，不改写原始采集事件。

## 文件与日历时间

来源条目已有 `observedAt`（扫描观察时间）、`modifiedAt`（源报告的内容修改时间）、`receivedAt`（中央接收时间）、`revision` 与当前/历史指针。新增 `metadata` 中的稳定属性随来源版本保存，并进入版本校验；原件仍可留在 NAS 或文件提供方，仅保存引用也能保留允许的元数据。

| 来源字段 | 含义与可用性 |
|---|---|
| `metadata.file.sizeBytes` | 扫描时源文件大小；不是压缩后截图大小或中央存储占用 |
| `metadata.file.createdAt` | 能区分出真实文件系统创建时间时提供；缺失、零或可能回填的值不冒充创建时间 |
| `modifiedAt` | 文件/提供方报告的最后内容修改时间 |
| `metadata.file.accessedAt` | 文件系统访问时间；同步进程也可能更新，不能证明用户阅读 |
| `metadata.file.metadataChangedAt` | 文件属性变更时间（ctime），不是创建时间 |
| `metadata.file.deletionObservedAt` | 完整扫描首次发现条目消失的时间，只存在于删除版本；不是真实删除时刻；移动、重命名或提供方变更也可能导致条目消失 |
| `metadata.provider.createdAt/updatedAt` | 日历等提供方直接给出的创建/更新时间，不是日程开始时间或参加证明 |

Mac/CLI 从打开的文件句柄读取属性并确认扫描期间内容未变。访问时间使用持久的读取前后标记，避免同步器自己的读取让每轮扫描都制造一个新版本；外部访问时间变化仍可产生新版本。不会为了稳定版本而修改原文件时间。Android SAF 和网页文件选择器只报告它们实际提供的大小、修改时间等，不推造创建或访问时间。来源不完整、权限丢失或超出扫描限制时，不把未看到的文件当作已删除。

[Node.js 文件系统时间文档](https://nodejs.org/api/fs.html#stat-time-values)说明 birthtime 在不支持的文件系统上可能回填 ctime 或零值，访问时间也可能被系统读取操作改变。因此这些时间应作为有来源的观察，而不是用户行为结论。

## 归档、索引与 Agent

活动使用 `source: "activity"` 和 `privacy.collection: "activity"`。服务器拒绝活动事件携带图像、窗口标题、正文、心情或文件引用，不生成占位正文，也不把它送入 embedding 索引。数据使用已有的持久队列、幂等 ACK、删除墓碑、增量变更与导入导出协议。

中央为应用标识和来源类型建立结构索引；时间线、检索、活动统计及对应 MCP 工具可使用精确 `appId`、`source`、`collection` 筛选。检索表达式和是否调用这些工具由 Agent 决定。设备/文件状态通过有界的证据投影提供，不按元数据硬编码任务或洞察。

活动统计同时接受内容采样与无内容活动区间。同设备重叠区间先去重，再按应用或级别筛选；不同设备分别计入。`captures` 兼容表示全部采样记录数，`contentCaptures` 与 `activityEvents` 分别统计两类记录；日记、文件和日历不是额外的屏幕或活动采样。应用切换、停止、锁屏、过滤或采样失败会断开连续计时，空白期不补齐。

Agent 可以回答已观察到哪个应用、采样覆盖多少秒、当时上报了哪些状态；只有活动元数据时不能回答看过什么内容、完成了什么任务。源访问时间、日历时间和删除观察时间也不应被当作完成证明。详细字段及示例见 [协议](protocol.md)。
