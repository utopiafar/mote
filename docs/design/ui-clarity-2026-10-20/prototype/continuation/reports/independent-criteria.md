# Mote UI 独立验收标准与 R15 基线

## 范围与独立性

本报告先固定首次理解，再依据可见界面自主选择路径。评估者未读候选 HTML 的实现、应用内部 state、作者改动记录或历史评分。只通过公共 `capture-dom.mjs` 的 `observe` 读取可见文字与控件，并通过这些控件行动；所有输入和原型资料均为合成数据。

基线候选：`docs/design/ui-clarity-2026-10-20/prototype/dist/rounds/r15.html`。SHA256：`65257ad350e155a01bd1e64c3241e812bff98c93fda593be70de2dae17bf32f9`。

交互证据来自 jsdom 26.1.0 的 DOM/样式可见性观察。完成有界的任务探索后，另用隔离的 Chrome 133.0.6943.16 补充三张首屏画面：桌面已有资料、桌面空白账号、Android 窄屏已有资料；请求全部本地拦截，使用共享工具提供的中文字体。没有读取内部应用状态，没有真实个人数据，也不是人类被试测试。**本评估者现在已见过 R15；后续复评是与实现独立的评估，不称为完全盲测。**

## 操作前固定的首次理解

Mote 是一个个人资料库：汇集文件、随手记与多个来源，用于查找、提问，并回到原文核对。已有资料时，我会先搜索或打开一条资料；有待保存的内容时，我会找“随手记”或“添加内容”。界面解释了三个产物：资料保留原文，记忆整理长期信息，洞察回顾一段时间的变化。

初看仍有待澄清的边界：“资料出处”与主导航“来源”有什么不同；顶部“随手记”与资料分类中的“随手记”是否分别用于创建和回看。已有资料首页同时提供资料、整理与回顾、原始记录和导入管理，能否一眼分清主次必须由真正的页面画面确认，不能据 DOM 数量直接判差或判好。

首次理解已在任何任务执行前保存到 [r15-initial-understanding.json](../evidence/independent/r15-initial-understanding.json)。

### 后补的视觉观察

桌面已有资料页（1440 × 1000）在首屏同时呈现用途说明、搜索和高对比“添加内容”按钮。多组分类放在次级侧栏，以组标题和较轻文字区分层级，没有 DOM 文本平铺时看起来那么拥挤。空白账号的“从一份资料开始”和“导入一份文件”主按钮明显，旁边保留随手记与连接来源选择。

Android 预览（390 × 844）把分类收成资料/记忆/洞察标签与分类下拉；用途、添加入口、搜索和第一条资料都在首屏，底部导航清楚。三张页面的实际宽度均等于视口宽度，没有观察到横向溢出。该视觉判断支持主要入口可见，但未执行窄屏交互，不能扩展成全部移动页面可用，也不能把熟悉 R15 后看画面重新称为首次盲看。

## 冻结后的验收标准

以下标准面向用户结果，不要求沿作者预设的按钮顺序完成。每项只报告“通过、部分通过、未通过、未验证”；不把入口存在或工具执行成功当成用户目标完成。

| 编号 | 要验收的结果 | 足够的证据 |
| --- | --- | --- |
| C1 用途和第一步 | 新访者能从首次画面说明“收集什么、保存在哪里能做什么”，并选出一个适合当前有资料/无资料状态的下一步。主任务视觉突出。 | 先看首屏截图并写下理解，之后才操作；分别检查已有资料与空白状态。DOM 文案只能验证表达，不能代替视觉判断。 |
| C2 功能边界和重点 | 添加、回看、提问、持续来源管理各有清楚职责；资料、记忆、洞察能被正确区分。相同名称若出现在多处，去向符合上下文。 | 用户凭任务选择入口后的实际去向、关键分类文字与视觉层级。完整的“没有功能遗漏”还需与独立需求清单核对，不能仅从看到的入口反推。 |
| C3 保存到使用的闭环 | 记下合成内容或导入示例之后，有可辨认的结果；离开保存页，仍能从常规资料入口找回并核对正确正文。空账号不再错误地保持空状态。 | 实际输入/选择、完成反馈、离开后的列表或搜索结果，以及打开后的正文；明确这里只验证原型会话，不声称持久化或真实上传。 |
| C4 范围与标签可靠 | 用户选择的资料、来源、问题范围和返回目的地均与显示标签一致；界面能说明当前范围并允许恢复。 | 从“此来源资料”进入后只显示该来源；标为“返回资料库”的操作实际回资料库，或将标签改为实际去向。检查页面内容，不靠路由属性猜测。 |
| C5 问答核对闭环 | 能输入具体问题，看清正在使用的资料范围和示例/真实状态，打开相关出处正文及原始内容，再返回原对话；原问题和回答保留。 | 问题、答案、引用正文、原始内容和返回后的会话截图/可见快照。示例回答应明确标识；本次不评真实模型的答案质量。 |
| C6 来源可控 | 连接新来源与编辑已有来源可区分；用户在确认前知道收集范围和保存方式，操作后能辨认具体来源状态，暂停不会被误解为删除，已保存资料仍可访问。 | 新建前后具体来源、确认文案、暂停后的状态、查看该来源资料的实际结果。若原型不支持多来源实例，应明确表达限制，不能将“连接”悄悄变成改写已有来源。 |
| C7 过程不丢路 | 完成、取消、返回、关闭弹窗和恢复操作不丢当前任务上下文；失败/未配置状态有下一步；窄屏关键控件仍可到达。 | 任务中的实际往返、结果与必要的一次错误恢复；最终浏览器证据覆盖桌面与窄屏。未执行的分支、平台、系统权限一律写明未验证。 |

验收时优先处理造成错误目标、错误范围或误以为已完成的问题。只调整措辞或视觉的建议与明确功能阻碍分开记录。冻结候选只做一次完整独立复评；发现问题后仅围绕具体残余风险补查，避免不停迭代打分。

## 自然任务卡

任务先给目标，不给按钮名、页面名或固定顺序。可使用新的合成名称和日期，避免仅靠记住 R15 路径完成。

| 任务 | 给评估者的目标 | 完成判据 |
| --- | --- | --- |
| G1 保存后找回 | 把一条合成会议决定保存下来。离开后，只按记得的关键词找回，并确认日期和负责人没有丢。 | 从常规资料入口找回，打开后正文与输入一致；不能只停在“已保存”提示。 |
| G2 提问并核对 | 想知道资料对“如何让新用户清楚第一步”有什么建议。提出具体问题，检查出处，并回到原问题。 | 原问题保留；回答/示例状态清楚；能阅读引用与原始内容并返回，知道是否真正回答或只是演示。 |
| G3 连接并控制来源 | 想让电脑上的一批资料以后持续进入 Mote。了解范围与保存方式，连接适当来源，再暂停，并确认过去的资料仍在哪里。 | 新建与管理没有混淆；范围与状态清楚；暂停后能回看该来源资料；模拟与真实连接边界明确。 |
| G4 第一次获得资料 | 从空白账号出发，自己选择一种合适方式获得第一份资料，然后到资料库打开它。 | 能凭首屏选择第一步；添加完成后出现对应可阅读资料；返回、结果名称和可见状态一致。 |

## R15 一次基线观察

| 任务 | 自主走过的实际路径 | 结果与阻碍 |
| --- | --- | --- |
| G1 | 顶部随手记 → 输入合成“蓝鲸项目”会议决定 → 保存 → 主导航资料库 → 搜“蓝鲸” → 打开结果。共 6 次动作。 | 原型会话内通过。保存有明确反馈，搜索得到 1 条对应资料；日期、负责人和尾句完整保留在正文。未测刷新持久化。 |
| G2 | 问一问 → 输入具体问题 → 提问 → 产品评审引用 → 查看原始内容 → 关闭 → 返回对话。共 7 次动作。 | 引用/正文/原始内容/返回的 UI 闭环通过，问题与示例答案保留。回答区同时出现“演示未配置模型”，但又给出完成形态的答案；示例与状态说明需要更明确。示例答案并未直接回答具体问题，这一观察保留，但不据此评价真实模型质量。 |
| G3 | 来源 → 连接来源 → 同步文件夹 → 暂停此来源 → 浏览此来源的资料。共 5 次动作。 | 部分通过。暂停后明确说明已保存资料仍可阅读。“连接来源”却带到已在同步的“研究资料”编辑界面，新建目标没有完成；随后“浏览此来源的资料”打开全部 6 条资料，含随手记、日历等其他来源，范围丢失。 |
| G4 | 切换空白账号 → 导入一份文件 → 选择示例文件 → 选研究资料.md → 填合成标题 → 开始导入 → 查看导入结果 → 返回资料库 → 主导航资料库。共 8 次产品动作，另 1 次演示状态切换。 | 第一份示例资料确实可阅读，并出现在资料库唯一一条结果中；正文清楚写明是示例。“返回资料库”实际回到了导入完成页，需额外用主导航恢复。 |

### 明确发现

| ID | 观察到的问题 | 用户影响 | 证据 |
| --- | --- | --- | --- |
| B01 | 从连接目录选择同步文件夹，却打开现有“研究资料”的“保存设置/暂停此来源”界面。 | 想新接一批资料的人可能误改现有来源，或无法判断是否支持新增。 | `r15-source.dom.json`，第 3 步后。 |
| B02 | “浏览此来源的资料”返回全部 6 条资料，来源筛选仍是“全部来源”。 | 入口承诺的来源范围不成立，不能直接确认该来源的历史资料。 | `r15-source.dom.json`，第 5 步后。 |
| B03 | 导入结果详情的“返回资料库”回到“导入资料 / 导入已完成”。 | 返回标签不可信，多一次寻找正确入口。 | `r15-empty.dom.json`，第 8 步后。 |
| B04 | 同一问答区域既显示完成答案，又有“演示未配置模型”按钮。 | 无法清楚分辨当前模型状态、示例结果与用于演示故障的操作。 | `r15-ask.dom.json`，第 3 步后及返回对话后。 |

B01–B04 均为可见界面观察，不据此推断实现原因。首次理解中的“资料出处/来源”“随手记重复”暂是待观察边界，不冒充已证实缺陷。
