# Mote UI：R19 最终方案与独立评估

日期：2026-10-21。评估对象是自包含 HTML 中的信息架构、视觉、文案、可发现性和可操作的模拟状态。所有资料、账户、权限、连接、模型回答与任务结果均为合成演示数据。

## 1. 本次交付与结论

**本批 HTML UI 方案定稿为 R19。** 已确认的来源范围冲突、功能细项缺口、内容保留与状态问题得到修正；三个全新评估上下文都能说明用途，并在没有路径提示时找到入口、完成各自的代表性目标。最后由首访发现的长对话标题越界，也经过独立有界复核。

累计独立语义矩阵为 **20 类 / 78 项主要用途支持，0 项主要入口缺失、0 项已确认范围冲突**；五维评分为 **75 / 100**。这份结果不等于所有条件分支或真实业务闭环均已执行。严格规程的八项门槛在本报告中归为 **6 项在约定范围内通过、2 项证据部分满足**：未穷尽所有 P0 条件分支，且早期部分历史原件仍缺失。两项限制保留，不改写成全部通过。

- [mote-ui-final.html](dist/mote-ui-final.html)：最终单文件原型，下载后直接用浏览器打开，无需安装 Mote 或配置运行环境。

## 2. 方法：先功能真值表，再生成和独立评估

参考 [Anthropic 的 harness 设计文章](https://www.anthropic.com/engineering/harness-design-long-running-apps)，继续采用生成器与评估者分离、冻结候选、保存观察和操作证据、围绕反馈修正，以及最后比较候选的做法。保留 Design quality、Originality、Craft、Functionality，增加用户要求的 Clarity。

本项目权重为 20 / 10 / 15 / 30 / 25，各维取 0–4 整数，总分为 `Σ(权重 × 分项 / 4)`。权重、刻度、78 项清单和验收门槛属于本项目方案，并非文章给出的统一公式。评分不会覆盖具体功能反例；入口可达也不等于所有操作通过。

功能母表来自仓库基线 `2c78ca8d52a7d17fae20962cf68d09a717ffc73a`，保留原有 42 个 core、36 个 advanced 编号，共 78 个单元，再按用户任务归为 20 类。没有为了提高覆盖率删减分母。[源码盘点](../../feature-inventory.md)和[冻结清单](../../feature-manifest.json)说明原能力、平台与主要归属。

实现 agent 只负责 HTML 与作者验证。知情独立评估者先固定 C1–C7 与自然任务，依据可见 UI 自己选路，不读候选 JavaScript 或作者测试脚本。全新上下文评估者先看真实首屏截图并固定理解，再执行目标；最后比较时披露已见过最终候选的熟悉度边界。

本次新增证据主要来自隔离的 Chrome 133.0.6943.16，真实渲染 HTML 并操作可见控件；部分定向状态检查使用 jsdom。所有网络请求被本地拦截。截图与可见 DOM 相互补充，未读取应用内部状态来代替 UI 结果。它们与旧轮的 WeasyPrint 静态排版材料明确分开。

### 重要修正

1. **新建、编辑与范围可信。** 新文件夹用独立身份保存，名称相同也不串资料；离开详情再返回仍保持范围。飞书工作详情使用该来源实际的模拟保存数量，活动卡与资料库都保留同一来源筛选。没有为匹配文案虚构已同步资料。
2. **三种暂停分别表达。** 暂停屏幕记录、暂停某个来源接收、暂停向中央发送有各自的确认和状态。全局恢复发送不会顺便恢复另行暂停的来源；暂停保留已保存内容。
3. **保存内容不会只剩成功提示。** 记忆当前正文、纠正历史、继续整理采用内容保留完整两句话；笔记离线队列可看正文和附件、重试或取消本机编辑，避免重复创建；新模拟账户有独立工作台，返回旧账户可找回旧草稿。
4. **记忆能查、能回看、能解释适用范围。** 新增搜索、当前 / 按时间 / 全版本视图、有效时间、替代关系、适用边界。没有矛盾关联时明确写明，未编造冲突；继续整理之前说明会采用已保存全文并保留当前记忆。
5. **内容查找更完整。** 已发布资料与原始记录增加设备筛选；截图可按日期、设备、会话或应用分组，再打开原件。该截图样本只有一条，分组入口和同一证据的衔接已验证，多截图复杂组合未据此宣称通过。
6. **补齐此前只见入口的细项。** 来源可说明内容与自己的关系；每次导入可单独查看和改变图片处理方案；账号页显示当前服务、中央节点和模拟登录保留期；应用使用记录用实际样例时长计算百分比并说明采样窗口与缺口。
7. **对外读取范围更具体。** 可以对某个具体问题预览指定只读授权下的资料 / 记忆上下文，再打开依据并返回。这里采用本地样例文本匹配来演示结果状态，没有调用模型，也不是生产检索策略的实现提案。
8. **中英与小屏同步。** 新功能的静态、动态提示和表单项均补英文；用户原文、标题、路径和设备名保持原语言。Android 的本机文件与结果设备文案与当前预览平台一致。

### 候选比较

先固定 R15、R17、R18 三个候选和相同的资料库、来源任务、记忆整理结果画面，以中性标签呈现并轮换顺序；三位首访评估者在完成任务后分别比较。标签映射为 reed=R15、pine=R17、stone=R18，评估时未提供映射。

| 评估者 | 查看顺序 | 实际结论 |
| --- | --- | --- |
| A | R15 → R18 → R17 | 范围与逻辑的综合判断偏好 R18；R15/R17 并列，整体视觉基本并列。[报告](reports/blind-r18-a-comparison.md) |
| B | R18 → R17 → R15 | R18 的来源范围说明更可信；未强排另两版，总体结构和视觉接近。[报告](reports/blind-r18-b-comparison.md) |

三位均指出 R18 在“此来源 0 份、其他来源各自保留”的解释上更清楚；**没有形成三位一致的全产品总排序，也没有证明 R18 的整体视觉优于另外两版**。静态比较不代替真实点击。比较者已看过 R18 首屏并完成任务，属于有既往暴露的遮名比较。

选择 R18 的功能与结构基础，再采用 R19 的窄排版修正。R19 没有被伪装成参加了这组静态比较；最终的 R15/R19 对照文件是给用户查看的工具，不是三位评估者的原始比较材料。

## 8. 边界、历史与复现

- 这是 HTML UI 验收。真实登录 / 会话期限、文件上传、来源同步、系统授权、后台任务、模型质量、跨设备存储和性能未验证；这些不是本次用户要求的验收范围。
- 78 项的“主要用途支持”保留每项的未测条件；不能解读成 78 项真实端到端功能通过。记忆历史与截图分组使用有限样例，未测任意数量、多冲突或复杂并发。
- 尚未进行完整无障碍审计、真实设备触控测试或对比度数值审计。当前视口结果只对应所列截图与操作。
- 原 15 轮中的 R9–R14 候选及部分后期原始材料仍缺失。此次 R16–R19、独立复评和新首屏证据完整另存，不称为恢复了旧原件。原 R15 的 75 分与 R17 更细的语义评估不可当作同一固定样本的升降曲线。
- 运行最终原型只需要浏览器打开单个 HTML。顶部可重置演示并切换平台、资料状态与外观；英文在设置的语言与外观中切换。数据仅用于演示，账号页也明确采用模拟状态。
- 维护原型时从冻结候选和 `continuation/scripts` 的明确合并记录开始。旧 `prototype/build.mjs` 对应较早的源检查点，不能用于覆盖这次最终候选。所有候选哈希见 `reports/r16-freeze.json`、`r17-freeze.json`、`r18-freeze.json`、`r19-freeze.json`。
