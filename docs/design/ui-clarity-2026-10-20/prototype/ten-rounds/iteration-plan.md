# Mote：三端 UI 的十轮迭代

日期：2026-10-21（北京时间）。从冻结 R19 继续，新增 R20–R29，共十轮；每轮同时产出 Web、Mac、Android 三个自包含 HTML。

## 本次目标

新用户在首屏理解产品用途，选择第一步，完成首次保存、找回与核对；常用功能重点突出，原有 20 类 / 78 项能力保留明确入口。Web 以跨来源管理为中心；Mac 体现本机记录、菜单栏状态与桌面操作；Android 体现触控、底部导航与并列的本机来源入口。

## 评分

独立评估冻结六维：设计质量 15%、原创性 5%、完成度 10%、功能性 25%、逻辑清晰 20%、新用户友好度 25%。五个新用户分项为用途理解、第一步、权限与连接、首次价值与核对、渐进披露。每端分别评分，三端等权汇总，同时列最弱端。各端功能性、清晰度、新用户友好度至少 3/4 且已观察关键阻断清零为本次检查门槛。85 分是改进参考目标。

完整口径见 rubric-independent.md / .json，独立评估者在查看新候选前固定。每轮的首屏解释记录在点击操作之前；连续评估者的既有知识和最终新上下文检查分别记录。

## 每轮顺序与留存

1. 根据用户要求或上一轮独立发现，写 changes/rNN.json，说明具体修订与核对目标。
2. 修改共享层及对应平台层，保留 R19 原件。
3. build.py 冻结 rounds/rNN/web.html、mac.html、android.html，以及源快照、变更输入、评分规程、SHA-256 清单。已有轮次拒绝覆盖。
4. 在隔离浏览器渲染三端，保存首屏与目标页的截图、可见 DOM、错误和溢出结果。
5. 独立评估者通过可见界面完成目标，保存逐端观察、问题、评分和实际动作。生成者以这些发现决定下一轮。
6. 当前轮评估保留后，再冻结下一轮。低分、失败和修复前材料全部保留。

十轮完成后提供版本浏览器、三个最终独立 HTML、评分变化与完整下载包；公开草稿 PR 保存可读原型、报告、脚本与清单。完整截图与较大的操作记录在下载包内。

## 初始任务队列

R20 建立三端首用与评分基线。后续依实际评估调整，优先顺序为：首次行动、设备与权限理解、保存到首次价值、空态与查找、完整功能发现、上下文返回、三端排版和中英、全新上下文反馈、最终有界修正。轮号不预设分数或通过结果。

## 执行范围

仅 HTML 模拟界面和合成数据。真实后端、模型、操作系统采集与权限接口留在应用实施阶段；本次评估界面如何解释、呈现和模拟相关状态。
