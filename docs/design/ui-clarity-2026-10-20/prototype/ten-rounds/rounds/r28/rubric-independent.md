# Mote R20–R29 独立 UI 评估规则

冻结时间：2026-10-21T04:30:58Z。评估者：`/root/r20_29_independent_evaluator`。

## 范围、独立性与证据身份

本规则在操作 R20 候选之前独立撰写，适用于接下来的十个冻结候选 R20–R29。每轮分别观察 Web、Mac 和 Android 的 **HTML 模拟界面**，只评可见界面表达和实际执行到的模拟交互。它不是原生构建、生产后端、真实模型、系统权限、文件上传、同步、加密或持久化验收。

评估者可以阅读功能清单、历史独立报告及验收规则，但不阅读候选的 HTML/JS 实现、内部应用状态、作者修改脚本或测试结论，也不修改原型代码。操作依据是实际渲染画面、可见 DOM 和用户可见控件。截图只证明画面；点击成功只证明动作执行；入口存在只证明可发现性。任务成功须同时有正确目标、可核对结果和有效返回路径的证据。

评估者已经阅读功能清单和 R15/R19 独立报告，因此不称为从未听说过 Mote 的人类新用户。每轮的“首次观察”是**该冻结候选在操作之前的记录**；后续轮次是知情复评，不能把记得入口当成界面容易理解。只使用合成内容，禁止真实个人截图、凭据或连接。

## 计分与平台门槛

| 维度 | 权重 | 核心问题 |
| --- | ---: | --- |
| Design / 视觉设计 | 15% | 视觉层级、布局和平台尺度是否帮助人完成当前任务？ |
| Originality / 产品辨识度 | 5% | 是否有适合个人上下文资料库的具体表达与组织，而非仅靠装饰或新奇？ |
| Craft / 完成度 | 10% | 排版、间距、响应布局、控件和状态细节是否可靠？ |
| Functionality / 功能闭环 | 25% | 观察到的操作是否达成承诺的目标，并保留范围与上下文？ |
| Clarity / 语义清晰度 | 20% | 在各状态中，用户能否判断自己在哪里、看到什么、操作影响什么？ |
| New-user friendliness / 新用户友好性 | 25% | 没有产品经验的人能否理解用途、开始、处理设置并核对第一次价值？ |

除新用户维度外，每项按下表给 **0、1、2、3 或 4 的整数分**。新用户维度由五个子项各自给 0–4 整数分，取算术平均，因此该维度允许 0.2 的步进。未知不是 0：证据不足的项标为 `not_observed`，不伪造总分或门槛通过。

| 分数 | 统一锚点 |
| ---: | --- |
| 0 | 关键能力/表达缺失，或明确误导，使观察任务无法开始或达成。 |
| 1 | 严重障碍：需要外部解释、猜测、绕路或重做，仍不能可靠完成。 |
| 2 | 能部分或最终完成，但有明显歧义、错路、摩擦或未解的结果不确定性。 |
| 3 | 在观察范围内清楚、可靠且可完成；少量摩擦不会阻断主要任务。 |
| 4 | 在观察到的常规和相邻不利状态下都顺畅、自解释、一致；无需要用户猜测的重要缺口。不能仅因未遇到问题就给 4。 |

单平台分数：`Σ(维度权重 × 维度评分 ÷ 4)`，满分 100。三端汇总是 `(Web + Mac + Android) ÷ 3`，不按桌面页面数量加权。报告同时给出最低平台分数，保留未取整原值，展示时至多保留一位小数；不得靠取整跨越门槛。

**关键通过门槛逐端适用**：Functionality ≥3、Clarity ≥3、New-user friendliness ≥3，且未观察到 critical blocker。任何一端未达标，三端总体不得标为通过。综合 ≥85/100 只是进步目标，不是用户要求的验收硬门槛，也不能压迫评估者提高分数。恰好进行十轮，不以分数继续上涨为理由追加轮次。未知门槛项使结论为“未验证”，不等于通过。

## 各维度的具体判据

### Design：视觉设计（15）

观察首屏主任务是否突出，阅读与操作区是否可分辨，密度和留白是否适合目标屏幕，颜色/文字对比是否支持层级，三端是否保持共同产品概念而尊重可见平台尺寸。4 分需要至少看到首屏及一个完成/错误/窄屏相邻状态仍保持清楚层级。漂亮截图本身不证明功能完成。

### Originality：产品辨识度（5）

观察“收集—找回—核对依据”的产品目的是否得到具体组织，资料、记忆、洞察是否有有用的区分，是否有帮助理解的实例与措辞。通用但可靠的常规界面可得 2 或 3；新奇或复杂本身不加分，不要求为了原创性破坏熟悉的交互。4 分需要可指出既鲜明又确实减轻理解/使用成本的设计。

### Craft：完成度（10）

观察长标题与正文、换行和截断、输入及按钮、对齐和间距、空态/加载/完成/错误样式、滚动与返回、弹窗和窄屏可达性。以实际尺寸截图为证，不凭 DOM 元素数量判断拥挤。只评实际观察到的焦点/键盘表现；未执行键盘或辅助技术检查时明确注明。

### Functionality：功能闭环（25）

检查第一份资料或随手记保存后可从正常入口找回并核对，提问可辨明示例状态、查看引用/原文并返回，来源创建/管理/暂停具有正确目标及范围，设置/取消/返回不丢上下文。任务中出现的失败必须有有效恢复路径。4 分要求这些当前轮次任务和至少一个相邻失败/取消分支有直接证据；不得以按钮存在、静态成功文案或继承旧轮次结果代替当前任务。

### Clarity：语义清晰度（20）

检查导航和返回标签与实际目的地一致；资料、原始记录、来源、记忆、洞察、后台活动与应用活动职责可区分；当前数据/平台/处理范围和状态明确；本地/中央、模拟/真实、已保存/已接收/可阅读等状态不混淆；用户可判断一个动作改变什么。此维度评**全旅程的概念和状态表达**，并不要求界面重复向熟悉用户讲解产品。

### New-user friendliness：新用户友好性（25）

五个子项等权，各占本维度 20%（总分的 5%）。每项保留直接证据和不确定性。

| 子项 | 0–1 的典型情况 | 2 的典型情况 | 3 的足够证据 | 4 的额外证据 |
| --- | --- | --- | --- | --- |
| N1 Purpose / 用途理解 | 首屏无用途解释，或让人误解产品做什么。 | 能猜出资料库，但不知道放入什么、为何有用。 | 操作前能从首屏说明可收集什么以及找回/提问/核对的用途。 | 示例贴合真实任务，价值明确，且在空白与已有资料状态均不依赖知识或术语猜测。 |
| N2 First action / 第一步 | 没有可执行入口，或突出与新用户目标无关的动作。 | 有多个并列选择，需猜哪个最适合开始。 | 主入口明显，标签说明结果；能自主选择一个低门槛动作。 | 选择与当下状态匹配，次要选项可达，首次操作不用先理解设置架构。 |
| N3 Permissions and setup / 权限与设置 | 不解释权限/连接/模型要求，或强迫未理解的授权。 | 有要求但出现时机、范围、跳过或返回不清楚。 | 需要时说明为什么、范围和影响；取消/暂不设置后有可理解路径。 | 同时有低风险试用/替代路径、明确模拟边界，完成或拒绝设置后仍能继续原任务。 |
| N4 First value and verification / 首次价值与核对 | 操作后无结果，或把模拟/后台接收误称为真正可用。 | 有完成提示，但不知道去哪里验证。 | 能离开创建页后找回正确内容，辨明保存状态并打开原文/依据。 | 结果与输入完整对应，来源/状态清楚，自然提示下一步，且返回继续任务不丢内容。 |
| N5 Progressive disclosure / 渐进展开 | 首屏堆满术语与高级设置，或关键功能被完全隐藏。 | 有分组，但新手仍难知道必需与可选。 | 首次任务简明；来源、记忆、洞察和设置在合理时机/位置可发现。 | 首次成功后的扩展选择具有上下文；高级功能仍可查找，展开/折叠不造成误解或死路。 |

新用户维度评**首次采用成本**；Clarity 评**持续使用中的语义可靠性**。同一证据只有在体现两个不同后果时才可影响两项，报告应分别写明后果。例如“返回资料库”去向错误影响 Clarity；若它同时使第一次保存后的资料无法找回，才另影响 N4。不得机械双扣。

## 每轮的观察协议

1. **冻结身份。** 先记录 UTC 开始时间、三个候选的路径与 SHA256、平台、浏览器版本、视口和初始状态。共享文件也要记录每个平台配置。操作完复核哈希；如文件变动，保留证据并判为无效冻结，不能悄悄换文件。
2. **先看后动。** 各平台先保存首屏截图和可见文字，尚未操作时立即写下：Mote 是什么、可放入什么、第一步会选什么、预期结果是什么、目前是否需要权限/设置、哪些词不明白。选择模拟器平台/空白场景属于测试准备，须与产品动作分开。
3. **自主任务。** 从可见控件自行选路，最少覆盖：第一次保存或导入→离开→找回并核对；提问→明确示例状态→引用/原文→返回；来源/权限/设置→取消或控制→确认当前状态；首次成功后找到一项高级能力。具体动作不是作者指定的固定脚本。若只完成部分，记录阻断点和未执行部分。
4. **截图与日志。** 保留真实动作顺序（点击、输入、滚动、返回）、可见结果和关键截图。每个发现至少连接到一个实际证据。工具定位失败单列为 harness 问题，不自动算产品缺陷；从可见 UI 恢复后继续。
5. **只给本轮证据支持的分数。** 每端分别说明覆盖任务、完成/部分完成/未完成/未验证、六维评分和 N1–N5。旧报告只可作为历史背景；未重测的功能必须明确引用旧证据身份，不能算本轮完成。
6. **先保存后交接。** 将本轮结构化报告、文字报告、首屏记录、动作/DOM/截图索引保存在本轮目录，再给作者有优先级的具体反馈。下一轮冻结后重新评价，允许持平和回退。不得改写上一轮负面发现以制造连续进步。

每轮最小证据包建议为 `rXX/independent-review.json`、`rXX/independent-review.md`、`rXX/evidence/first-look.json`、`rXX/evidence/actions.json`、各平台截图以及候选哈希清单。可以按平台拆分文件，但须有统一索引。

## 缺陷等级和结论边界

| 等级 | 定义与处理 |
| --- | --- |
| Critical | 核心目标无可理解的完成路径；操作作用于错误目标/范围；丢失用户工作；明显把模拟授权/成功冒充真实完成。当前轮次整体门槛失败。 |
| Major | 可绕过但显著影响第一次成功、核对或返回；或关键标签造成可复现的误解。影响对应维度，给出具体恢复成本。 |
| Minor | 不阻碍任务的排版、措辞、冗余或效率问题。按实际影响计分，不自动否定门槛。 |
| Observation / Unknown | 待核对疑点或未覆盖分支，不伪装成已证实缺陷，也不当作成功。 |

功能清单中的 20 类 / 78 个单元是防遗漏的背景范围。每轮有限任务不等于逐项完整验收；没有证据不得宣称全部能力可用。三端 HTML 只证明模拟界面，不把一个 HTML 的平台外观称为 native parity。报告必须写明未覆盖的真实后端、模型、权限、采集、上传、同步和跨刷新持久化。

评分可以不同于作者或其他评估者。任何争议应靠指定候选和具体画面/动作解决；不能为了满足期望分数修改规则。十轮结束时同时展示所有真实评分、最低平台、门槛状态和仍有的限制。
