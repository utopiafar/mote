# HTML 设计提案与仓库现有能力的差异

本项来自最后的文档与代码核对，独立于各轮 HTML 交互评分。它没有修改 R20–R29 的冻结候选或历史报告。

## Web 服务器文件夹持续接收

R27–R29 原型展示了在 Web 中创建、暂停和管理“工作台服务器文件夹”持续来源的流程。**这是额外的 UI 设计提案，不能视为仓库已有的普通浏览器用户能力。**

仓库中的三个范围需要分别理解：

| 范围 | 已查明的现有行为 |
| --- | --- |
| 普通浏览器用户 | 一次导入用户选定的文件、文件夹；不能通过目录路径读取中央服务器目录 |
| 中央 / 管理路径 | 服务器目录按一次导入任务处理 |
| Mac / Android 本机 | 本机文件来源可按所选范围持续接收 |

初始功能盘点中的 F04/F05 已说明一次导入与本机持续来源的区别，但对 Web 中不同账号模式的简写不够具体。最终核对又直接读取了当前 checkout `73fc85a0a22013d4bf21b9c07b64e0ed00e6beb5` 的以下代码：

- [apps/web/src/Imports.tsx](https://github.com/utopiafar/mote/blob/73fc85a0a22013d4bf21b9c07b64e0ed00e6beb5/apps/web/src/Imports.tsx)：普通 Web 模式明确提示“浏览器只导入所选文件或文件夹，不读取中央服务器目录”，并阻止目录模式提交；目录字段属于其他中央模式。
- [apps/server/src/scope/processing-imports.ts](https://github.com/utopiafar/mote/blob/73fc85a0a22013d4bf21b9c07b64e0ed00e6beb5/apps/server/src/scope/processing-imports.ts)：用户作用域的导入创建拒绝带 `directory` 的请求。
- [冻结功能盘点](feature-inventory.md)：F04/F05 保留原盘点口径，未追改历史基线。

本次模拟仍保留了一次文件/文件夹导入入口。后续落地应保留现有账号与目录权限边界；是否增加服务器持续来源，应作为单独的产品范围和实现决定。不能直接将 HTML 中的保存成功状态当作实际服务器支持，也不能从本轮 UI 评分推导这项能力已经验收。

最终报告、查看器和 PR 均应同时保留这一说明。最终评分描述的是候选中已执行的模拟路径，不会因为候选可点击而扩大现有产品能力。
