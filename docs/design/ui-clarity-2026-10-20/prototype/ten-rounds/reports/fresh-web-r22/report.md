# R22 Web 首次使用复核

## 简述

首次看到页面，我把 Mote 理解为保存个人文件、想法与设备记录，再通过搜索、提问和引用找回内容的资料库。可添加的内容和第一步明确；首屏只有“中央端”仍需猜测。截图及第一印象已在任何点击前保存。

我沿“记录屏幕 → 连接设备 → 连接 Mac 示例设备”前进。连接后页面直接标明目标是“Mac 示例设备”，要求打开该设备的 Mote → 来源 → 屏幕记录，选择应用并确认；系统权限和暂停操作也属于这台设备。网页的交接说明足够具体，我能判断下一步应转到 Mac，尚未开始记录。

查看设备状态时出现一次明显疑惑：点“重新授权这台设备”，徽标立即变成“授权已更新”，但下方仍显示“屏幕：未在记录 · 等待授权”。页面没有区分这两种授权，我无法判断刚才更新了什么。随后“调整屏幕与应用范围”返回同一设备端指引；通过“返回来源”成功退出。当前任务在网页端完成了设备连接和操作指引，没有验证真实 Mac 授权、屏幕采集或后续检索。

## Findings

| 级别 | 发现及用户影响 | 实际证据 |
|---|---|---|
| 中 | “重新授权这台设备”后，“授权已更新”与屏幕“等待授权”同时出现。两种授权没有名称区分，容易让首次使用者误判屏幕权限是否完成。 | `05-device-status.png/json` → `06-reauthorize-dialog.png/json`；后者实际是点击后的状态页，没有对话框。 |
| 低 | “中央端”“向中央发送”“记忆整理”在此流程没有解释。我能继续连接，但不清楚资料发送目的地以及与“工作台”的关系。 | `01-default.png/json`、`05-device-status.png/json`。 |
| 正向 | 明确展示目标 Mac、设备端设置路径、权限归属与暂停位置；“返回来源”可退出接入流程。 | `04-mac-confirmation.png/json`（实际为连接后的交接页）、`07-return-to-device-handoff.png/json`、`08-return-control-focused.png` → `09-backed-out-to-sources.png/json`。 |

## 证据与边界

- 默认空白账号、浅色、1440×1000；仅通过可见控件操作。
- `first-look.json` 在首次点击前写入；会话脚本在每次操作前检查该文件已存在。
- `actions.jsonl` 保存实际操作；`trace.zip` 保存真实浏览器轨迹和画面；`browser-errors.json` 为 `[]`。
- 只查看候选渲染页面与获准复用的浏览器辅助脚本；未阅读候选源码、其他报告、功能清单或改动说明；未修改产品代码。
- 演示连接动作直接进入交接页；本轮没有打开真实 Mac 客户端，因此不评价设备端授权或采集是否成功。返回来源仅证明离开设置流程，不证明解除连接。
