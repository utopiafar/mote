# Mote 三端 UI 迭代结果：R20–R29

## 1. 交付结论与打开方式

已在冻结 R19 的基础上完成 **十轮、三个端、30 个独立 HTML 候选**。每轮的中间结果、源码快照、修改原因、评分规则、独立评估和浏览器证据均已保留。最终版本为 **R29**，三个端为 **Web、Mac、Android**。

最终三端均通过预先冻结的关键门槛。三端综合均分由 R20 的 **72.5** 提升至 **85.4**，增加 **12.9** 分；最终最弱端为 **81.3** 分。分数是独立 agent 的有锚点评价，不是真人用户成功率。

- [三个端并排查看](dist/mote-three-platforms.html)：最终版本，可切换单端放大、空白/已有资料、浅色/深色。
- [Web](dist/mote-web-final.html)、[Mac](dist/mote-mac-final.html)、[Android](dist/mote-android-final.html)：各端可独立打开的完整 HTML。
- 十轮便携查看器（评审对话附件：`mote-rounds-portable.html`）：一个 HTML 保存全部 30 个候选和评分，可离线切换。
- [逐轮目录查看器](dist/mote-rounds-gallery.html)：轻量版本，需与 `rounds/` 保持相对路径。
- 完整证据包（评审对话附件：`mote-ui-r20-r29-evidence.zip`）：包含每轮原件、源码、报告、截图、可见 DOM、操作记录及追踪文件。
- 精简评审包（评审对话附件：`mote-ui-r20-r29-review.zip`）：包含可交互的十轮原型和文字报告，不包含截图与浏览器追踪。

独立 HTML 与便携查看器下载后直接用浏览器打开。默认从空白资料库开始；无需用户安装原产品或准备运行环境。模拟器顶部的轮次、数据和外观控制仅用于评审。

## 2. 新用户友好度：独立占 25%

沿用文章的视觉设计、原创性、完成度、功能性四项，同时保留用户此前要求的逻辑清晰度，并新增新用户友好度。本次为 Mote 设定的权重如下，**不是文章公布的统一权重**。

| 维度 | 权重 | 评价对象 |
| --- | ---: | --- |
| 视觉设计 | 15% | 层级、布局与平台尺度是否支持当前任务 |
| 产品辨识度 / 原创性 | 5% | 是否针对个人资料、上下文、来源和依据作出有效设计 |
| 完成度 | 10% | 排版、控件、滚动、响应布局及状态细节 |
| 功能性 | 25% | 实际执行到的 UI 任务能否完成、核对、恢复与返回 |
| 逻辑清晰 | 20% | 用户在整段旅程中能否理解位置、对象、范围、状态 |
| **新用户友好度** | **25%** | 首次采用的理解和操作成本 |

新用户友好度分为五项，每项占最终总分 **5%**：

1. **用途理解：**先看首屏，再记录它是什么、能放入什么、以后可以怎样使用。
2. **第一步：**能找到一个低门槛、结果明确的主操作；不需要先理解全部设置。
3. **权限与设置：**在需要时解释原因、作用范围和设备；能取消或暂不设置。
4. **首次价值与核对：**保存后离开，仍能从正常入口找回同一内容、核对原文并继续。
5. **渐进展开：**第一次操作简单；来源、记忆、洞察和维护功能仍可在合理位置发现。

每项使用 0–4 锚点；新用户五项取平均。单端总分为 `Σ(维度权重 × 评分 / 4)`，三端等权取平均，同时显示最低端分数。各端必须分别达到功能性 ≥3、逻辑清晰 ≥3、新用户友好度 ≥3，且没有观察到关键阻断。85 分只作为进步参考，不作为强行抬分的条件。

“逻辑清晰”评持续使用中的概念与状态；“新用户友好度”评第一次理解和成功的成本。规则要求分别说明影响，避免对同一问题机械重复扣分。完整规则在 [rubric-independent.md](rubric-independent.md)。

## 3. 方法：先冻结，再独立操作，再进入下一轮

参考 [Anthropic 的 harness 文章](https://www.anthropic.com/research/harness-design-long-running-apps)，采用实现者与评估者分离、具体指标、真实浏览器操作及结构化反馈。文章强调实际点击后的问题可能与静态截图评价不同，也记录了迭代分数并非总是线性上升。本次针对 UI 模拟，保留这种反馈结构并限制验收范围。

每轮按以下顺序执行：

1. 结合上一轮具体反馈修改三端原型，写明原因。
2. 保存三份独立 HTML、四份源码快照、修改记录、评分规则和 SHA-256 清单；构建器拒绝覆盖已存在轮次。
3. 独立 agent 先保存首屏并写下理解，再依据可见控件自主操作，不读取候选实现或内部应用状态。
4. 各端至少执行保存/找回/核对、问答/引用/原文/返回、来源设置或权限控制、成功后的进阶能力发现。
5. 保存当前轮次的动作、截图、可见 DOM、评分及具体发现；检查评估前后候选哈希一致。
6. 修复只进入下一轮；旧轮次的失败和评分保持原样。

连续评估者已了解功能基线，因此各轮首屏记录明确标注为知情复评。同时安排四次全新上下文评估：R20 Android、R22 Web、R23 Mac、R25 Android 进阶旅程。它们与连续评估分别留档，不冒充真人首次使用实验，也不把操作条数换算成成功率。

| F12 全部输入来源 | 来源 → 新增数据源 | 能找到完整来源目录及接入要求 |

**减少重复的原则是职责唯一、快捷路径保留。** “添加内容”负责开始，资料库负责找回，来源负责持续接收与控制，活动负责后台工作，设置负责维护。上下文中的快捷入口可以存在，但回到同一项任务及其正确范围，不能制造第二套概念不同的来源目录。

**防遗漏采用目录核对与任务核对两种证据。** 最终目录检查逐端访问 78 项，共 234 个可见入口；它证明入口与目的地的保留。代表性旅程则验证保存、核对、返回等行为。目录点击不等同于 78 项能力的所有状态均已验收，也不代表生产端功能全部可用。原始结果见 [final-reachability](reports/final-reachability/)。

## 5. 三端最终体验

### 共同首屏

首屏直接说明 Mote 是“个人资料与记忆库”，主标题是“让日常记录，随时找得到”。说明覆盖保存文件、想法和设备记录，之后搜索、提问、沿出处核对原文。

主操作为“写下第一条记录”，次操作为“导入已有文件”。持续接入放在下一层，用“同步文件夹 / 记录屏幕 / 连接在线来源”三个入口说明能力。用户可以先保存一个想法再按需连接来源；高级能力仍通过来源目录、资料库分组和全部功能可达。

第一次保存后给出可核对的结果和下一步，避免三处重复确认。问答结果就地标注示例状态；引用可进入原文并返回同一答案。原文和回顾中的时间字段区分保存时间与事件时间。

| 平台 | 主要安排 | 平台相关交互 |
| --- | --- | --- |
| Web | 资料、问答、来源与后台工作清楚分区；来源管理先状态和常用操作 | 文件来源说明工作台服务器或具名设备；屏幕记录交给明确的 Mac/Android 设备，连接授权与系统权限分别说明 |
| Mac | 保留桌面侧栏、菜单栏收集状态、本机快捷操作 | ⌘K 搜索、随手记快捷入口、Finder 风格文件夹选择；当前状态与保存策略分开呈现 |
| Android | 底部四项导航和移动排版；首次选择与常用动作优先 | 系统风格文件夹选择、大触控区域、明确返回；深页切换回到合适滚动位置，提示不挡底部操作 |

**与仓库现有能力的差异：** 基线中的 Mac/Android 支持本机持续文件来源；中央/管理路径的服务器目录导入是一次任务。普通浏览器用户模式仅导入用户选定的文件或文件夹，不读取中央服务器目录。R27–R29 中新增的“工作台服务器文件夹持续接收”属于 **HTML 设计提案**，不能据此认定仓库已经支持服务器目录持续同步。浏览器的一次文件/文件夹导入入口仍保留；落地时应先保留现有账号权限边界。若采用服务器持续来源提案，需要另行明确产品范围、可用账号和实现。这是产品范围差异，与本轮模拟交互是否顺畅分开记录。具体代码锚点见 [known-proposal-gaps.md](context/known-proposal-gaps.md)。

最后一轮还处理了“更改表单但尚未保存”的状态：重新选择文件夹后保留路径、名称、持续接收和保存方式；保存前原配置继续生效，保存后数量与状态一起更新。记忆纠正会保存实际输入，窗口尺寸变化不丢草稿，历史版本可核对。

更详细的三端设计理由与作者验证范围见 [platform-delivery-summary.md](rounds/r29/author/native-checks/platform-delivery-summary.md)。

## 8. 留存、验证与可追溯性

汇总工具逐一读取十份实际报告、对应操作文件及截图引用，得到：

- **10** 份完整独立评估，**30** 个平台首屏记录；所有 **30** 个候选身份与冻结清单一致。
- **763** 条连续评估操作记录、**607** 个被报告引用的独立截图文件。它们是记录数量，不是成功任务数。
- 四次新上下文评估另行保存，其截图、动作和追踪不混入上述口径。
