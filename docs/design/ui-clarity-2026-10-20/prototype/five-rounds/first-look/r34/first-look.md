# R34 首屏第一印象（独立 AI 代理观察）

这是 **AI 代理观察，不是人类用户研究**。仅查看三个实际首屏视口，按 Web → Mac → Android 顺序分别记录，全部冻结后才核对对应 DOM JSON 与 manifest。未阅读应用源码、功能契约、其他评估、计划或生成器说明；未点击、滚动或探索。后续平台可能受本次前图形成的概念影响。不提供产品总分或人类用户准确率。

## 图片阶段记录

三端共同可见原话：「Mote · 个人资料与记忆库」「把资料收好，需要时有据可查。」「保存文件、想法和设备记录。以后搜索或提问，沿着出处回到原文。」以下“理解”为观察者推断。

### Web

- **理解用途：** 一个个人资料库：收集文件、笔记和设备记录，之后通过搜索或提问找回信息，并核对原文依据。
- **可做的事：** 导入第一份资料（首屏深色主按钮直接写明。）；写随手记（主按钮旁的次按钮；顶部也有「随手记」。）；查看提问使用例子，再从自己的资料中找答案（右侧「上次讨论决定了什么？」示例、「看一个使用例子」和左侧「问一问」。）
- **会先做：** 导入第一份资料。唯一最突出的深色首屏主按钮，且说明明确要求从一份资料开始；先放入资料才有可查的内容。
- **采集发生在哪里：** 可见原话 「Mac / Android 采集本机内容；中央负责接收与整理。」、「从一份资料开始，再按需连接更多来源。」。推断：自动或持续采集发生在 Mac、Android 本机；网页上可以主动导入资料、写笔记；另有中央接收整理角色。 未知：「中央」具体是哪一端、设备采集哪些内容以及是否需要授权，截图未说明。
- **主要区域：** 左侧资料库、问一问、来源、活动导航；底部开始使用、今天、全部功能、设置；顶部当前资料库位置、工作台在线、随手记、添加内容；中部价值说明与导入/随手记按钮；右侧有据可查的问答示例卡；下方持续积累与连接来源说明。
- **困惑或不可见概念：** 「中央」是系统角色，但没有直观指向网页或某个服务，首次阅读仍需推断。 「记忆」「洞察」只在底部小字解释，首屏导航没有对应入口，尚不清楚与资料库的关系和使用时机。 设备记录的采集范围、权限和触发方式不可见；不能仅据此断言已经启用采集。 「今天」与「活动」的区别未从首屏建立。

### Mac

- **理解用途：** 运行在 Mac 上的个人资料与笔记库，可以把本机内容收进统一资料库，之后搜索或带原文依据地提问。
- **可做的事：** 导入第一份资料（主内容区的深色主按钮。）；写随手记（主内容区、顶部和左侧本机快捷操作均有入口。）；同步文件夹或选择可连接的来源（左侧「同步文件夹」和下方「选择可连接的来源」可见。）
- **会先做：** 导入第一份资料。主标题下最显眼的按钮，也是「从一份资料开始」引导所指；相比同步整个文件夹，单份导入的意图更容易理解。
- **采集发生在哪里：** 可见原话 「在这台设备选择范围，保存后汇集到中央资料库。」、「本机快捷操作」、「同步文件夹」、「收集状态」。推断：先在本机选择要收集的范围，再把保存的内容汇入中央资料库；Mac 端还提供持续同步文件夹的入口。 未知：截图没有显示已选范围、收集是否正在进行、同步是单向还是双向。
- **主要区域：** Mac 菜单栏与窗口标题栏；菜单栏出现收集状态，标题栏有搜索与快捷键提示；左侧主导航及单独的本机快捷操作区；顶部资料库位置、工作台在线、随手记和添加内容；中部价值说明、导入与随手记动作；右侧提问示例；下方本机范围与中央资料库的说明及连接来源按钮。
- **困惑或不可见概念：** 「工作台在线」说明连接，但不能据此判定正在收集；「收集状态」入口尚未呈现实际状态。 「同步文件夹」与「选择可连接的来源」的包含关系需要点开后才能确认。 本机选择范围到中央资料库的方向有文字说明，但中央存放位置和保留方式仍不可见。 「记忆」「洞察」仅有一句小字解释，暂无直接可见入口。

### Android

- **理解用途：** 一个手机上的个人资料库，保存文件和想法，再从自己的资料中查找或提问，并通过引用回到原文。
- **可做的事：** 导入第一份资料（主标题下的深色按钮。）；写随手记（与导入并排的次按钮。）；查看问答使用例子，或进入问一问（问答示例卡有「看一个使用例子」；底部有「问一问」。）
- **会先做：** 导入第一份资料。深色按钮紧接价值说明，且下面直接提示「从一份资料开始」；下一步目标足够具体。
- **采集发生在哪里：** 可见原话 「在这台设备选择范围，保存后汇集到中央资料库。」、「来源」。推断：手机本机可以选定收集范围，内容会汇入中央资料库；底部「来源」可能是配置入口。 未知：采集说明位于首屏最下缘，当前视口未呈现选择范围的具体控件；仅凭首屏不清楚可采集哪些手机内容或何时采集。
- **主要区域：** 顶部原型控制条、手机状态栏和资料库标题栏；标题栏有加号与省略号；主标题、说明、导入与随手记两个按钮；一张完整的提问示例卡；屏幕下缘开始出现持续积累区及本机到中央资料库说明；底部固定导航：资料库、问一问、来源、活动。
- **困惑或不可见概念：** 采集说明几乎落到固定底部导航上方，选择范围/连接来源的操作未出现在首屏；容易只记住手动导入和笔记。 标题里的「记忆库」没有在可见区域得到进一步说明；「洞察」在当前视口不可见。 文案承诺可以搜索，但首屏未见明确的搜索入口；加号和省略号没有文字标签，不能确定其菜单内容。 「来源」可以作为推测中的采集入口，但其功能范围仍需进入后确认。

## 后续核对（不回填第一印象）

- 三个 DOM JSON 支持已记录的标题、按钮和平台文字；均为 empty / light，平台和视口尺寸与图相符。
- Android DOM 含「选择可连接的来源」及记忆/洞察说明，但提供的首屏图片没有显示它们，不能把 DOM 中存在当作首屏可发现。
- Android 加号、省略号分别有「添加内容」「更多页面与设置」的 DOM 标签；截图仍只显示图标。
- manifest 将三张图标为 R34 first-use。候选源码哈希只按 manifest 声明记录，没有读取候选源码或其他场景。

## 可执行观察

- **all：主价值与第一步一致且具体。** 保留「资料→查找/提问→核对原文」的主说明，以及「导入第一份资料」的单一显著主动作。
- **android：持续采集说明落在视口最下缘，来源连接动作不可见。** 若持续采集是首屏要被理解的能力，压缩示例卡高度或前移本机采集行及一个有文字的来源入口，使其在 390×844 首屏可见。
- **web：「中央」缺少具体所指。** 与 Mac/Android 统一为「中央资料库」等明确名词，减少对系统角色的猜测。
- **mac：在线状态与实际收集状态尚未建立对应。** 在可见的「收集状态」附近给出可核实的简短状态摘要；避免让连接在线成为唯一的状态线索。
- **all：标题引入记忆库，但记忆/洞察关系在桌面只见小字，在手机首屏不可见。** 若继续把「记忆库」放在标题，提供短解释或清楚可发现的入口；首屏信息仍应围绕开始收集与查找保持集中。
