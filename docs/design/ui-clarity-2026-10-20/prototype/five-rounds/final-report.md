## 本轮回应的三个核心问题

### 1. 资料说明重新成为导入流程的一部分

三端导入页恢复“资料说明（选填）”，以“说明资料的内容与背景”解释用途。它保留最多 12,000 字符的多行文本，用来说明格式、时间、作者、背景和归属等帮助 Agent 理解材料的信息；导入名称仍是独立的选项。解析器和图片处理等次要设置按需展开。

独立操作已观察到：填写说明后预览、确认、查看同一次导入和资料出处时，说明保持一致；修改说明后必须重新预览；配置所需模型后可回到同一次导入。R34 又补上本地上传暂停、重试、文件失效后的重新选择与 Central 回执路径，错误文件不会覆盖原来的说明。完整功能是否通过仍以逐断言覆盖表为准。

### 2. 本机采集由采集端承担

移除 Central 本机目录扫描、持续同步和启用采集控件。Web 的文件夹入口引导用户在 Mac 或 Android 采集端选择范围，并查看已经收到的资料；浏览器选择文件或文件夹仍是一次主动导入。Mac 与 Android 保留各自支持的本机权限、范围和暂停控制。

此前 R27–R29 的 Web 服务器文件夹持续接收提案已被本次用户澄清取代，不再作为待落地能力。中央接收与整理资料，不能通过另一处入口重新引入中央本机采集。

### 3. 页面围绕当前任务收拢

首屏集中说明“保存资料 → 搜索或提问 → 核对原文”，突出“导入第一份资料”。资料库收拢为主要页签，筛选与细节按需展开；来源连接、范围设置、接收结果分别进入对应任务页。日程编辑、固定审核和执行回执分开呈现；选中文件后的重复摘要被合并，一次导入不再暗示还有下一次扫描。

这些调整保留了来源、导入、资料、记忆、洞察、待办、模型和维护的明确入口。入口存在只能证明可发现性，不能替代输入、状态变化和结果的功能验收。

## 独立分工与评估方法

采用 Anthropic 文章中的生成者与评估者分离、明确评分标准、实际操作 UI、保存证据并反馈下一轮的方法：[Harness design for long-running application development](https://www.anthropic.com/research/harness-design-long-running-apps)。本次增加独立功能清单角色，并按用户要求加入新用户友好度、简洁度和逻辑清晰指标。

独立清单 agent `/root/r30_34_feature_inventory` 根据用户澄清和仓库代码，先冻结 [功能清单](contract/user-features.md)、[结构化契约](contract/user-features.json)与[关键旅程](contract/journeys.json)，评审者再据此核对生成者的候选。生成者自测单独记录，不作为独立评分。

清单基于代码版本 `81a73c0ec81af876d6eeef71451b75cd51684b34`，覆盖 **20 个功能族、188 个命名语义功能、400 个输入、642 个动作、618 个结果**。原有 78 个目录单元中，77 个映射到语义功能，1 个中央本机目录入口按用户要求废止。这是命名审计契约，并不声称穷尽所有代码路径和状态组合。

每轮冻结三个 HTML 与源代码哈希；评审记录对应候选身份，修复进入下一轮，旧候选和旧结论保留。评审通过渲染页面、可见控件与交互结果取证，不用隐藏应用状态或作者声称来补足未观察断言。

### 固定权重

| 维度 | 权重 |
|---|---:|
| 新用户友好度 | 25% |
| 功能与语义完整性 | 20% |
| 简洁与注意力集中 | 20% |
| 信息与状态清晰 | 15% |
| 视觉设计 | 10% |
| 交互与细节完成度 | 5% |
| 产品辨识度 | 5% |

每项按 0–4 分、0.25 分步长评定；平台得分为各项 `得分 / 4 × 权重` 之和，轮次均分为三端等权平均。新用户、功能、简洁、清晰四项要求每端至少 3 分；同时必须满足语义完整性、关键旅程和中央不采集本机目录等硬门槛。高均分不能抵消未通过项。

## 最终独立观察与剩余问题

独立评审确认了三端导入说明与原任务恢复、普通录音目录到独立文稿/音频的路径、本机文件范围和更简洁的确认摘要。Web 的日程最终确认会重新检查已选设备是否仍有授权；对执行结果不确定的情况，界面核对原事件，不另造一条。用量页能区分未知费用与零费用，当前价格修改不重写历史运行的价格快照；Agent 目录浏览、首次上下文预览和保留的历史读取也有了分开的实际观察证据。以上结论仅限报告中操作过的样例。

| 剩余项 | 已观察结果与影响 | 建议修正 |
|---|---|---|
| 上传队列主状态过期 | 三端在刷新导致本地文件不可用后，正确要求重新选择同一文件并阻止继续，但队列标题仍可能显示“正在上传”。说明和提交身份没有丢失，也没有误报 Central 已收到。 | 将主状态改为“需要重新选择文件”，先前进度单独保留。 |
| 手机首屏采集入口不够靠前 | Android 的连接来源按钮在第一视口以下，容易只让新用户记住手动导入与随手记。 | 压缩示例卡或前移一句本机采集说明与有文字的来源入口。 |
| 演示状态提示仍有两处含混 | 未选审核设备时，撤销演示仍泛称授权变化；新生成的示例建议还可能显示旧的依据变化提示。实际选中后再撤销的目标已被最终确认正确拒绝。 | 演示提示依据真实所选对象变化，生成新建议时清除或限定旧提示。 |

### 新用户首屏观察

额外的全新上下文 agent 先查看三张实际首屏截图，再核对 DOM；未先读功能清单、代码或既有评分。它将三端理解为保存个人资料、以后搜索或提问并核对原文，首选动作均是“导入第一份资料”。这是 AI 代理观察，不是真人研究或理解率统计。

它仍指出：Android 的采集说明在 390×844 首屏最下缘，连接来源按钮和记忆/洞察解释尚未进入视口；Web 的“中央”称呼不够具体；Mac 的“工作台在线”不能让用户直接知道本机是否正在采集。标题中的“记忆库”与资料之间的关系还可进一步解释。详见 [原始首屏记录](first-look/r34/first-look.md)。
