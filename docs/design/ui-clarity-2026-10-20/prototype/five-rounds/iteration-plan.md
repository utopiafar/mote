# R30–R34 bounded UI plan

Source-of-truth application: utopiafar/mote at 81a73c0ec81af876d6eeef71451b75cd51684b34. Visual/interaction starting point: frozen R29 three HTML candidates at 9aec3d55d9e6af391c0cc5c2b1dbca8b2936a0e1, recovered archive checksum 0f48a1d3014ec6b6c24946b4b54d0e20922edd19628c0ea2bf0b772100478371.

## Owner-authorized boundaries

- KEEP: existing current-code user capabilities, source provenance/originals, privacy rules, three pause scopes, source/context attribution, asynchronous progress, recovery and retained drafts, platform differences, Chinese/English and light/dark.
- CHANGE: restore import understanding metadata through input → review → saved task → revise/retry; separately expose source-wide description and per-material attribution; simplify page hierarchy with one clear main task and grouped secondary disclosure; maintain consistent canonical homes.
- REMOVE: every central-server local directory collection/synchronization control, path field, server-folder fixture and associated cross-link. User explicitly states collection belongs to clients. Central Web receives/imports/organizes; browser one-time file upload remains.
- EXCEPTION: HTML simulates native UI, permissions, connector/backend/model results using synthetic fixtures. This work does not implement or verify production behavior, full backend logic, real credentials, native collection, or live models.
- UNKNOWN: exact source-driven subfeature preservation is settled by the independent inventory, not the historical 78 directory entry list.

## Roles and contract

Independent feature inventory: r30_34_feature_inventory and its read-only native audit. Generator/integration owner: root. Independent evaluator: r30_34_independent_review. The generator cannot author evaluation scores or mark its own missing features verified. Evaluator must use contract/user-features.json (version/hash recorded each round), major page inventory, and observable input/action/result transitions; candidate code or internal state cannot stand in for UI evidence.

Proposed fixed rubric: Design 10, Originality 5, Craft 5, Functionality 20, Logic clarity 15, New-user friendliness 25, Simplicity/attention concentration 20 = 100. 0–4 anchored scales. New-user has purpose, first action, setup comprehension, first value verification, progressive disclosure. Simplicity examines responsibilities, primary action, visual zones, optional controls, and retained discoverability. Each platform separately; report mean and weakest. Functionality/clarity/new-user/simplicity >=3 plus zero missing required semantic features and no central self-collection are hard acceptance gates; scores never override a missing-feature gate.

## Five actual iterations

Before R30: freeze inventory, rubric and reviewer approval; record R29 diagnostic observations under new contract.
Each R30–R34: changes from prior evidence → implementation → freeze three self-contained HTML and source snapshot with hashes → independent browser evaluation and action/screenshot evidence → report failures honestly → separate Git branch and commit → next round responds to findings. Never overwrite frozen rounds or retroactively change scores. R34 is final only after its own review. If gaps remain, deliver and clearly list them without relabeling the gate.

## Focused validation

Three platforms at realistic viewport sizes; inspect all major pages and disclosures against semantic inventory; check import metadata draft/review/save/revise including multiline and quoted third-party text, collector-only handoff and native source configuration, source context conflicts/attribution precedence, pause scope, original evidence, failure recovery, note/memory drafts, and first-use journeys. Check narrow Android, keyboard labels/focus, theme/language on directly affected paths. Browser evidence is UI-only.

Each round contains readable source, three HTML, exact artifact hashes, changes, independent rubric, independent feature coverage and scores, evidence manifest and Git reference. A final gallery offers all fifteen HTML snapshots and final three-platform view. Existing PR185 is updated; no merging/deploying.
