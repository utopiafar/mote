## 2. 从文章采用了什么

参考 [Anthropic 的 harness 设计文章](https://www.anthropic.com/engineering/harness-design-long-running-apps)，采用生成器与评估者分离、固定评判维度、保存中间候选、根据反馈继续迭代，以及最后比较候选的做法。保留文章讨论的 **Design、Originality、Craft、Functionality** 四项，按本次目标增加 **Clarity**。下表的权重、0–4 刻度、78 项分母与验收门槛是本项目的执行设计，并非文章给出的统一标准。

| 维度 | 权重 | 这里评什么 |
| --- | ---: | --- |
| Design · 设计品质 | 20% | 页面整体、布局、主次关系与产品内容是否协调 |
| Originality · 原创性 | 10% | 是否针对个人资料、出处、记忆和回顾作出合适设计 |
| Craft · 基本功 | 15% | 间距、对齐、状态、不同宽度、键盘和返回细节 |
| Functionality · 原型功能性 | 30% | 入口、输入、提交、取消、反馈、恢复与同一对象的衔接 |
| Clarity · 理解与易用性 | 25% | 第一眼理解、功能发现、分组命名、重点突出及顺畅旅程 |

五项均取 0–4 整数，总分为 `Σ(权重 × 分项 / 4)`。独立知情评估者查看实际可见材料与交互记录，不负责 HTML 实现；阶段盲评以新的 agent 上下文开始，不看功能清单、代码、作者改动或历史分数。先固定首屏回答，再给自然目标，由评估者自己选择动作。[完整规程](plan.md)

按本次确认的范围，执行方式是 **jsdom 运行 HTML 事件与状态，WeasyPrint/Poppler 生成静态排版图**。DOM 记录提供实际输入与前后状态；静态图提供可见排版。二者不等于真实浏览器或设备捕获，静态引擎分页也不等于浏览器里的断页或遮挡。

## 3. 关键功能先如何梳理

功能分母来自源码基线 `2c78ca8d52a7d17fae20962cf68d09a717ffc73a` 的既有目录：**42 个 core 单元 C01–C42，36 个 advanced 单元 A01–A36，共 78 个唯一编号**。本次再归纳为 20 类用户任务。20 类之间存在 16 个交叉关联编号，因此逐族关联数不能相加当作新的功能总数。[冻结清单](feature-manifest.json) · [源码盘点](feature-inventory.md)

### 主导航与对象边界

保留四个主入口：**资料库、问一问、来源、活动**。今天、全部功能、设置作为辅助入口。这里的“不重复”指一个操作对象有明确的主要管理位置；全局添加、今天、详情页和错误恢复可以提供同一流程的快捷入口。

| 位置 | 用户在这里完成的事 | 需要讲清的边界 |
| --- | --- | --- |
| 资料库 | 查找、阅读、核对内容，查看记忆与洞察 | 资料保存原文；记忆整理长期信息；洞察回顾一段时间的变化 |
| 问一问 | 针对全部资料或当前资料提问、核对引用、继续对话 | 提问范围、原问题和待澄清事项属于同一次任务 |
| 来源 | 接入文件夹、设备与在线内容，管理范围、暂停和恢复 | 一次导入、持续接收、外部位置引用分别说明；资料出处负责归档后的版本核对 |

| 今天 | 近期资料、回顾、待办与日程 | 跨任务快捷入口保留原始对象和返回关系 |
| 设置 | 账号、模型、处理方式、维护和偏好 | 每组设置进入对应对象，进阶能力按需展开 |
| 全部功能 | 按目标搜索完整能力目录 | 用于完整发现，常用能力也在所属页面保留自然入口 |

### 哪些独立发现改变了方向

- **入口可见不代表能完成。** R3 的新上下文评估者找到文件夹相关文字，继续尝试后仍未得到完整的目录与范围流程。R4 才补上可保存、可暂停、能核对范围的状态。
- **到了对的页面，还要是同一件事。** R9 局部脚本通过，但独立评估发现澄清没有稳妥回到原任务；本周回顾也暴露问题和范围未正确保留。R10–R12 针对任务、问题、报告和资料身份修正。
- **全局历史需要说明对象。** R12 新评估者生成记忆后，从全局历史误入旧记忆记录。R14 将历史按记忆对象分组，并保留每条记忆自己的入口。
- **窄屏要优先让人看到内容或起点。** R13/R14 逐步收起低频筛选，R15 对空账号去掉无数据筛选，把首次导入与随手记直接放到主要区域。

这些发现来自实际记录，保留失败和绕路，没有把后续修正追写为早期通过。[R3 探索](prototype/evidence/r03/blind-journey.json) · R9 探索（原件当前缺失，见材料清单） · R12 探索（原件当前缺失，见材料清单）

### 关键 HTML 操作是否走得通

R15 的 **28 条交互场景 + 5 份初始状态全部通过所列检查**。有动作场景合计执行 **378 步：200 次用户操作、178 次断言**。独立审阅认为其中 **26 条在各自限定范围内支持目标，2 条仅部分支持**：用量场景没有实际改变模型筛选值；旧记忆继续整理未能确认完整采用卡片上的两句话。前者是检查范围不足，后者还有可见内容不一致；两者不能由脚本 pass 抹去。这些数字只计算最终命名场景，独立自然探索、全量路由和候选比较另行记录。最终场景索引（原件当前缺失，见材料清单） · 独立复核（原件当前缺失，见材料清单）

实际覆盖包括：新记忆的输入、关闭重开、保存、历史、取消删除与继续整理；澄清后回到原工作；本周和自定义范围报告及其输入资料；两批导入分别打开各自正文；待办与日历值；来源范围和具名授权；问答范围及返回；模型、存储、费用；空账号一致性；390/768 下的导航与筛选返回；对话框键盘与焦点。每条场景只声明所列动作和断言观察到的结果。

五维评分冻结后，在同一份未改动的 R15 上另做 **9 条定向补测，共 85 步：53 次操作、32 次断言；8 条脚本通过、1 条失败**。这些不并入原 28 条，也不追改原评分。笔记的两行正文和附件可在离页、返回、保存、历史重开后核对；缺少模型的原问题和最近 7 天范围也得到补充验证。失败项是屏幕应用范围：取消勾选编辑器后，权限状态变化或保存会让它重新勾选；重开后仍未保留所选范围。这个实际反例加入最终门槛结论。补测索引与范围说明（原件当前缺失，见材料清单）

登录补测的脚本通过只说明准确核对了“登录界面预览”的打开、关闭及未变化的身份；输入新用户名并进入后，账号仍显示原示例用户，不能算完成账户切换。笔记没有可见的离线状态演示入口，该子分支记录为未提供；设备连接只核对具名示例设备及授权反馈。整个补测继续限定为 HTML UI，不要求真实账户、系统权限或后端。

## 6. 保留问题与结论边界

1. **英文界面仍不完整。** 主要导航和资料详情动作已有英文，但设置说明、部分数量、面包屑及无障碍标签仍有中文。用户原文和自定义标题保持中文不计作翻译遗漏；A36 因界面残留记为 partial。
2. **旧示例记忆的内容范围有不一致。** 卡片显示两句话，“继续整理”采用内容和旧初始历史只呈现第一句，未说明是摘要。具名工作、结果、依据和返回均可达，但不能据脚本只断言第一句就认定整条可见记忆已被采用。新生成记忆的草稿、保存与继续链另有实际检查。
3. **来源专属浏览没有延续范围。** 文件夹盲测的“浏览此来源的资料”打开了全部资料空态，没有显示刚设置的来源名称或空内容原因。暂停状态下持续同步复选框仍勾选，其“暂停当前接收、保留恢复后的策略”关系也未明确。这是 UI 范围衔接缺口；空账号中没有先保存过文件，不能推断删除或丢失。
4. **屏幕应用选择没有稳妥保留。** 最终补测取消编辑器、仅保留浏览器后，权限状态变化或保存会恢复编辑器勾选；返回重开仍为两项，而来源卡片写三项。未授权或已拒绝时，顶部仍称来源正在接收选定内容。拒绝后的提示、允许后的保存反馈和暂停入口可以操作，但这些局部结果不能抵消范围状态不一致。只据实际可见控件判定，不推断真实屏幕采集行为。
5. **首屏能感知高级能力，含义仍需进入后确认。** 新评估者能指出记忆和洞察，但仍询问它们是否自动生成、何时生成，以及与资料的区别；来源、资料出处、原始记录的边界也有首次理解成本。
6. **这是一轮 HTML UI 验收。** 合成问答、同步、授权、模型、上传和记忆结果用于检查界面表达与状态衔接。登录仅有界面预览，笔记离线分支没有可见演示入口；这些范围限制和真实系统、网络或跨设备闭环分别记录。静态图不证明真实浏览器遮挡、真实设备触控或性能；DOM 焦点与键盘检查也只覆盖所列执行范围。
