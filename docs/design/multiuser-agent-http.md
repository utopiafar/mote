# Personal Agent inspector HTTP seam

This bounded server-only increment is based on M15 declared a324c3474fb756749e3ba878fa992df51cb6446c, including Joint2528/519. It is not the full M13 or whole-system acceptance. All routes use the existing M01 user/credential and M08 scoped readers; no administrator private grant or client-supplied owner.

- `POST /api/agent-view/startup`: `{question?:string,timeZone?:string,after?:ISO,before?:ISO,deviceId?:string}`. Returns `{kind:new_conversation_preview,context,system,tools:string[],toolDefinitions,modelCalls:0}` using the same actual M08 opening Memory (existing limit8), context/system/tool builders and evidence pins. It admits no model/run/job. Context contains actual request/time/device/Memory leads, never reconstructed historical prompts.
- `GET /api/agent-view/evidence?id=<declared evidence ID>&offset=0&length=4000` (length1..12000) uses the M08 query-visible evidence reader and returns `{items:[...record,ocrText,textRange]}`. Material entries declaring `material_read` still use `/api/agent-view/material-read?ref=...` instead; do not use404 fallback or substitute a raw reader. Catalog default is the existing maximum12 and Material segment metadata retains title.
- Personal `GET /api/configuration` now contains domain `agentTrace`, effective `{traceEnabled:false}` by default. Explicit `PUT /api/configuration/agentTrace {revision,value:{traceEnabled:boolean}}` uses the existing whole-document CAS. This maps the former detailed-trace opt-in to the current account. Instance diagnostics supplies only existing maxBytes/maxFiles/maxEntries retention; no directory or global private trace access. Opt-out is observed before every event, including a provider response after a held call. A retained observer stops detailed recording when its settings entry retires (for example after session relogin); already admitted work may continue, but the old observer never borrows the new session or its opt-in. Partial history remains explicitly partial.
- `GET /api/agent-view/runs` returns `{items:[{runId,at,type:retained}],recording:{enabled},partial:true}` from existing owner/run ma_traces. At most the original recent20 retained runs are listed; no invented runs, totals or history.
- `GET /api/agent-view/events?runId=<UUID>&limit=100&cursor=<opaque>` returns `{items:[{seq:<runId:sequence>,at,trace:{runId,type,stage?,phase?,tool?,status?,durationMs?,payload?,truncated?}}],nextCursor:string|null,recording:{enabled},partial:true}`. Optional runId limits one run; omit it for all retained owner events. Cursor binds owner/deployment/run/limit. Legacy initial `afterSeq=0` is accepted; positive numeric offsets are rejected. Native consumers must retain and return opaque cursor unchanged/URL-encoded.

Detailed payloads appear only when explicitly recorded; turning off tracing does not erase or reconstruct retained history. Existing compaction/event maximum and byte/count retention apply. A returned payload may be truncated and is never proof of complete model reads. Context events use the actual Agent trace shape. Harness tool reads arrive as `trace.type=provider.event`, payload `{type:tool/result,data:{message:{role:tool,isError?,content:[{type:text,text:<JSON>}]}}}`; the JSON's `source=untrusted_personal_context` distinguishes actual results. Calls/user messages/error/truncated events are not reads. Older tool.completed shape is not manufactured.

Before history reads, the existing exact original/Material/Memory proofs are revalidated; retired inputs are unavailable and an administrator has no private read privilege. These projections reuse existing M04/M08 services and ma_traces, no new store/schema/runtime.
