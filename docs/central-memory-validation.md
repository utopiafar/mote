## 真实 DeepSeek 多轮验证

使用用户授权的本地连接，模型 `deepseek-flash`、high reasoning，测试数据完全合成。通过临时中央服务的 HTTP API 上传原件、生成预览、确认导入、自动提取候选 Memory，再调用问答和洞察。未向测试模型提供人工验收答案。

下表记录第一组四类场景在修复后的结果；后续新版独立导入另列，不覆盖旧失败记录。

| 场景 | 来源记录 | 该组候选 Memory | 核对重点 |
| --- | ---: | ---: | --- |
| JSON 日记 | 3 | 4 | 计划与完成、他人转述、2023 年原始时间 |
| ZIP 中 Markdown 与元信息清单 | 2 | 3 | 收藏作者与用户区分、未知日期、原件关联 |
| CSV 偏好变化 | 3 | 3 | 旧偏好明确标为历史、当前更新、说话人分别保存 |
| 同一条目的两个历史版本 | 2（当前 1） | 2 | 当前更正版、历史检索、取消不等于参加 |

每组两问，并进行了失败重试、修复后重测和一次跨来源综合问答。逐条人工对照原文，核对 Memory 的 UTF-16 引句偏移、出处、时间、版本和 HTML/Markdown 的事实一致性。该组共保留 12 条候选，均为 proposed；这不等于自动确认用户事实。

真实测试发现并修复：

- 内层 Memory JSON 多出 `citationIds` 等格式错误：严格拒绝，给固定校验反馈，最多重新生成一次。真实调用已验证第二次成功，无效结果没有入库。
- 引句偏移错误与原文变更混用错误类别：分开处理，真实原文删除或更新不触发模型修复。
- 导入最终答复不是 JSON：同一 Harness 会话最多修复一次，共用总超时。
- 缺失反馈被扩大成没有任何更晚记录；设备记录数被误当单来源记录数：收紧事实和范围要求。
- 综合类 Memory 缺少旧偏好的历史限定；HTML 添加原文没有的“每天”：更新 Skill 至 1.0.1，并保留旧失败产物后重新提取和测试。
- 导入为了查 schema 搜索工作树，导致超时和范围风险：将权威 schema 放入该任务目录；测试增加可选的操作系统文件限制及只允许固定模型转发端口的启动器。该启动器是测试设施，未新增生产沙箱部署体系。

核心事实与来源区分复测通过。人工评审仍记录少量表述、局部引用冗余：一处回答先引用文章，随即明确更正为对应笔记。有效的 ID 集合和正确引句不能单独保证每个就近引用都支持该句，不能宣称模型零幻觉。合并后只读复测再次通过两个版本问题和跨来源三项核对；HTML 仍出现一处历史卡片末句引用只覆盖初稿、而更正依据在邻近卡片的局部标注问题。

### 复现

先构建工作区依赖。测试输出只能写入新 `.mote/` 子目录，原件、失败答复和工具轨迹均留在忽略目录，Key 不写入报告或版本库。

```sh
node --import tsx scripts/private-import-runtime.ts --self-test
node --import tsx scripts/test-live-central-memory.ts \
  --env-file /absolute/path/to/private/mote.env \
  --out .mote/central-live-new --private-import
```

`--private-import` 仅支持已验证的 macOS 测试启动器；其他环境不能退回未受限的真实导入。`--resume --read-only` 禁用导入执行，只测试已上传的合成档案。`--repeat-queries`、`--repeat-insights` 可重复评估；`--refresh-memories` 仅允许 Skill 版本已变化时保留旧结果并替换本测试的候选记忆，不能绕过同版本的遗忘检查点。
