# 自主委派与活动

Mote 把用户目标、工作分支、结果和证据投影为 Activity。ExecutionEngine 仍然是任务状态、租约、取消和提交的唯一执行来源。界面默认展示目标和真实工作，操作 ID、工具轨迹、依赖与错误码放在技术详情。

模型选择是否委派、语义规划如何分组和什么时候补充工作；普通问答默认直接查证，普通就绪自动 Memory 由宿主按传输与授权合同结构装箱。宿主约束权限、输入版本、容量、资源、产物结构和覆盖，不根据关键词派发任务，也不把日期或字数当成语义边界。完整历史整理要求每份输入有明确结果，开放问答只要求有足够证据支持回答。

## 执行边界

协调会话通过独立的宿主控制通道发现能力、提交工作包、读取结果和保存等待条件。控制通道与只读 ContextToolRegistry 分开：模型不能借委派获得任意写入、Shell、外部消息或更大的原文读取范围。

提交返回持久句柄。子任务由同一个 ExecutionEngine 执行。协调者等待子任务时结束当前模型片段，释放 Agent 和模型执行名额；子任务完成后再恢复协调者。第一版只开放一层，worker 不继承父对话全文，也不获得继续创建 worker 的控制通道。

结果保存在私有工件中，协调者按需读取。子任务见过一个 ID 不会自动授权父任务引用它。宿主重新验证原文、范围、版本和当前读取政策，将实际交付的原文加入父会话的证据账本。撤销、更新和删除使旧工件失效；原文字符串精确匹配仍不能替代语义审查。

## 历史记忆整理

普通增量的有界结构装箱不需要模型规划；真正语义整理和 needs_context 才提供有界资料目录及版本快照。目录穿插来源队列，避免一个来源的旧积压独占，这是调度公平性。每份输入保留独立来源、原始身份、授权、修订、范围和指纹；宿主事务领取所有成员，失败不能只领取一部分。

提取和独立审查都读取授权原文。工作包包含零候选的输入也必须经过审查。逐输入覆盖结果与候选容量一起验证；缺少成员结果、输出达到容量或者需要更多背景时，不能把整个包直接标记完成。拆分保留已经完成的其他批次及检查点；未完成或饱和批次内的成员可能重新提取和审查，不能把尚未独立审查的覆盖声明当作完成。审查失败后可以复用仍然有效的提取草稿。

需要规划的 Memory 片段完成有界目录分组后，由既有执行器提取、审查和按容量拆分；普通就绪输入直接进入完整 package/coverage 合同。独立审查确认的 `needs_context` 与 `contextRefs` 交回同一运行时的持久反馈规划，模型可重组未完成目标，或选择原包已授权范围内的背景。目标与背景分别保存，都检查原文、修订和权限，覆盖及检查点只计目标，已完成的其他分支保留。

反馈最多进行两轮；需要的背景越界、无法安全重组或两轮仍未解决时，保留缺口并等待用户输入，不自行扩大原文授权。重启复用已提交的计划和工件，重试不会重置轮次或绕过新的独立审查。重新执行有效的失败产品可以恢复对应分支而不重复初始规划。通用问答协调者可根据子任务结果继续提交、重试或取消工作。

产品通过原有入口恢复后，来源计划的状态分支重新连接该产品的现有执行回执。每轮最多检查 64 个分支，以稳定 ID 游标轮转；已失效、取消或成功的父计划不参与恢复，其他授权检查拒绝的历史分支也不能阻塞后续有效分支。这里仅更新产品状态观察，不调用规划、提取或审查模型，不重试产品，不改变授权和自动尝试次数。

暂停或失败曾使来源队列停查某项产品时，原有手动恢复或重试入口已把产品改回待执行状态，队列会重新登记同一任务，重启后继续处理。检查仍有界且轮转，其他仍暂停、失败、取消或已完成的产品不会自动恢复。执行前继续检查当前原文版本、配方、读取政策和原始授权；恢复登记不能制造新授权、输入领取或模型尝试。

模型、推理强度和实际运行并发保持用户当前配置。升级不会为了提速自行更改这些设置，也不会为过去没有自动授权的输入补发授权。

Memory 初始与反馈规划使用宿主明确声明的 proposal 阶段：完整提交后正常返回，由宿主校验再交接产品。不能通过 yield 完成规划或等待尚未接入执行器的提案；独立原文抽样仍可等待。升级后，旧的循环等待先检查当前配置与授权，对完整持久计划复用原句柄直接交接，不再调用规划模型；不完整计划携带原 localId 恢复新片段。过期计划标记 stale，重叠输入由既有原子领取去重。具体决策与回归见 [ADR](adr-memory-proposal-lifecycle.md) 和 [验证矩阵](memory-proposal-lifecycle-validation.md)。

## 界面和进度

“活动”提供进行中、需要处理、最近完成的工作。详情按工作、结果、证据和技术执行逐层展开；旧处理任务视图保留在高级入口。问答显示阶段、检索已返回的项目计数和工作分支，用户可以看到 Mote 仍在推进、正在核对什么和哪里需要处理。返回项目可能包含重复命中或目录元数据，不等于独立原文数量；实际模型输入由 Agent Inspector 展示。

输入集合已知时展示已检查份数与总份数，按独立版本去重，零候选也计入已检查。模型调用数、步骤数和产物数分别显示。开放问答没有固定分母，因此使用阶段和实际计数，不生成进度百分比。后续整合的完成状态与提取、审查分开，延后整合不能计为处理加速。

`GET /api/memory-jobs` 支持 `limit=1..100` 和 `cursor`，返回 `items` 和 `nextCursor`。统计全量历史时必须遍历游标，不能把默认一页当成整个队列。

## 扩展与 A2A

能力注册描述目标、输入输出契约、工具与权限版本。新场景可以提供能力及验证器，复用执行、工件和事件。内部 worker 直接使用宿主运行时；A2A 仅作为未来独立外部 Agent 的适配边界，当前不部署 A2A server/client，也不维护第二套内部任务状态机。

## 验证与性能口径

自动化验收使用生成的日记、来源和模型响应，覆盖合批、独立授权撤销、缺失覆盖、零候选独立审查、拆分、恢复、取消、重复请求和引用交付。真实模型结果、浏览器渲染、物理设备验收单独记录。

`npm run check:local` 执行全工作区检查。`npm run test:activity-ui` 构建 Central 并用真实 Electron 浏览器打开隔离夹具，检查 390/1360 宽度、中英文、原文链接、Agent Inspector 和高级处理入口；截图与报告保存在忽略的 `.mote/activity-ui/`，不会采集个人屏幕。

性能对照应固定模型、推理强度、并发和数据，分别比较逐篇、给定工作包并行、模型规划工作包三条路径。记录端到端时间、提取与审查时间、总模型调用与用量、协调者读取量、独立输入覆盖、失败和恢复代价。语义质量须另外核对关键事实遗漏、取消或修订、第三方归属和时间；候选更多或 worker 更多都不是质量通过的证据。生成响应的测试只证明执行与验证契约，不证明真实模型的语义召回或生产提速。
