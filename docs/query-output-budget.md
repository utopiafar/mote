## 可复现的问题与修复

使用相同模型连接、400 条生成截图记录和同一句问题复现，未读取或传输个人档案。旧配置为 8,192 tokens：第一轮明确以 `max-tokens` 结束，最终 JSON 在 HTML 部分截断；一般格式修复后第二轮完成，合计约 101 秒。普通总结被自动加载的 `personal-insight` Skill 要求生成嵌套的 Markdown + HTML 报告，既重复输出，又不符合聊天页面的文字展示方式。

现在由宿主明确指定回答模式。普通问答直接返回文字/Markdown，回顾页面才生成 HTML 报告，记忆提取保留自己的结构。模型仍自行选择检索和解释证据，没有增加关键词路由。识别 SDK 的 `max-tokens` 终止原因，即使截断片段碰巧是合法 JSON 也不当作完整回答；在原检索会话和原期限内，只允许一次更短的完整回答重试。引用校验仍然执行，不猜测或补全引用 ID。

默认预算提高到 65,536 tokens。模型服务的高级设置提供常用档位、自定义值、当前生效值和保存入口。诊断错误新增固定原因枚举，以区分输出上限、无效 JSON、无效结构和各类引用问题，保留内容脱敏。

## 预算参考

输出预算属于每次模型响应，服务商可能把推理 token 与最终文本一起计入；它不是整个 Agent 的累计 token 配额。输出预算和上下文容量、工具数据预算、最长等待时间是不同的限制。

- 当前安装的 DeepSeek Harness `llm-deepseek` 默认输出上限为 256,000，显式请求值可覆盖。SDK 允许省略输出限制，交由适配器决定。[官方适配器文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-deepseek/README.zh.md)
- DeepSeek 当前 API 在思考模式的默认输出预算是 64K，最大支持 384K；实际输入加输出也受上下文容量约束。[官方 API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)

Mote 选择 65,536 作为应用默认值，并保留显式可调的 1–128,000 范围；该默认值不是对所有模型容量的保证。用户选择较低模型限制时应调整预算。软件升级不自动改写已保存的用户值；本次按用户要求把本地 dev 环境和页面生效值都改为 65,536。
