# ADR: Recording export outcomes and execution readiness

Status: Accepted, 2026-10-13; the owner approved the complete repair and then explicitly requested historical failed work be rerun.

A successful vendor export can have no transcript text. Absence of parsed speech does not prove that upstream transcription is pending. Feishu's documented not-ready response (2091003), a successful empty TXT export, unsupported nonempty structure, and an acquisition failure have separate receipts. Empty and unsupported exports remain encrypted archived originals with independent audio backups. Empty exports create neither full-text evidence nor Memory inputs. Later ordinary synchronization can discover text. Nonempty unsupported exports retain their original and require action; no ASR fallback or speech inference is introduced. DingTalk's explicit `complete` flag remains the transport readiness contract.

A configured archive policy and an unscheduled summary are normal omissions. Membership marks those steps optional before admission; the existing skip projection describes their outcome. Optional configuration errors and actual execution failures keep their receipts and are not called normal skips. Current memberships can be corrected after upgrade without resetting attempts or executing old work. Program failures keep known configuration/limit codes. File detail reads current canonical receipts whose input authority remains current; resupply and authorized evidence edits enroll their current definitions without running a model, including recovery that occurred while an ephemeral program handler was absent. An exhausted child recovery window ends its waiting parent instead of promising further automatic retries.

Model installation and runtime readiness are independent. Native startup probes Python packages and `ffmpeg`; missing system commands are reported without preventing the OCR or audio health endpoints from starting. Audio health reports specific missing dependencies. An authenticated local worker can explicitly certify that a rejected request never started execution. Only that structured local transport fact clears a 503 issued-call guard; a bare 503, timeout, disconnect, or historic provider error does not. Owner-authorized explicit reprocessing continues to use the existing unknown-outcome acknowledgement. Snapshot inputs may be reused while valid; this does not turn them into retained originals.

2026-10-29: [Managed media preparation](adr-managed-media-preparation.md) supersedes the Native startup dependency-installation mechanism with explicit one-click preparation and one Central-owned worker lifecycle. It preserves the execution, ownership and unknown-outcome rules above.

| Disposition | Scope |
| --- | --- |
| KEEP | Vendor account binding, independent audio backup, original exports, encryption, exact transcript coordinates, bounded retries, unknown-call guards, source scope/privacy/retention, model-based interpretation and manual ZIP confirmation. |
| CHANGE | Empty/unsupported/readiness classification; current optional membership and file receipt projection; terminal retry wording; complete step pagination; actionable runtime dependencies; cancellation reason and existing task-kind labels. |
| REMOVE | Empty text implies upstream not-ready; archive omission is a required blocker; all optional blocked work is a normal skip; all cancellation comes from the user; installed weights prove runnable audio; domain mirrors alone determine recovered execution state. |
| EXCEPTION | Missing inputs, permissions, unsupported formats, owner confirmation, actual model/processing failures and ambiguous issued calls preserve their restrictions. Explicit reprocessing is limited to the owner's selected historical failures. |
| UNKNOWN | Empty audio does not prove absence of human speech; anonymous speakers are not identities; historical transport errors do not establish whether each provider executed; physical Android lifecycle and semantic model quality require separate evidence. |
