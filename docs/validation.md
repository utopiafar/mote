## 真实端侧模型测试

使用固定 Qwen3.5-0.8B Q4_K_M 与 F16 projector，完整核验两份权重，总计 737,504,352 字节。两端使用同一生成的非露骨测试图片、默认策略、相同系统提示和 reason → allow 生成语法，实际 CPU 推理均返回允许：Mac 冷启动约 5.7 秒、暖约 4.8 秒；Android 模拟器重建测试约 11.8 秒和 8.9 秒。已验证强杀/取消后可以重新加载。这些是当前测试环境的功能性测量，不能外推 K90 真机速度或耗电。

国内 ModelScope 两份固定 revision 文件均实际探测 Range，返回 206、正确 Content-Range 总长度，前 64 字节与已核验本地权重一致。完整权重使用用户 demo 中已有文件离线导入并验证 SHA。没有进行 703 MiB 全程公网下载吞吐测试。

曾发现不同提示下模型布尔值与理由不一致，统一系统提示并改为先生成简短理由后，同图在两端复测通过。没有添加理由关键词修正逻辑。小模型仍可能误判或漏判；没有进行 NSFW 准确率/召回率基准评测。

## 审查后修复

- 模型下载的并发写入者使用各自拥有的文件，避免另一进程继续修改已验证的最终权重。
- 原生和中央随手记在入队前持久保存稳定 ID/时间，覆盖入队或 ACK 后未清空界面就退出的窗口。
- 更换中央节点不能隐式沿用旧令牌；原生队列或准备中的记录未完成时阻止换节点。
- Mac 中央窗口并发打开合并，关闭后保留草稿但撤销网络/认证能力，防止会话监听残留。
- 诊断文件写入/重命名失败清理临时文件，恢复时不删除其他活进程持有的文件。
- 中央节点启动时识别上次退出后残留的同 PID 锁，解决容器复用 PID 时无法恢复的问题；另一活进程仍阻止重复启动。
- 构建缓存、模型、运行资料、凭证和参考源码不进入 Git；保留维护源码、测试、构建配置和必要文档/依赖通知。

## K90 首次验收顺序

1. 安装 APK、连接节点，USB 可用 `adb reverse tcp:47832 tcp:47832`；后续长期连接使用 HTTPS。
2. 下载或离线导入两份千问权重，确认双文件就绪；显式开启无障碍并按应用指引设置 HyperOS 后台选项。
3. 先显示自建测试笔记，检查中央窗口中的图片/OCR；验证应用排除和固定遮罩，再检查原生随手记同步。
4. 断网/恢复、锁屏/解锁、杀进程/重启，检查队列、重复事件、草稿和中央最后心跳，记录采集缺口。
5. 启用开发者数值诊断，先短测再做 8 小时/24 小时测试；设备电量是整机读数，不当作 App 独占消耗。根据结果调整采样间隔、图片大小、CPU 线程和电量策略。
