# Material 归属与持续处理（2026-10-07）

状态：接受。基于 main `42a9e11`；本次取代普通自动提取关闭语义，保留独立策略、来源授权及显式历史模型授权。

## 用户旅程与决定

| 问题 | 当前基线 | 本次行为 |
| --- | --- | --- |
| 用户怎样完成 | 授权来源或导入资料；Material 保留原件和定位。归属主要依赖正文、contentRole 和模型推断。自动工作还受提取开关、来源 memory 选项、空配方选择影响。 | 来源正常接收后，按已选策略持续处理新输入。默认归属未知，不要求分类。用户可在既有来源设置声明默认归属，或在资料详情「来源与处理」修正单份资料。 |
| 未标识日记 | authored 只能说明内容角色，不能单独证明是用户本人；缺少统一的声明上下文。 | unknown 仍归档、提取、检索；模型利用实际正文和对话判断并保留不确定性，不设「未知禁止记忆」门禁。 |
| 外部访谈和混合剪藏 | 已有第三方归属政策和 observation 层，但正文与用户自己的操作/批注容易混淆。 | third_party 正文不转换成用户的主观经历或观点。模型区分引用与本人批注；有证据的访谈、转写、收藏及产物关联可保留为观察，原文和定位始终可查。 |
| 改错以后 | 普通来源修订会让依赖产物失效，但缺少跨链路归属纠正入口。 | 元数据事务生成新归属版本及正式修订，撤销旧语义结论和迟到提交。复用未改变的文本及 OCR/ASR；不发放历史模型授权。需要收费重做时沿用显式历史任务。 |

「资料在库中」只证明归档存在，不能证明用户采访过、读过或认同过。用户要求转写的记录也不能改写成用户亲自实施访谈。模型应保留实际动作、已述结果和可核验定位；未给出的文件、日期、结果和人物均不能补造。

## 所有者与契约

`MaterialStore` 真正拥有版本化归属、继承、纠正和证据依赖。SourceStore 只保存所有者声明的来源默认，连接器继续负责原件传输和真实来源字段。ProcessingRuntime 消费统一上下文；Memory 提取及独立审核策略负责语义解释和各自的价值政策；EvidenceReader 和 Agent 负责授权范围内的检索。没有新增事实库、分类器、任务引擎或产品侧的总 ready 开关。

共享 `AttributionContext@1` 包括 ownerRelation（owner/third_party/mixed/unknown）、basis、来源声明版本及单份纠正版本。它是宿主填入的顶层元数据，与正文、speaker、author 和 subject 的语义解释分开。来源默认不是逐句身份事实：owner 资料仍可能含引用；mixed 需要逐片段解释。未设置默认时使用 unknown，native note 和 Coding 也不因来源名称自动推断 owner。

所有者 PATCH 来源的 ownerRelation，可设为 null 清除默认；对当前资料 PATCH /api/materials/:id/context，提交 expectedRevision 和 ownerRelation，null 恢复继承。单份覆盖优先。来源声明变更作用于现存及未来资料，单份覆盖保留；清除/恢复继承同样有版本记录。历史资料显示原声明，纠正后旧引用不能继续作为当前证据。配对设备按既有 owner 身份管理资料；MCP 读写凭据均不能改此控制平面。捕获正文、frontmatter 或导入的模型输出不能伪造声明。

声明进入 Material 清单、目录、分页、块和原件证据投影，也进入处理、提取、审核及查询。语义产物固定其上下文版本，提交时再验证；纠正不重跑 OCR/ASR，不静默产生付费历史工作。默认 unknown 不改变旧原件指纹；明确声明/纠正参与指纹，防止缓存和引文跨归属复用。

同一个原件被多个 Material 引用时，完全相同的声明可复用；不同声明不能由「最后更新者」随意决定。原件投影返回 unknown 和 materialDeclarations，显示最多 32 个资料声明、总数及覆盖全部版本的 digest；这只是上下文披露预算，不限制归档/读取。正式资料仍保留各自声明。所有版本参与提交指纹，包括未展示的条目和恢复 unknown 的版本，以防 owner→恢复继承时旧结果重新通过。

## 历史原则与取代检查

| 类别 | 处理 |
| --- | --- |
| KEEP | AI-native：模型解释主体、意图、活动与记忆价值，代码不按关键词、文件名或应用名分类。 |
| KEEP | 资料、观察、精选记忆分层；可读原文不等待 Memory；空精选结果不是资料或活动不存在。 |
| KEEP | Material 是公共锚点；单一执行器、依赖图及模型账本；独立策略不能相互否决，固定组件版本不随安装漂移。 |
| KEEP | 只读查询、捕获内容不可信、隐私/来源权限、精确引文、版本提交和删除防重建。 |
| KEEP | 安装不授权全部能力；升级/重建/重启不补发原件收据，收费历史重算必须显式请求。 |
| CHANGE | 已授权来源的新输入持续提取；提取 enabled:false 及来源 memory:false 的旧 API 载荷被规范为 true。旧空默认选择恢复内置个人 v2，旧空来源覆盖恢复继承；新的空选择拒绝。 |
| CHANGE | 来源默认和单份归属修正成为可选所有者控制；外部正文排除个人主观归属不排除真实用户活动与资料定位。 |
| REMOVE | 普通提取启停 UI、空配方作为自动关闭、来源 memory:false 的新任务门禁、「用户原文」对 authored 的身份暗示。 |
| EXCEPTION | 来源授权与暂停接收仍存在；模型未配置/本地性/预算/缺少选中插件等原有执行条件仍生效，不替换不可用策略。取消任务、显式历史重做、整合/洞察/工作摘要各自的开关保留。 |
| EXCEPTION | 旧自动关闭期间没有授权的历史输入不回放。迁移推进旧提取日志水位；固定且原来获授权的在途窗口，以及显式手工任务可按原权限完成。历史收据和策略版本保持原样。 |
| UNKNOWN | 未声明正文的主体归属不能保证完全正确；本次小样本不能证明全语料召回率。真实账户同步、实体设备和所有媒体模型质量需分别验收。 |

旧架构文档里的「启用」仍可指安装能力选择、来源授权、整合等独立流程，不能再解释为普通新资料必须额外开启 Memory。[策略组合](memory-strategies.md)、[生命周期](memory-lifecycle.md)、[准入](memory-admission.md)同步当前行为；旧设计调研和冻结评估文件保留历史事实并标明适用范围。

## 新增产品行为的公开说明

本次增加可选的来源默认和单份归属修正，以及其版本、失效和恢复继承语义。将既有自动关闭/空选择配置转为未来新输入的持续处理，会改变这些用户的新输入处理范围和可能的模型消耗，这是用户本轮明确接受的方向。它不恢复过去缺失的授权，不增加必填标签、逐条确认、强制分类、新保留期限或语义兜底过滤器。归属元数据修正导致旧语义结论撤权，重新收费处理继续由用户显式触发。

未知场景无需等待「高召回率开关」才能接收；不存在该开关。质量评估分别测本人感受保留、外部观点误归属、本人活动/结果/位置召回、原件检索和引用有效性。使用相同新代码的「无声明/有声明」配对输入观察上下文收益，不冒称旧代码 A/B 或总体召回率。

验收和实际执行记录见 [归属验证](validation/material-attribution-2026-10-07.md)。
