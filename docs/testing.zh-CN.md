# 验证规范

[English](testing.md) · **简体中文**

用最少且有效的检查证明本次行为，已有覆盖与仍有效的结果可复用。证据足够后停止；新改动、失败或明确的覆盖缺口才扩大范围。

<a id="daily-feedback"></a>
<a id="test-layers"></a>

## 日常选择

按已有覆盖或直接验证入口选择检查。普通改动检查相关模块；接口变化同时检查真实生产者输出能被真实消费者使用。涉及权限、删除、恢复、持久化或生命周期时，覆盖对应失败情形。

```sh
npm run check:affected -- --dry-run
```

预览帮助选择轻量检查，不能当作运行通过。按任务选择执行；本地不例行重复整套 CI。单个文件或用例的命令从对应 app 的 AGENTS 及 CI 参考查阅。

例如，只改按钮文案时，检查显示、翻译和相关界面；修改删除后的读取权限时，验证删除后读不到，并拒绝晚到结果；修改上传字段时，接通真实序列化输出与接收端。

<a id="risk-based-review"></a>
<a id="regression-test-design"></a>

## 测试质量

新增测试应防止具体用户故障。能复现的 bug 尽量先复现；优先真实领域对象与公开入口，外部服务和不可用平台才模拟。已有有效覆盖足够时，不为每次改动机械新增测试。

取消、重启、部分上传和迟到结果要控制状态来验证，避免依赖碰巧出现的时序。不得缩小必需输入、放宽断言或超时、绕过入口来取得通过；将失败挪去手工套件也不能算修复。

<a id="early-integration-and-candidate-checks"></a>

## 集成与昂贵检查

跨模块的大改动尽早连接实际入口、真实生产者和消费者，按需要覆盖重启、取消与部分失败；小改动不套用整套旅程。

## 检查结果

CI 承担约定回归。重型跨端旅程、规模、性能和真实模型检查只在用户明确要求时选择运行，未运行则说明相应未验证范围。文件名含 performance 或 migration 不改变其中正确性断言的价值。

<a id="logs"></a>

生成资料、真实模型、模拟器、真机及第三方账号的证据分别表达。构建成功不能冒充真机或真实模型通过，旧版本记录不能当作当前证据。

只重跑后来改动使其失效的检查；失败、中断或清理结果未知的检查不得复用。文档修改检查内容、格式、链接和呈现即可。

完整日志留在忽略目录或 CI，简报保留退出状态和失败位置。PR 写明实际运行、明确复用及未验证范围，不新增每任务验收文件。
