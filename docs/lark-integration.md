# 飞书文档与日历（中央只读）

飞书文档与文件、截图和录音是同级上下文输入。中央使用固定版本的官方 CLI，在所有者明确选择的范围内发现文档、保存正文版本及可核验的活动线索。模型只读取已归档证据，不获得 shell 或任意飞书 API。产品决定、取代检查和未知边界见 [飞书上下文 ADR](adr-feishu-document-context.md)。

## 接入与首次同步

1. 从中央「新增数据源 → 飞书文档」进入；Mac「添加 → 连接飞书文档」打开同一中央页面，Android 提供原生连接与范围表单。云同步由中央执行，不依赖页面或采集客户端保持打开。
2. 完成专用账号的用户身份只读授权。当前部署预先准备固定官方 Lark CLI `1.0.98`；缺失或版本不符时，由管理员运行 `node scripts/mote.mjs connectors-prepare --profile <name>` 后重新检测。页面不会下载安装或回退到全局可执行文件。首次创建应用或填入 App ID / Secret 是必要时展开的设置步骤。
3. 选择自动发现“我创建的、我编辑过的、平台打开筛选命中的”文档，首次默认最近 30 天。也可固定跟踪指定 docx / wiki 文档、文件夹和知识库分支，或明确排除某些文档。旧选择没有发现配置时继续只读取原先明确的范围。
4. 保存范围并预览。预览只读取发现元信息，显示实际发现结果，不读取正文、不发布活动、不启动 Memory。确认后才进行首次正文同步；扩展或修改范围后重新预览与确认。
5. 来源详情显示本轮发现、正文和活动状态、待处理及失败项。可仅重试失败文档，已成功部分继续可用。设置的保存、手动立即同步、暂停来源及断开分别生效。

文档读取申请 `docx:document:readonly`、`wiki:wiki:readonly`，活动发现另需 `search:docs:read`；文件夹范围新授权申请 `space:document:retrieve`，已有 `drive:drive:readonly` 或 `drive:drive` 授权也可满足原生列目录接口，不要求重新授予旧版权限。日历读取独立需要 `calendar:calendar:readonly`，文档操作不因未选择的日历权限缺失而阻塞。首次添加日历时先点「授权日历读取」，授权后加载可选日历并保存选择，不自动收集未选日历。应用后台权限与用户授权是两层，组织管理员可能需要先批准。

授权使用官方设备码流程。页面显示原始授权 URL、复制入口和本地生成的二维码；设备码不返回浏览器，后台轮询直到完成、取消或过期。刷新页面可继续查看任务，服务重启后的未完成登录需重新发起。Secret 通过子进程 stdin 传递，不进入 argv、响应或日志。

## 内容、活动与时间

- 保存 Markdown 正文及普通文本表格，保留上游 document ID 和 revision。图片、附件、嵌入电子表格与 Base 只留引用，不自动下钻。长正文通过已有文件对象与中央解析路径保留完整文本，不能静默截断；旧 snapshot 来源如不具备该保存方式，明确显示 `lark_document_archive_required`。
- 文档 ID 标识正文，Wiki / docx / 目录入口按实际对象去重。不变正文幂等；修改保留历史，A→B→A 形成新的观察版本。正文归档不等于索引、Memory 或洞察完成。
- 创建、编辑和打开搜索返回的是有范围的提供方线索，不是完整操作流水。活动是独立的版本化事件证据；正文未变不吞掉活动，重叠搜索不制造新的动作次数。
- 提供方打开谓词可能包含 API / 采集器访问；在真实租户验证前始终显示这一限制，不将它写成人类读完、认同、学习、停留时长或确切所见版本。
- `observedAt` 是 Mote 实际观察时间，活动范围与精度独立保存。未知的作者或发生时间保持未知，正文中的历史日期由模型解释；不把同步日期写成创建日期，也不伪造精确动作时间。
- 首次取得当前可读正文，它可能晚于用户之前打开或编辑的版本。严格日期范围不能从宽泛的历史活动窗口恢复某一天的每次行为；问答保留这一覆盖边界。

正文进入现有 Material、个人 Memory 和问答。可信活动输入只进入对应日常事件处理；飞书默认组合独立持久，来源覆盖优先，历史输入不因安装而重跑。精选、事件与资料、原文继续分层；活动线索不会自动变成长久偏好。来源说明是可选所有者背景，正文中的指令或第一人称不能伪造所有者声明。

## 调度、恢复与暂停

中央默认每 900 秒检查，关闭网页后继续运行；中央停止期间不执行，上游索引可能延迟。发现使用固定绝对窗口和真实分页游标，逐页持久化；逐文档待处理、错误和已知别名可在重启后恢复。首次范围确认前后台不会读取正文。

失败保留已归档部分和上次成功时间。来源暂停、取消或权限变化在远端读取和发布阶段复核；重新授权、保存说明和保存范围不恢复用户手动暂停。换账号后暂停旧来源并清空范围，新账号不继承旧选择。

空结果、权限丢失、未完成扫描或窗口外消失均不推断为上游删除。取消选择和断开停止后续读取，保留已有归档；彻底删除使用既有 owner 删除操作。断开不等于飞书撤权，也不删除可能与其他配置共享的 CLI 凭据。

## 配置与凭据

`connectors/lark.json` 保存范围、账号指纹和确认状态，目录 0700、文件 0600、原子写入；发现与待处理状态位于中央 SQLite。普通归档导出不包含连接器配置或外部凭据，迁移服务需重新配置和授权。

`LARKSUITE_CLI_CONFIG_DIR` 指向当前资料库专用配置，子进程清理继承的其他 Agent / Lark 身份环境变量。CLI 配置隔离不等于操作系统钥匙串隔离：macOS 官方 CLI 仍按系统账号、appId 和 userOpenId 存储凭据；Linux 使用指定数据目录。建议使用专用应用及服务系统账号。录音 Provider 仍保留其原有中央登录策略，本次不静默迁移凭据。

管理 API 仅接受节点 owner 身份，设备与 MCP 凭据不能安装、登录或改范围。所有响应禁止缓存，CLI 使用固定参数和 `shell:false`。日志只保存固定错误码和数值，不记录正文、原始 CLI 输出、Secret、设备码或 token。远端部署继续要求 TLS 与强访问令牌。

## 管理接口

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/connectors/lark | 安全状态、当前任务及文档发现/失败状态，不执行 CLI |
| POST /api/connectors/lark/check | 检测版本、应用及登录 |
| POST /api/connectors/lark/install | 安装固定官方版本 |
| POST /api/connectors/lark/setup | 创建应用 |
| POST /api/connectors/lark/configure | 保存已有应用，Secret 经 stdin |
| POST /api/connectors/lark/login | 按能力发起用户只读授权；`{calendar:true}` 明确申请首次加载可选日历所需权限 |
| POST /api/connectors/lark/cancel | 取消任务 |
| GET /api/connectors/lark/calendars | 列出可读日历 |
| PUT /api/connectors/lark/selection | 保存明确的发现、固定范围、排除和周期选择 |
| POST /api/connectors/lark/preview | 只发现元信息，返回本次预览 |
| POST /api/connectors/lark/sync | 首次确认并同步；可用 `{document}` 重试已选失败文档 |
| DELETE /api/connectors/lark | 断开并暂停，保留历史及凭据 |

日历仍保留原生 instance_view、详情权限过滤、30 天分窗、全天时区及明确取消状态，不从缺失推断取消。

## 验证范围

用户场景、系统状态矩阵和真实模型入口见 [飞书文档验收](testing-feishu-document-context.md)。实际结果与未验证项记录在带日期的验证报告。
