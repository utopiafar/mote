## 执行和授权

- 通用运行时夹具检查批量快速提交、单名额下让出协调者、按私有工件恢复、失败分支局部重试、范围收窄、循环依赖拒绝及不可变句柄。
- 真实 Harness 和 Codex 适配器使用生成的供应商响应，验证独立宿主控制通道、等待释放名额、原文交付和引用账本；缓存解释不会自动授予引用权限。
- 完整 `buildApp` 夹具检查问答委派、控制通道不传入子任务、原文引用、最终对话提交、重启后只复用成功子任务，以及后台暂时失败后的恢复。
- 跨数据库连接取消、删除原文/正式锚点、权限撤销和迟到结果均有提交围栏。缓存解释的全部原文依赖会重新验证，包括未引用的原文。
- 私有输入、目标、分支指令、事件文字与工件遵循资料库加密设置；整库解密在退役密钥前也处理新增委派数据。
- 验证元数据配额统计新增委派及活动索引，配额拒绝会回滚整个提交，不留下半份工作或授权。

## 记忆和来源

- 检查跨来源合批与全部成员原子领取，独立授权撤销不能只消费包的一部分。
- 检查逐范围覆盖、零候选独立审查、容量饱和拆分、缺失覆盖不能完成、草稿恢复及检查点去重。
- 反馈端到端检查使用实际宿主控制通道及通用运行时：补入已完成但仍获授权的背景、重组目标、区分背景与目标覆盖、拒绝仅背景支持的候选。两轮仍未解决进入等待输入；越界提案被拒绝，未授权的第三份原文没有读取。
- 注入反馈子批次提交故障后重启，复用同一规划、分支 ID、原始授权和成功检查点；可复用提取草稿，但独立审查重新执行。重试不能把两轮限制重置。
- 检查规划前的资料权限过滤，以及领取后、关联产品执行前的崩溃恢复；部分工作包已创建时继续使用其余持久句柄。
- 目录调度检查一个来源的旧积压不会挡住另一个来源的新输入；穿插来源只选择目录，不代替模型分组，也不领取授权。
- 真实应用路径的图片、文件导入与录音测试均使用生成资料；验证就绪状态、失败恢复、重复输入和重启不会凭空增发自动授权。
- 记忆任务游标测试遍历 67 条同时间戳记录，验证稳定排序、分页间新增记录及参数边界。
- 活动列表检查同来源 1000 个历史任务及 1000 个独立目标的分页；列表读取关系元数据，避免逐条加载历史任务或批次正文。导入覆盖只计入本次保存的资料清单，排除同来源的其他导入。
- 1000 份生成原文的完整队列验收通过：16 个至多 64 项的规划目录、125 个工作包、125 次提取与 125 次独立审查、1000 个独立授权及检查点、1000 个明确覆盖结果。响应由夹具生成，证明有界调度和完整记录，不证明千篇日记的模型语义召回。

## 真实模型

在隔离临时 Store 中，用只提供生成原文的 ContextReader 和 Codex `gpt-6.1-sol`、`high` 完成一次真实委派验收。准确执行 4 个模型片段：协调者提交并让出、两个子任务读取各自原文、恢复协调者读取两份工件并回答。工作修订为 2，最终引用两条原文，最大同时模型名额为 1，各片段结束后名额归零。

实际使用了 `delegation_capabilities`、`delegation_submit`、`delegation_yield`、`evidence`、`delegation_results` 和 `delegation_read`。初次预检发现真实 SDK 的嵌套工具 schema 与其编写格式不兼容，发生在模型调用前；已修复并补上真实序列化器回归，再运行通过。

临时报告 `/tmp/mote-delegation-live-result.json` 不进入源码包。这次验收只证明生成资料上的工具和引用链路，没有运行真实个人归档或 Memory 三路径性能对照。

## 验证边界

物理 Android/macOS 设备没有验收。生成模型响应只能证明协议、恢复和提交约束；候选数量与执行并行不能证明语义召回或质量。生产吞吐提升没有作出结论。

性能比较应固定模型、推理强度、并发和数据，比较逐篇、固定工作包和模型规划工作包三条路径，单独记录提取、独立审查、协调读取、失败恢复、完整覆盖、总模型用量和端到端时间。质量另需核对事实遗漏、修订/取消、第三方归属及时间。
