# 原件资产与观察记录

`AssetStore` 是截图、导入原件、目录原件与衍生音频样本的字节写入口。新原件统一存为 `files/objects/<sha256>/<part>.plain|.aes`，每片最多 4 MiB。`EvidenceStore` 保存观察记录、来源版本、provenance、变化日志和删除语义；`store.ts` 只保留旧模块名的兼容导出。

相同 SHA-256 共享字节，但观察 ID、文件 ID、来源版本与时间各自保留。`asset_references` 由领域表的事务触发器维护；GC 同时检查引用和持久化 `asset_pins`。原件发布、pin 和资产目录提交在同一个 SQLite 事务中，GC 使用同一写锁，不能在发布与挂接之间删除原件。流式读取持有 pin，结束或关闭时释放。进程崩溃留下的 pin 在 24 小时后到期。

浏览器上传使用二进制分片；导入提交读取和校验每片，并逐片归档，不拼接整份文件。下载使用流式读取。解析器仍可在自身格式上限内物化内容；这不代表全部解析已移到 Worker。保存完整截图的 API 保留原有有界输入契约。

旧库的 `blobs/<hash>`（含 MOTE1）和 `files/<hash>` 原件通过资产目录中的显式格式读取；原 ID、hash 和版本不变。迁移现有字节时 `AssetStore.migrate(hash)` 校验完整原件并发布统一分片。兼容副本保留，备份只复制当前资产目录选择的格式。混合明文/密文、分片校验、批量解密、便携导出及一致性备份都有回归测试。

升级前先停止中央服务并制作一致性备份。回滚使用升级前备份恢复到空目录；不能让旧版本直接读取已采用新资产目录的库。备份仍不包含私钥或访问 token；原有加密密钥需单独保管。

测试包括 400 条跨 400 天的生成观察（200 条批量、200 条逐条），共享导入和目录原件后逐类删除；64 MiB/16 分片导入与重放；流式尾片损坏检测；独立 SQLite 连接的 GC 与 pin；旧格式迁移、稳定身份和重启读取。全部素材均为生成数据。
