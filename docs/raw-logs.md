# 原始日志与日志中心

正式版和 DEV 版均可在诊断设置中开启或关闭运行日志，并选择 DEBUG、INFO、WARN 或 ERROR。记录所选级别及更严重的事件；保存后立即影响后续事件，历史不因关闭而删除。新的本机日志设置默认开启：DEV 为 DEBUG，其它环境为 INFO。数值诊断与运行日志分别设置，各设备不互相修改设置。

各端的日志位置及读取方式：

- Web：系统管理 → 运行与诊断，分别设置当前浏览器日志和中央节点日志。浏览器日志保存在本站点的 IndexedDB，最多 2000 条，支持查看和导出；清除站点数据或浏览器回收存储会删除它。浏览器不能提供本机文件路径。日志只写入固定字段，写入失败不影响网页操作。
- 中央：日志中心可选择 `central.0.ndjson` 当前文件或历史轮转文件，目录取中央实际生效配置，默认是中央数据目录下的 `logs`；容器路径属于容器文件系统。API 为 `GET /api/diagnostics/logs?file=0`，只允许管理身份，返回 `text/plain`，禁止缓存。中央界面显示实际级别；选定新级别时关闭原有的 debug 覆盖，详细 Agent trace 仍单独控制。
- 日志中心支持按阶段筛选并分页；阶段是新增的兼容字段，旧日志会按事件名前缀回退推导。分页 API 可追加 `stage=system|request|ingest|index|agent|source|maintenance|file|unknown`，省略或使用 `stage=all` 保持原行为。
- 桌面：此 Mac → 帮助与诊断，显示 profile 的 `diagnostics` 目录，可打开文件夹、查看当前文件尾部或导出保留的事件。当前文件为 `events.0.ndjson`，最多轮转 7 份，每份约 2 MiB。
- Android：设置 → 诊断与支持，显示应用私有 `no_backup` 目录，可查看 `mote.log`、复制或导出各轮转文件；每份最多 1000 行，最多 7 份。数值诊断开启时另有固定事件文件 `support-events.json`，同样遵循运行日志开关和级别。
- iOS：设置 → 诊断与支持，显示应用私有的 `Diagnostics` 目录，可查看和导出日志。每份最多约 2 MiB，保留 3 份；日志和设置不属于用户内容备份。

日志在写入端带级别：阶段开始为 debug，成功/停止/正常过滤为 info，等待调度或缺少权限/模型等状态为 warn，操作失败为 error。中央节点的 4xx 阶段失败为 warn，5xx 为 error；debug 事件需要开启中央调试日志。

本次补充了中央请求开始及来源/配置等路由标识、桌面模型审查/OCR/隐私审查/入队/上传阶段，以及 Android 模型审查/OCR/隐私审查/入队阶段。已有请求完成、失败、服务生命周期、索引、查询与维护日志继续保留。

原始展示和支持包是两个不同入口：日志查看器保留文件原文；安全支持包继续使用固定字段白名单。普通诊断和原生监督日志不记录截图、OCR 原文、令牌、模型对话或任意异常文本。中央显式开启详细 Agent trace（DEV 默认开启）后，结构化日志可包含个人上下文、prompt、模型输出和工具结果；支持包继续排除 trace 正文。DEV 默认每份结构化日志 100 MiB、3 份，其它 profile 为 2 MiB、3 份；显式配置与旧 DEV 的升级规则见 [日志配置](server-configuration.md#日志与调试)。旧日志不会在查看时重写或补级别。

## 验证

使用合成数据验证原文（含空白、中文、损坏 JSON 和 HTML 字符）保真、读取上限、级别持久化、鉴权、日志轮转和复制/选择行为。Android 编译与 JVM 单元测试不等同于 Android 真机界面验证；未进行真机采集或真实模型调用。

## 0.0.23 新主线复查

- 中央文件 API：`file_upload`、`file_part`、`file_commit`、`file_revision` 有开始/完成/失败事件；请求另含 HTTP 方法和固定路由类别。
- 中央文件处理：`file.started/completed/failed` 含文件任务 UUID、批次请求 UUID、尝试次数与耗时。可重试失败记录 `retryAfterMs`；达到尝试上限不会声称还有下一次重试。`file.step.*` 区分 extract、diarize、align、turns、summary；`file.cached` 表示复用已完成检查点。
- `file.blocked` 使用固定原因（未配置、仅归档、不支持格式、每日预算、本地处理禁止云摘要等）；配置更改或停机导致的取消记录 `file.cancelled`，不作为模型故障。
- Android：后台界面任务、文件扫描/准备/上传/分块/提交和批量去重记录固定阶段、耗时与结构化失败类别，不记录 UI 标签、文件路径、文件名或服务响应。
- 桌面：来源扫描与设置、连接、更新等后台操作增加阶段日志。HTTP 失败保持 AUTH/CONFLICT/SERVER 等传输类别。
- 复查并修复 `UiTask` 的执行器拒绝分支：拒绝结果走正常界面完成回调，清除忙碌状态；新增合成仪器回归。原日志分页/级别筛选测试更新为原文保真和文本选择测试。

中央详细 Agent trace 与普通 DEBUG 事件相互独立：原有 DEV 默认可能启用 trace，内容可能包含个人上下文；更改日志级别不会自动开启该选项。
