# 日程建议与行动平台

第一版实现 `calendar.create`：分析主动上传与持续采集，逐条确认，写入 Android / Mac 上用户选定的已有日历。日历备注添加 `#Mote` 及稳定的 `[Mote:<action UUID>]`，便于系统日历同步与追溯。本版不修改、取消、邀请参与人或创建重复规则，也没有 Google 写入或 iOS 原生客户端。

## 使用

1. 在中央网页「行动 → 发现设置与设备授权」开启分析。默认关闭；开启后分批分析已归档和新增资料。选择原始信息使用的时区，允许指定设备查看跨来源建议及原文片段。模型服务沿用中央配置；没有模型时保留待处理队列。本地限定文件不进入远程分析。
2. Android 在「日程建议」点击连接本机日历，明确请求读写权限；Mac 在中央窗口「行动」连接这台 Mac 的日历。只列出可写的已有日历，不创建额外日历。Mac 的中央窗口继续使用管理员登录，采集专用凭据不会因此获得全部管理权限。
3. 打开建议、查看原文、补充缺失字段，选择已有日历后逐条确认。开始、结束与时区缺失时不能写入。原文中不确定的信息不会自动补成事实。全天结束日期为不包含的下一天。
4. 本机确认可立即写入；网页可交给另一台已登记的设备。Android 连接日历后登记 WorkManager 周期任务（约 15 分钟，实际受系统调度影响），遵守同步网络/充电/低电量限制；手动同步模式不后台执行。Mac 已连接日历后每分钟检查已确认任务，手动同步模式不自动执行。打开客户端日程页面可立即同步。离线、权限撤销或设备未运行时会保留任务。

## 边界与实现

- `packages/agent/skills/calendar-extraction` 是可复用过程；独立后台会话运行在现有 Harness，仅具备只读检索工具与 Skill 加载工具。没有日历写入工具、shell 或外发能力。程序不按关键词识别日程、主题或意图。
- `Actions` 在中央 SQLite 管理建议、版本、确认、设备目标、操作编号、回执与提取检查点。新增行动类型应扩展 kind 的类型契约、校验、专用 Skill 和执行器，不给查询会话增加通用写权限。
- 原件、导入记录、OCR 更新通过到达游标发现；文件正文/转写通过独立片段游标发现。内容分段有重叠并避开 UTF-16 代理对边界。通知正文从结构化通知字段原样投影，不改变归档原件，也不推断意图。
- 模型输出带原文引句与 ID。宿主检查结构、已读引用、确切引句、来源当前版本和批次范围。相对日期以原始消息/资料日期为准，不能以补传时间推断。宿主按明确的日期及时区排除已经过期的候选；此检查不解释自然语言。模型错误的语义推断仍需用户确认；引用匹配不证明整条推断必然正确。
- 模型参考有上限的最近建议判断跨来源重复；同批或近期完全相同的结构化结果另行去重。超出上下文窗口的语义重复不保证检出；拒绝的建议也进入近期比较。后续可增加专门的只读行动检索工具与评测。
- 确认绑定建议版本、编辑后的内容、设备和日历。再次确认同一请求幂等，不同目标或内容的竞争请求失败；一个操作只分配给一个设备。客户端领取后重新验证宿主确认数据，备注中的来源标记由确定性代码生成。
- 本机在调用日历 API 前持久保存 attempting，成功后保存外部事件 ID。响应丢失时重发回执；中途崩溃后只查找带相同标记的已有事件，不再次盲目创建。无法核实的操作进入「保存结果待核实」，不会宣称成功。Mac 按原时间附近的有界区间查找；如事件被大幅移动、标记被手动删除或多个副本存在，保留待核实状态。
- 来源更新使尚未执行的建议失效；删除原文会在数据库触发器中立即清除相关引句，即使发现功能已关闭。用户已确认的事件与执行回执保留，删除来源不自动删除系统日历事件。
- 日历同步由用户现有日历账户负责；Mote 不保证系统提供者一定同步自定义备注。稳定标记便于关联，但不构成跨供应商的绝对去重保证。

## API

所有接口均需节点身份认证。设备可登记自己的日历；查看跨来源建议、确认、忽略、领取和回执还需要所有者授予该设备 reviewDeviceIds。MCP 查询凭据没有行动接口权限。

- `GET /api/actions?cursor=`：有界分页建议、设置、目标与批处理进度。
- `PUT /api/actions/settings`、`POST /api/actions/retry`：仅所有者设置和重试。
- `POST /api/actions/targets`：本设备可写的日历列表。
- `POST /api/actions/:id/confirm`：version、event、target。
- `POST /api/actions/:id/dismiss`：version。
- `GET /api/actions/deliveries?deviceId=`：指定设备已确认、尚未完成的投递。
- `POST /api/actions/:id/claim`：deviceId；领取持久化操作。
- `POST /api/actions/:id/receipt`：deviceId、operationId、status、externalId。
