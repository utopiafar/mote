# 资料、理解产物与精选记忆

本机制最初随 0.0.44 引入；以下描述按 2026-10-13 当前契约更新。

原始文件/截图/来源记录 → 解析文本与定位 → 事件和资料理解产物 → 有明确用途的精选记忆。箭头表示可以加工，不要求每份输入逐级提升。原始记录始终可检索；全文和向量索引是可重建的查找设施，不能成为独立事实来源。

`admission.layer` 区分 `observation`（事件与资料摘要）和 `memory`（精选记忆）。`reason` 说明用途，`scope` 说明主体/项目/情境边界，`attribution` 区分用户陈述、第三方陈述、观察和推断。该分类由模型判断，不用应用名或关键词分发。`tier=episode|consolidated` 只表示初次提取/整合阶段，`kind=episodic|semantic|procedural` 表示事件/语义/方法类型，`status=proposed|published|stale` 表示候选/已生效/失效；这些维度独立，候选状态不是旧格式标记。

所有生产提取入口都要求 admission 和逐条精确证据。独立只读模型调用核对记忆价值、语义支持与范围覆盖，模型可以拒绝、缩窄或降级；新范围评估契约的空候选也必须经过审核。宿主随后重新检查版本、范围、精确引文与事务检查点。可省略 offset，让宿主在授权范围内定位唯一的完全相同子串；不会模糊匹配、纠正 OCR 或靠引文长度判断真假。模型审核不是事实认证。

新配方及新建未绑定独立审核任务的 `range-evaluation@1` 契约要求完整评估所有授权目标范围，空候选也经过独立审核；API 未传 recipes、没有 work package 或手工任务未绑定回退都不会退回旧配额。模型按固定策略选取独立有用的线索，不要求将原件全部事实或每个可能有用的细节写入 Memory；未选事实仍可从完整原件检索。`checked` 和 `no_candidates` 都声明该目标范围已经完整评估，候选数量不能证明遗漏。`incomplete` 必须说明具体未完成原因，未读或截断不能伪装成空结果。显式旧配方/收据、既有无新字段任务和内部无审核路径保留原契约。详见[范围评估 ADR](adr-memory-range-evaluation.md)。

长期整合只接收 layer=memory 的未失效 episode。仅重述或将无关约束打包为检查清单不算新增价值。每条结果提供实际使用的 relatedMemoryIds，宿主验证其属于本轮候选、未失效且贡献了引用证据。原始证据仍直接挂在每条结果上。独立审核和生成均计入模型调用账本，reviewRunId 指向最终审核运行，模型字段优先使用宿主生成的用量回执。

当前持久 Memory 使用严格 schema：版本、domain、tier、kind、admission、fingerprint 和原件证据结构必须明确保存，证据条目必须有 contentHash。读取不补分类、版本或 admission；`layer=legacy` 已删除，缺字段的旧记录拒绝读取，旧中央库也由 epoch 6 边界拒绝启动，不会自动转换或发布。MVP 切换需按清理记录先用旧版本备份/导出，再建立当前格式环境；升级不会自动把旧私人资料发送给模型。

Owner 的列表 API 不传 layer 时可列出当前合法的 observation 和 memory；网页默认显示精选记忆。Agent 的 memories 工具默认 layer=memory，也可显式查询 observation，或回到 search_context 搜索原始资料。生效状态不会改变分类；审核后生效的观察不等于升级为个人事实。重新处理资料必须通过当前授权范围建立新任务，并使用本轮固定的原件版本与检查点。

提取任务将校验失败的时间、阶段和固定错误码保留在批次 validationFailures（最近 20 项），不额外保存私人模型失败原文。最终成功不会清掉失败历史。

当前已授权且就绪的新来源输入进入独立滚动队列，不等待增量门槛或最长等待；保留的 artifact/history 窗口路径在有增量时，达到 25 次增量或最长等待到达即可启动。

此窗口路径默认 `intervalHours=6`，但未显式设置 `maxWaitHours` 时实际最长等待为 `min(intervalHours, 1)`，即 1 小时；并非 6 小时 AND 25 条。启动时固定最多 maxItems × drainWindows 条增量的水位（默认 100 × 100），每个 tick 最多处理一个窗口，让其他工作流有机会执行。该轮次的不足 25 条尾部仍会处理；新到达的增量留到下一轮。整个轮次完成后更新成功时钟，下一轮重新检查数量或最长等待门槛。drainWindows 可设为 1–1000；该窗口路径失败按原窗口退避，水位跨重启保存。不提供普通提取关闭开关；`extraction.enabled=false` 会被拒绝，source 配置不再接受 `memory` 字段。启动不转换旧开关或回放旧水位，详见 [MVP 基线 ADR](adr-mvp-baseline.md)。两条提取路径与暂停协议见 [Memory 生命周期](memory-lifecycle.md)。该上限是增量数量预算，不是美元或 token 预算，单窗口中的模型批次数取决于原文长度；使用新范围评估契约时，每个批次包括空候选都须独立审核。整合、洞察和对话摘要保留原本的独立周期。

新 Memory 在内部模型审核、原件精确引用、版本和权限校验通过后，由当前提交事务自动生效；用户无需逐条确认。启动时不发布或修复历史 proposed 记录。当前 proposed 候选仍有显式 publish 路径，执行时重新核对版本、原件是否失效、删除意图和关系目标；它不会为缺 admission 或缺原件证明的旧内容建立迁移入口。删除语义见 [版本更新](memory-updates.md#automatic-activation-and-deletion-intent-2026-09-27)。

2026-10-10 起，截图和 v2 页面字段的采集默认新增独立[日常事件策略](adr-daily-event-memory.md)。它收录日常展示、浏览、计划和有证据的行为为 `observation`，保留各采集时点与原文证据，模型回顾可显式按请求时区查询该层并归纳重复事件；不把普通活动或文章作者观点升为长期个人事实。2026-10-15 起，[飞书文档活动](adr-feishu-document-context.md)另有可信的 `daily-events` 输入和独立默认组合；正文仍使用普通个人策略。其他一般来源及显式来源覆盖保持各自组合，默认变化只授权之后的新接收资料。
