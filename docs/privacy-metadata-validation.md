# 0.7.0 分级采集与元数据验证

验证日期：2026-09-14。

本记录覆盖 Android、macOS、中央节点、管理界面及 Agent/MCP 的新增分级采集与元数据链路。所有自动化输入均为合成应用、文件、日记与图片，没有读取个人截图或日记备份。模型调用、平台运行和测试替身分别记录，不以 HTTP 成功代替答案质量验收。

## 可重复的协议与应用检查

- npm workspaces：323 项通过，包括桌面端 136、服务端 98、Web 17、Agent 40、诊断 5、本地推理逻辑 13、共享协议 14。全仓 TypeScript 检查通过。独立环境、文件同步、加密备份、升级与回滚的真实子进程回归也通过；已将新增访问时间标记与原同步状态分别验证。
- 合成端到端链路通过：采集事件、笔记、持久归档、只读 Harness 工具、证据引用与导入导出；隐私合成检查 22 项通过。
- 活动事件拒绝截图、窗口标题、OCR、心情、文件引用及内容采样属性；没有图像占位、无 embedding 作业。测试包含空字段、超长时间字符串、非法元数据与越权筛选。
- 活动计时先在同设备去重，再按应用、来源或采集级别筛选；身份相同的应用聚合，名称相同而身份不同的应用不混在一起。日记、文件和日历不算屏幕采样。
- 文件属性随来源版本保存、导出和恢复；完整扫描才产生来源消失版本。不完整扫描、权限故障和策略变更不伪造删除。同步器自己的读取不会反复触发访问时间版本。
- MCP 使用实际 SDK 验证元数据和精确筛选；查询 Agent 只拿到有界证据，来源路径、令牌与任意设备字段不进入证据投影。
- 本地停滞模型服务验证真实 Harness 超时、运行时清理和 504 诊断。清理失败不掩盖原始错误，错误不转发提供方正文或运行时 stderr。

## Android 实际运行

49 项 JVM 测试通过；0.7.0 / versionCode 10 的日常 debug 与 Development APK 在本地完成构建、lint、签名与 16 KiB 对齐验证，沿用原证书身份；lint 分别为 0 error / 100 warning 与 0 error / 104 warning，不能称为零告警。关闭 debuggable 的日常 Release APK 由发布 Workflow 重新构建并验证。采样的单调时钟与截图观察时刻绑定，处理完成时间不会改变采样区间；异步处理耗时不同的回归用例通过。

Android 平台验证使用专用 Android API 35 模拟器与开发版 App。真实系统权限、无障碍截图、MediaProjection、SAF、Keystore、WorkManager 与本机中央 HTTP 用于端到端链路；画面、文件和 OCR 内容均来自测试生成的界面和文件。6 项仪器测试全部通过、无跳过，共 28.842 秒：

- 实际首页在保存投屏模式而全部规则仅活动时启动，无系统投屏授权、截图请求或图像读取。
- 真实无障碍窗口观察、活动记录与生成画面截图分别通过本地队列和中央 HTTP ACK。
- 实际系统投屏授权后，活动分支仍零截图请求/零帧读取；内容分支在同一个 VirtualDisplay 连续取得两帧并获中央确认。
- 元数据开关不改写旧队列，生成图 OCR 后仍使用观察时钟计算采样区间。
- SAF 文件大小、修改时间及完整扫描的消失版本通过。

## 官方 DeepSeek 验证

使用用户授权的官方 API、`deepseek-v4-pro`、真实 DeepSeek Harness、high reasoning 与默认 120 秒预算起测，再以明确配置的 300 秒预算复测复杂场景。输入为固定的纯活动、文件时间、重叠采样和含伪 system 指令的合成日记。密钥与完整响应仅存在被忽略的私有验证目录，不提交到仓库。

首轮发现并修正了以下问题：

- 扫描发现文件消失曾被模型推断为实际删除区间。已明确区分最后观察到存在与首次发现消失，并说明移动、重命名、挂载或提供方变化同样可能导致消失；文件时间场景复测通过。
- 混合场景曾把日记算入内容采样，又用旧健康报告断言不存在后续采集。已将设备健康报告与归档时间分开投影，补充只统计屏幕/活动的工具契约，并加入回归测试；复测得到内容 1 条、活动 2 条、另有日记 1 条，去重后 60 秒，且识别出旧报告之后的归档记录。
- 两次混合请求达到 120 秒总预算。已增加明确的 504 超时类型与安全诊断，默认预算保持不变，拆分为 `MOTE_MODEL_REQUEST_TIMEOUT_MS`（单次请求 5–600 秒）和 `MOTE_AGENT_TIMEOUT_MS`（整个 Agent 运行 5–3600 秒）；不把达到预算推断为单一网络或提供方故障。相同复杂输入在 300 秒单次请求期限下首次用了 142.085 秒完成，验证了实际生效的预算。
- 进一步检查发现模型可能按倒序时间线叙述电量变化或把 UTC 查询窗口称为本地全天；已补充按元数据观察时间排序与转换查询端点的说明，单独复核。随后又发现状态时间被误用为采样时间，证据投影补上独立的本地时区 `displayObservedAt`，并测试两种时间跨本地午夜的情况。
- 一次响应把完整证据 UUID 缩成 8 位前缀，使引用无法点击；此前只验证完整 UUID 的逻辑未拒绝它。已对明确匹配检索 UUID 前缀的缩写引用作格式拒绝，要求模型在原证据会话内修复，不自动猜测或补全。

6 轮共 11 次正式 API 请求：9 次返回 HTTP 200，2 次达到默认期限（首轮旧诊断为 502，后续为明确的 504）。这些数字不等于 9 次语义全对；上面的失败与修复均保留。最终混合场景在 300 秒配置下用时 105.912 秒，4 个完整可点击证据引用、内容 1 条/活动 2 条/另有日记、60 秒去重统计、未发送计划、注入抵抗及历史电量边界均符合合成事实。

**保留的模型问题**：最终答案的一句话仍把截图时间写成了早 1 秒的设备状态观察时间。归档与界面分别保存并展示正确的两个时间，模型的秒级时间归因尚不能视为完全可靠；没有将这一轮标注为语义全通过。原始响应保存在本地私有验证记录，以上语义核对由执行任务的 Agent 完成，未经过独立人工评审。

答案的引用范围和只读工具集合由程序检查；采样覆盖、删除观察、状态时效、计划与完成、注入抵抗另外逐条对照合成事实检查。模型仍可能产生不准确表述，原始证据与测量统计是核对依据。
