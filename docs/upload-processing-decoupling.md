# 上传与处理解耦：当前契约（2026-10-05）

本页替代 2026-10-04 的本机文件处理方案。端侧只负责授权、发现、用户明确配置的过滤、不可变输入暂存和传输；文件解码、OCR、ASR、整理与索引都在中央执行。截图文字的本机 OCR 仅服务于上传前隐私审查，不生成归档正文。

## 保存方式与授权

- `snapshot` 文件会上传完整输入，由中央执行所选 recipe。中央处理成功后清理临时原件，保留提取正文及其处理证明；处理状态与可查询性独立于上传 ACK。
- `archive` 上传完整输入并在中央长期保留原件，使用同一中央处理宿主。
- `reference` 只发送目录元数据，不读取、暂存或哈希正文，不创建内容处理任务。
- 文件快照来源必须明确确认完整输入上传。旧配置没有这项确认时暂停扫描和上传，待用户在来源设置重新确认；普通同步和恢复配置不会补授确认。
- 客户端不选择轻量或完整索引。索引的实际覆盖和处理限制由中央报告。允许额外正文读取时，中央保留提取全文，设备离线仍可按范围读取；没有端侧按需解码或 ASR 服务。
- 用户的原文件不会被 Mote 删除。端侧仅在验证中央 durable receipt 后清理自己的暂存输入。

## 旅程与恢复

Android SAF、Mac 与 CLI 将输入身份、传输 manifest、字节散列和暂存内容持久保存。扫描与传输独立调度；丢失 ACK 后重发同一不可变版本，不重新解释文件。政策、选择或输入变化必须阻止旧传输和晚到处理结果发布。

中央通过既有 ExecutionEngine 执行已固定版本的 recipe 和 stage pins，产生 Artifact，再发布 Material 和索引。文件快照与原件归档共享这些步骤；保留策略决定原件生命周期，不决定是否跳过 recipe。

处理失败或结果未知时保留恢复状态。重试未知外部调用必须由用户明确确认；各入口共享相同的等待、取消与重试协议。快照临时输入过期后的恢复请求绑定原先 capture、版本、散列和大小，不能借恢复授权发送不同内容。

本机备份保留待复核记录的隔离状态；恢复、同 ID 合并和普通同步不能自动放行。配置与记录状态是两个分别需要保存的授权边界。

## 检查边界

自动化测试只使用生成输入，覆盖离线、丢失 ACK、重启、跨入口重试、隐私隔离恢复、输入变化和晚到结果。物理设备、真实应用版本、真实 OCR/ASR 与模型质量需单独记录，不能用 fixture、编译或安装包构建代替。
