# 上传与处理解耦决策（2026-10-04）

## 问题与决定

Android 的文件清单把已获中央确认、仍等待本机转写的文件计入 `todo`。上传准备再次选中该文件，调用本机 ASR；服务不可用时返回空准备结果，后续文件无法前进。上传 worker 还把“下一项尚未准备”一律当作稳定性等待，导致每个已完成文件之间最多空等一分钟。

沿用 [文件同步设计](file-sync-design.md) 的三维边界，以及 [后端插件重构决策](backend-plugin-rearchitecture.md) 的 host/module/recipe 分工：**上传完成表示输入已被持久接收；处理与可查询性另有状态。** 不引入第二套中央任务引擎、Redis 或插件私有队列。

- 明确选择 `archive` 的来源先上传精确原件，中央通过既有 Cordis / ExecutionEngine 独立执行 OCR、ASR、解析、整理与索引。录音目录的新建入口默认展示原件归档，仍通过来源编辑表单确认。
- `snapshot` 保持原件留本机：先发文件状态，再在独立的本机处理队列中生成正文，最后作为新的不可变 revision 发送。它没有中央原件备份的保证。Android 使用 SAF 输入的前后版本检查；桌面和 CLI 保留本机加密输入快照，以应对原文件被修改。
- `reference` 继续只发目录，不读取、暂存、哈希正文，也不创建处理任务。
- 既有来源不自动改留存模式，不自动付费重跑历史。临时上传原件、处理后删除的方案需要独立的保留与删除契约，本次不启用。

## 客户端与模块审查

| 入口 / 模块 | 传输前必要步骤 | 处理与恢复边界 |
| --- | --- | --- |
| Android SAF 文件与录音目录 | 来源授权、过滤、基线、稳定性、archive 的分块加密暂存 | 上传 marker 与本机处理等待分开；连续传输受字节/请求/时间预算限制；只在没有可发送项时等待稳定窗口 |
| Android snapshot 索引 | 文件状态和版本 | `LocalFileIndexWorker` 独立读取/解析；失败逐项退避，成功发布新 revision；不在上传 journal 锁内调用处理器 |
| 桌面本地文件 | 路径/授权检查、排除与用户文字遮盖策略、不可变输入暂存 | SQLite 的 `localProcessing` 与 outbox 同事务保存；单独的 Node worker 处理，上传不 await 扫描、读取请求或解析任务 |
| CLI 文件导入 | 与桌面共用扫描、journal、回执协议 | 先确认状态，再处理本机输入、发送正文版本；不可用任务跨进程保留，`--watch` 或下一次执行恢复 |
| 桌面日历 / Coding Agent，Android 日历 | 平台权限、格式规范化、稳定身份和游标 | 沿用注册的 SourceAdapter；无上传前语义模型依赖 |
| 截图、页面、活动、通知、随手记 | 明确采集权限、隐私过滤、持久 outbox | 新截图上传后中央 OCR；旧本机 OCR 有自己的处理任务，结果补写仍属传输。Android 的中央处理结果回拉移到传输之后，不作为文件 worker 启动的前置条件 |
| Web 导入 | 分块与恢复身份 | 既有轮转调度先取得归档 fileId，再创建异步 import 工作；每块验证散列与长度 |
| Web 随手记附件 / 聊天图片 | 文件类型与大小、归档权限、内容身份 | 共用分块验证能力；验证 v2 durable receipt、原件散列、长度与身份后才返回附件引用；支持 AbortSignal，不等待 OCR/ASR |
| 云录音连接器（飞书 / 钉钉及同契约提供方） | 账号、授权范围、元数据与 provider 版本 | 元数据后分别调度 media / transcript，使用各自资源锁；media 可在没有 transcript 时归档，后到的一侧关联另一侧；失败预算跨发现轮次保留 |
| Gmail / Google / MCP 等结构化提供方 | 账号、配置、分页与来源规范化 | 原有 upsert 接收路径没有上传前模型处理；沿用中央处理宿主 |

这些差异是输入、权限、保存位置和格式能力的差异，不是用目录名、文件名或关键词判断用户语义。中央可查询状态继续由既有处理 / 索引模块报告，不能从客户端待发数量为零推断。

## 扩展契约与宿主责任

客户端 SourceAdapter 继续拥有发现与平台能力；独立 LocalFileProcessor 只拥有解码能力。模块以 `id + version` 注册，任务固定处理器版本与输入身份。桌面默认处理器实际接入独立 worker，Android 默认模块实际接入 WorkManager；fixture 使用同一契约替换处理器。缺失模块/本机服务保留输入并退避，不能阻塞 transport。

宿主保留授权、source policy、来源启停、版本比较、队列容量、取消、回执校验和发布。处理完成时再次核对当前任务、策略与输入；编辑规则、删除或新扫描已撤销任务时，旧结果不能回写。ready 结果成为新 revision，已经排队的旧 manifest 和原件字节不变；ACK 丢失只重传该版本，不重新转写。

桌面本机处理输入与原件 outbox 共用 512 MiB 预算，单个本机解析输入仍为 16 MiB。临时输入完成/取消后清理，用户原文件不删除。Android 延用 16 MiB 本机解析边界和 archive 的 512 MiB 单文件 / 1 GiB 暂存边界。

中央处理器继续使用既有 `received → ExecutionEngine → Artifact → Material → index` 边界。安装、启用与历史重处理仍是不同动作；停止新输入不删除历史成果。录音连接器只新增两条任务之间的独立性，继续保留账号/epoch/providerVersion/ExecutionGrant 和 forget 检查，不复制文件 ASR 流水线。

## 迁移与验证

Android 一次重建 transport marker，将旧 `indexPending` 留在处理状态中，保留现有 pending manifest 和暂存原件。桌面重新观察旧的 pending audio 索引时建立独立处理任务；已经处理完成的历史正文不因升级全量重跑。

生成 fixture 回归覆盖：缺失 ASR 时批量状态接收；重启/丢失 ACK；新处理版本链；本机原件不进入 snapshot wire；文字遮盖；策略或输入变化阻止迟到发布；转写失败/运行中时 media 独立归档；随后关联已有音频而不再次下载；错误块/归档回执拒绝及取消。

本次物理设备检查用于诊断旧版本队列与调度状态，没有读取或上传录音正文，也没有采集个人截图。新 APK 的物理设备安装与真实录音/真实模型验收需要单独执行，fixture 与编译不能替代这项验证。
