## 质量反馈及修正

第一轮发现两种问题：代码结构介绍被收成“设计决策”；空工具输出被误当成成功证据。收紧规则后，同一份 Claude/Kimi 原文各返回 0 条候选，保留原始资料用于查阅，不制造记忆数量。

Codex 原文包含一项权限受限的操作，适合作为带条件和未知结果的会话经验。模型反复算错长工具输出的引用字符偏移，宿主拒绝保存。改为可由宿主在已授权片段内定位唯一的逐字引用：缺失、重复、越界或错误的显式偏移仍拒绝；不做模糊匹配或语义修补。持久化引用仍包含绝对 UTF-16 位置、内容指纹及来源。

进一步定位到 Codex 工具结果可为文本块数组；按原顺序提取可读文本后，消除了不必要的 JSON 二次转义。最终 Codex 任务完成，保存 2 条候选：项目范围的预检决策，以及会话范围的删除后复核经验，均有逐字原文和适用边界。Claude/Kimi 的零候选结果来自收紧规则后的完整批次。

最终真实 Chat 与洞察均成功：Chat 返回带原文引用的经验说明，洞察保存了带引用的文字报告和静态 HTML。早期较长的洞察经临时 relay 出现模型请求失败；最终用简短报告复测通过，不将早期失败算作成功，也不声称所有长度或模型均已验证。Chat 采用的批次记忆尚未覆盖后续复核结果；洞察读取更多原文后看到了成功复核。因此本期候选保持待确认，跨批结果没有自动合并为最终会话结论，这仍是已知质量边界。

## 范围与限制

- 可读对话归档不等于原生 session 的逐字节恢复；图片附件不在本期采集范围。
- 经验按批提炼，跨批缺失的上下文必须保留不确定性；不保证每段对话都产出记忆，也不保证跨会话语义去重。
- 本机验收没有读取或上传个人截图；未进行 Android 真机检查。
