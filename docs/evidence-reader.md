# Shared evidence reads

`EvidenceReader` owns archive retrieval and expansion. The app constructs it once, shares its MemoryStore and passes it to MCP; stateless MCP transports do not initialize read models for each request. It stores no authorization or previous query scope. Owner and MCP credential checks stay at the protocol boundary, including revalidation for revoked MCP grants. Current connection invitations issue owner credentials; retired collector credentials are rejected. Declared device scopes on synchronization and device record routes still apply.

`ContextQuery` provides bounded cards and text on top of this reader. Web and MCP expose both exhaustive literal search (stable cursors) and ranked retrieval (the same optional embeddings with lexical fallback used by the Agent). Ranked retrieval is bounded and may be incomplete; use literal pagination to enumerate matches. Missing results do not establish absence of offline data.

`capture:<UUID>` and `memory:<UUID>` are public evidence refs, parsed and formatted by the shared package. Case variants normalize both the kind and UUID together; an explicit kind never falls back to another table. Public EvidenceReader, Web context reads, MCP evidence/file/Memory tools and the model tool bridge require the declared namespace. Bare UUIDs do not select a namespace.

Resource identities remain UUIDs where an API declares them as IDs: capture/file/Memory resource URLs, original `record.id`, and the internal Agent `ContextReader` facade's capture and Memory IDs. Adapters convert these IDs to typed refs explicitly. For example, a public `memory:<UUID>` is parsed to a UUID before calling the internal Memory facade, while that facade validates its UUID and formats a Memory ref before calling EvidenceReader. Typed refs are not resource URL IDs. The Agent checks discovered records and host-granted text ranges after these explicit conversions; neither form grants disclosure by itself.

Collection and session cards carry versioned, bounded navigation refs containing an original anchor and a strict explicit query scope. `mote_read` and the Web read endpoint return a search expansion with empty text, not a derived claim or citable original. Resolving a ref intersects its original view with the current request; conflicting identity scopes and disjoint times return missing. Every resolution rechecks the anchor in the archive, so a deleted anchor never silently resolves to a new source head. Reconstructed readers need no cache or persisted mapping. These are query descriptions, not credentials; editing one grants no authorization. Hash-only historical refs have no resolver fallback.

Memory lists, details and context catalog/bundles also pass through the shared reader and check every original dependency for filters not covered by their SQL index. Source-item listing retains its separate calendar planned-time overlap semantics rather than substituting screenshot capture time. An immutable capture ID never resolves to a newer source head. Reference reads reapply device/source/time/coding scopes; Memory reads require all dependencies in scope. Queries don't change authorization. Shadow reads recheck the parent after awaiting the collector.

Captured text is untrusted evidence. This service exposes no write tools. Image disclosure remains an explicit host setting and is disabled by default. All Web context routes require owner authorization.

Derived context artifacts use `artifact:<encoded-id>:<encoded-revision>`. The segment catalog's declared logical-ID filter can select the current output; a public artifact ref pins the revision, and superseded or deleted refs return missing. Web, MCP, the Agent and the context catalog share the same resolver. It checks up to 1000 ancestors and 1000 original dependencies and returns unavailable if that bounded verification cannot finish. Scoped list pages retain their cursor even when every candidate was filtered out.

Artifact scope checks use a small SQLite metadata projection, without loading original text or images. They verify every transitive original, preserve authored/occurred time rather than import time, and disclose only fully contained intervals. List/detail member references are bounded (3/30), with total counts and truncation flags; the full lineage is still checked before any derived text is returned. Original capture IDs remain the evidence for claims.

Owner Memory/capture/note reads, file details/chunks/playback, and device record detail/image routes convert their declared resource IDs to typed refs before shared evidence scope checks. Device routes retain their device boundary; MCP read/write grants retain their separate permissions. A cached thumbnail or playback grant does not bypass current credential checks. Memory exports first validate the same dependencies as the detail route. Current Memory records must satisfy the strict schema; missing classification/admission metadata is not filled on read.

The 2026-10-04 removal of historical ref, credential and persisted-record fallbacks is recorded in [compatibility cleanup](audits/compatibility-cleanup-2026-10-04.md).
