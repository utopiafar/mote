# 同步机制与恢复设计

## 同步的含义

这是“手机采集 → 中央归档”的单向同步，包含两条发送通道：不可变采集事件（截图/应用活动/媒体/通知/设备事件/笔记）和来源版本（日历/文件）。两条通道共用网络和同步策略，独立提交、独立确认。

手机保留数与中央归档数通常不同：手机在中央确认后清理已完成处理的副本；等待 OCR、冲突和中央不可用的副本继续保留。中央显示上次心跳时的统计，不能视为实时状态。

## 状态和故障

| 情况 | 行为 | 用户操作 |
| --- | --- | --- |
| 还没上传 | 加密保留到待发队列 | 等待策略条件，或立即同步 |
| 请求传到一半断网 | 未获确认，不清理本机副本；重发完整记录 | 自动模式指数退避，手动模式点同步 |
| 中央已提交，确认丢失 | 用相同 ID 和原始内容重发；中央返回重复确认 | 无需手工去重 |
| 成功一批，仍有待发 | 立即接续下一批，不消耗失败退避时间 | 显示已确认数量和剩余数量 |
| 图片已上传，OCR 未完成 | 保留本机图，OCR 结果另行提交；结果确认后再清理 | 等待充电/识别条件 |
| 原始内容或 OCR 冲突 | 隔离该条，保留副本，继续其他记录；不显示“全部完成” | 查看本机副本，可重新核验；绝不自动覆盖 |
| 中央明确删除 | 服务端墓碑拒绝同 ID 重建，手机保留异常副本 | 查看记录；全量补传不恢复删除 |
| 授权失效 / 协议不兼容 | 留存数据、显示需要处理 | 重新连接同节点 / 更新中央端，再同步 |
| 来源失败、暂停或权限失效 | 已确认版本不回滚，剩余版本保留；完成状态检查两个通道 | 到来源页面恢复对应来源 |
| 应用中断 / 重启 | 已确认部分保持成功，未确认事件用原 ID 续传 | 手动模式需要再次请求；自动模式后台恢复 |

单条 JSON 或图片没有字节级断点续传；失败重发该条，不重新发送已确认且已清理的整批。成功批次使用 WorkManager 后续任务接续；实际失败使用指数退避，受系统后台调度影响。

## 同步与恢复页面

概览和连接设置均可进入。显示本机保留、待发、待 OCR、需处理、来源待发，以及最后收到确认的时间。冲突列表可打开原始副本；“重新核验”仅重试已有协议，不更换 ID 或覆盖中央内容。

1. **立即同步待发记录**：一次明确的发送请求，遵守 Wi-Fi 约束。
2. **检查两端记录状态**：每批最多 100 个 ID，检查手机仍保留的采集记录在中央是否可见；保存本次任务的批次检查点。检查结果不作为上传 ACK，不改本机清理状态。缺失、中央删除和其他设备的 ID 均返回“不可见”，不泄露其他设备记录。此检查不代表字节校验成功；真正重传时由中央的不可变记录校验验证内容。
3. **全量补传本机保留数据**：明确说明范围后，将非隔离的保留事件重新排队；保留原始事件和独立 OCR 结果。已启用来源重新排队当前保留版本和未确认版本，去重、不启用暂停来源。实际发送继续走统一上传机制。
4. **停止检查/准备补传**：取消恢复任务；已经排入正常发送队列的记录不会被删除，仍按所选同步策略处理。

全量不意味着恢复整个历史档案：已从手机清理、从未成功捕获、从未授权或本机没有保存的资料无法补传。需要重建完整中央归档时，应使用已有备份/导入流程。未设计隐式双向删除、时间戳覆盖或“以手机覆盖中央”。

## 协议

- `POST /api/capture-browser/reconcile`：请求 `{deviceId, ids}`，上限 100；响应 `{checkedAt, items:[{id,state:"present"|"unavailable"}]}`。设备凭据严格限制自身 deviceId，返回顺序对应请求。接口只读，不修改回执、记录或墓碑。
- 原始事件重传继续使用 `POST /api/captures`，同 ID 同内容幂等确认，冲突 409，墓碑 410。
- OCR 继续使用 `POST /api/capture-browser/:id/ocr`，原事件与结果分别确认。
- 心跳增加可选 `blockedRecords`、`awaitingOcrRecords`、`retainedRecords`，旧客户端保持兼容；中央端将保留数、待发数和需处理数分别显示。

## 验证边界

使用生成记录验证：确认丢失重发、中央墓碑防恢复、409 冲突、批量检查设备隔离、队列重启与重传不改变原始 OCR 事件、来源版本重传去重且暂停来源保持暂停。Android Worker 和界面测试代码编译、JVM 测试、lint 与服务端测试分别报告，不等同于 HyperOS 真机网络中断实测。本次不涉及部署。

检查期间采集和同步可以继续；结果是本次逐批观察，不是锁定两端后的事务快照。过程中新增或清理的记录应以之后的同步确认或再次检查为准。

本次验证：Android 94 项 JVM 测试、服务端 149 项测试、共享协议 23 项测试通过；Android Kotlin 与 instrumentation 测试代码编译、lint、中央端与网页类型检查通过。未执行 HyperOS 真机断网/后台恢复和界面实测。

## 同步条件

Android「连接与同步」中的同步条件与采集、OCR 的电源条件分别保存：

- 仅非计费 Wi-Fi 同步（原有默认开启）。
- 仅充电时同步（默认关闭）。
- 低电量时暂停同步（默认关闭，低电量由系统判定）。

条件共同约束记录、OCR 更新、来源上传、心跳及两端检查。立即同步和全量补传仅跳过时间与批量门槛，不跳过电源和网络条件。未满足时保留队列，概览和恢复页显示等待原因。设置保存会撤销旧任务并按新条件重建；约束接入所有后续批次和恢复任务，上传循环也在下一条记录前复查条件。已经发出的单条 HTTP 请求可能完成并确认，其余条目等待条件恢复后续传。

调度使用 [Android WorkManager 约束](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)；系统后台限制可能推迟实际运行。
