## 插件组合与迭代约束（2026-09-27 补充）

功能与效果优先于性能，性能优先于成本；超时、取消、有限重试与预算核算始终属于公共保证。下列要求也是验收标准，不能由接口存在或单个插件运行成功代替。

1. 按职责拆分：可独立变化的产品判断做成策略，可复用的处理能力做成模块，通过配方组合。拆分不要求新建存储或任务引擎，不应增加无必要的模型调用，也不要求每个参数都成为插件。
2. 每次改动区分四种情况：组合已有能力、增加独立能力、修复实现与契约的偏差、修改不足的公共契约或公共保证。避免各插件重复补丁，单一场景偏好不能成为全局政策。
3. 同一资料允许个人 Memory、Coding Memory、洞察等多种策略独立准入。一个策略不收录不否决其他策略；来源类型不决定语义类别。整合策略可替换，负责去重、关联与冲突，保留来源和策略版本，不静默覆盖已确认事实。
4. 提取、价值判断、语义审核、检索与展示策略可替换。权限、证据定位、版本、删除传播、状态管理、取消恢复与预算由公共层执行，插件不能绕过。生成策略和验收标准分开维护，不能同步放宽以通过测试。
5. 组合声明输入、输出、版本、依赖、权限和失败状态，复用仍有效的中间产物。业务只等待自身依赖；插件失败不阻塞无依赖的流程。查询使用当前可用资料并说明缺失状态。
6. 安装、启用、历史重算分别管理。默认组合允许场景覆盖和多个策略同时启用。安装或升级不自动开启全部能力或重算全部历史；确定性依赖可重算，收费历史模型调用须有用户触发或此前明确授权。停用不删除旧产物。
7. 以 Coding Memory 实测提取和审核独立替换、与个人 Memory 同源并行、跨来源复用、失败恢复和局部重算。复用证据及基础设施，证明没有重复转写和无必要的提取。MVP 先落实实际需求，不提前建设完整插件市场。

## 目标与不变量

中央端仍是一个部署单元。Cordis 管服务依赖、插件注册与资源回收；`ExecutionEngine` 管持久工作、租约、重试、预算和提交栅栏；`MaterialStore` 是正式资料的唯一发布入口；Harness 仅作为需要模型的执行器，以只读受控工具读取 Mote 资料。Material 是正式归档的权威，不等于查询 Agent 只能看已发布 Material：对话随附图片等即时输入可按所在业务操作的授权直接读取。

来源内容、外部文档、模型输出和插件接收的数据都是不可信证据。来源或处理器不能通过正文改变配方、提升读取权限或直接写正式资料。用户配置的隐私过滤、鉴权、去重和删除传播由可信内核执行。意图、主题和洞察由模型解释，不能靠关键词分派。

接入一个已覆盖数据形态的新来源，原则上只增加适配器、解码器、处理器或配方，不修改上传、任务、正式发布、授权查询内核。扩展接口要同时有默认实现、实际消费方和契约测试；只有接口而消费方继续直接访问物理文件或业务 SQL，不算完成。

## 单条输入到查询的目标路径

```text
来源适配器 / 现有客户端协议 / 文件上传 / MCP 或 CLI
  → 认证、端侧与中央隐私门禁、格式/大小/身份校验
  → IngressEnvelope + RawWriter（原件或受控远端引用）
  → Receipt（只承诺输入可恢复，不承诺已整理或可检索）
  → 持久工作请求（固定输入、配方、处理器、配置和权限版本）
  → ExecutionEngine 调度变换、分组、窗口、聚合、可选模型执行
  → ArtifactRef / MaterialDraft
  → MaterialPublisher 在短事务中校验输入与栅栏并发布不可变 revision
  → 独立的索引投影、目录投影、模型视图和后续 Memory 工作
  → 统一 QueryGateway 按业务操作选择已可用的视图，并执行权限、时间/设备范围与输出预算
```

可靠任务不能只由 Cordis 事件驱动；事件可用于观测与界面刷新。跨请求、耗时或需要恢复的操作进入执行引擎；同步校验和小型只读调用保留直接调用。任务和事件只传引用、范围与版本，不传整份大型原件。外部动作按幂等性与结果可核对能力分类；结果未知时不能盲目重发。

处理依赖按产物与业务操作声明，而不是用一条全局“资料已完成”开关。问答不等待所有 OCR、转写、聚合与 Memory 完成：它使用当前合法可见的输入，同时让模型看到缺件、处理中或版本过时状态。Memory 可对某些来源声明必须等 OCR 或转写完成，另一些来源可只依赖原文；每个派生工作固定所依赖的具体产物及证据指纹；未提供块映射时固定整份资料 revision。

## 接口边界

| 边界 | 注册的能力 | 内核强制约束 |
|---|---|---|
| 接入 | SourceAdapter、EnvelopeCodec、IdentityPolicy、InputValidator | 鉴权、幂等身份、大小、保留承诺、receipt |
| 原件 | RawWriter、RawReader、BundleStrategy | 物理路径不外露；读取范围、可用性、权限、校验和受控 |
| 处理 | TriggerPolicy、GroupPolicy、WindowPolicy、JoinPolicy、Transform、Aggregator | 固定输入版本、取消、预算、重试、checkpoint |
| 执行 | 原生、Python、Harness、远端 Worker 的 ExecutorProvider | 统一执行状态与提交栅栏；不可信代码独立进程隔离 |
| 发布 | MaterialAssembler、MaterialPublisher | 只有 Publisher 可写正式资料；保留覆盖度、保真度、血缘 |
| 读取 | IndexProjection、IndexProvider、CatalogProjection、EvidenceView | 可见性按来源、受众、业务操作、处理阶段和视图声明；标题、摘要、片段、正文、图片、错误和导出都受控 |
| 应用 | 问答、洞察、记忆、待办、外部动作、导出与清理工作流 | 消费固定资料 revision，不自建来源接入与长期记忆权威 |

配方是有版本的可验证 DAG，引用上述能力 ID、明确输入形态和发布/索引/暴露策略。它不能把任意脚本字符串当作可信步骤；Python 脚本需要受限执行器和受控原件读取。一个 Source Pack 可以注册多个细粒度能力和一条或多条配方。卸载停止新输入并撤销运行资源；已经接收的工作应可排空或显示为 blocked，不能顺势删除历史资料。

## 来源场景的目标组合

| 场景 | 原件及变换 | 聚合与发布 | 默认模型视图 |
|---|---|---|---|
| Coding 会话 | 分段原始事件、确定性规范化和增量拼接 | 会话版本，缺件标为 partial，迟到更新出新 revision | 分页正式正文；原始事件包隐藏 |
| 截图与应用 UI | 图片原件、去重/关键帧、结构化 UI 优先，OCR/VLM 可作回退 | 明确的屏幕片段或会话 | 概览、文字和授权的关键图片 |
| 应用状态与通知 | 原始观察/JSONL；压缩状态变化与时间段 | 按对象或窗口发布，不以上传批次定身份 | 有时间定位的状态片段或通知资料 |
| 手工非结构化文件 | 原始资产、解析 Agent、必要时确认 | 文件或显式关联的逻辑资料 | 经批准的解析正文和原件定位 |
| 手工结构化文件 | 原表、字段映射、Python 清洗、按业务键去重 | 一个逻辑数据集可含多个上传文件 | 目录、摘要与受控结构化查询 |
| 录音设备 | 音频、设备转写、按键标记、照片异步到达 | recording ID 分组；缺件、迟到与窗口持久化 | 转写/定位，音频按授权读取 |
| MCP/飞书 CLI | 来源能力声明、游标与同步策略；可中央保存或只存引用 | 显式来源身份和版本 | 根据保存/现时读取权限选择目录、摘要或正文 |

跨来源同一会议或项目使用有依据的关联，不凭标题相似合并原件身份。打包、无损聚合和有损摘要是三个独立步骤。新算法重处理基于原件创建新执行批次，先对照覆盖度和索引投影，再切换正式版本。

## 已确认的产品决策

1. 允许清空旧中心库及端侧待传队列；这是本次明确授权的 MVP 断代。实现仍需让断代显式发生，不能把旧数据静默解释为新格式。便携 JSON 导出不是完整历史备份。
2. 旧 Mac/Android 与后端同步升级；新协议无需兼容旧路由和 receipt 形状。新协议仍要保证明确接收承诺、幂等、冲突与删除墓碑。
3. 模型可见性按场景配置：对话时附带的图片可让查询 Agent 按需读取；高频屏幕截图和 Coding 原始事件默认不直接暴露；Coding 聚合正文可读取。Material 是正式资料权威，但不是所有即时输入的唯一可见载体。
4. 查询不得被整条加工链阻塞，应使用已可见的部分结果并携带处理/缺件状态。Memory 等派生任务按来源声明的具体依赖（例如 OCR 已完成）等待。
5. 手工文件解析的低置信或有歧义结果待人工确认，其余自动发布。
6. 确定性步骤可在配方升级后自动重算；会产生费用的模型历史重算由用户触发。
7. 首版先支持内置和本地受信 Source Pack；Python 在隔离进程运行。不要求任意第三方包动态安装与卸载。

### 可见性与依赖的场景契约

Source Pack 声明输入形态、产物和默认暴露路由；可信内核按「受众 × 操作 × 处理阶段 × 表示形式」逐次授权。资料正文不携带读取权限。一个来源可以同时有原件、可分页 Material、目录卡片和命名产物，但这些表示不自动互相授权。

| 输入 | 查询时可用的表示 | 默认不暴露的表示 | 后续工作依赖 |
|---|---|---|---|
| 对话随附图片 | 仅在本次对话授权范围内供 Agent 按需查看和引用图片 | 其他对话的附件 | 是否生成 Memory 由该操作的资料依赖决定 |
| 每 5 秒的屏幕截图 | 当前压缩片段或 Material、覆盖度和时间定位；从片段展开时可核对选中的原图 | 逐张截图的目录和任意 UUID 直接读取 | 需要 OCR 的 Memory 等对应 OCR 产物就绪 |
| Coding Agent 长会话 | 一个会话 Material，正文按块分页，标示缺片和未完成状态 | 成千上万的原始事件包及独立事件搜索结果 | Coding Memory 等 `conversation` 产物就绪；新增事件按版本续接 |
| 手工上传文件 | 高置信且无歧义时自动发布解析资料；有缺件时返回当前合法部分与状态 | 未核准的低置信解析结论 | Memory 按配方要求的 OCR、解析正文或其他命名产物等待 |

查询只使用当下有效的授权和资料版本；旧引用不能成为跨请求读取已被替换资料的能力。资料所有者仍可按保留政策查看历史版本。Memory 工作固定实际使用的命名产物与证据指纹；没有块映射的依赖固定 Material revision。模型调用前后及提交时复查依赖。

## MVP 断代操作

新服务启动时检查 `backend_epoch=3`。旧库不会自动迁移或静默读取。先停止中央服务并备份完整数据目录，再显式执行 `npm run reset:mvp-vault -- --data-dir <中央数据目录> --confirm-clear`。该命令移除 SQLite、截图与文件原件、来源归档、导入暂存及退役的模型/文件处理设置，保留访问令牌、内容密钥、客户端及外部连接凭据、模型和日志。来源登记随 SQLite 清空，需要重新选择来源和处理配置。便携 JSON 只恢复当前格式，不能用来跨代恢复历史资料。

Mac 和 Android 使用本机格式 3；发现旧格式时明确拒绝并保留原文件，不自动清队列、转换密文或改写草稿。先完成备份，再对端侧应用存储进行明确重置，重新设置并配对。CLI 旧 ingress spool 也需用户显式移走。升级顺序及回滚限制见[兼容清理实施记录](audits/compatibility-cleanup-2026-10-04.md)。采集写入仍使用 `X-Mote-Ingress-Version: 2`，成功收据表示输入已可恢复；幂等与冲突、绑定、隐私及删除防重建保护继续生效。

资料的 `artifacts` 记录会话拼接、OCR、文件提取等命名产物的 `ready/pending/failed/unavailable` 状态。查询可阅读已发布的 partial 资料并看到这些状态；当前来源配方与配置显式声明 Memory 所需产物，任务固定所用版本。

## 验收门槛

- 生成 fixture 覆盖重复上传、同身份不同批次、乱序/缺片/迟到、接收与发布前杀进程、旧 Worker 提交、插件升级/卸载、隐私删除、索引失败、模型阻塞及外部动作未知结果。
- 用小规模生成会话验证：多条原始事件拼成同一份完整逻辑 Markdown 资料，正文可连续分页、索引可搜，模型只看到会话资料而非逐条原始事件；追加、缺片、修订与删除保持同一逻辑身份和正确可见性。追加只处理变更的原件与资料尾块；确定性拼接调用模型次数为零。百万条压力测试不是本次 MVP 验收门槛。
- 停止处理 Worker 后仍能在配额内完成接收；大文件处理内存随批大小与并发有界；后台满载保留前台查询/取消名额。
- 搜索片段、目录、材料正文、图片、结构化查询、Python 输出、错误日志、追踪和导出都验证可见性；查询 Agent 只得到只读工具。
- 新 CSV、硬件协议、Python 转换、存储打包方式和 Coding 分组方案通过架构回归用例，核心运行时业务代码无需修改。
- 自动测试只使用生成资料。真机、真实模型和真实外部账户验证单独报告。PR 前运行 `npm run check:local`；新增 `moteText` 同步英文目录。
