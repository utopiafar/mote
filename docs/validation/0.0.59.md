# 0.0.59 分层上下文与响应性能验证

产品约束：Mote 是 AI 原生个人上下文采集器和中央档案。所有原始观察保留；固定时间窗、显式来源、精确去重、权限和预算由确定性代码处理，语义解释和检索路径由模型决定。Working memory 只负责当前对话。精选 Memory 不是唯一入口；新近事件、数字核对和未整理资料允许直接检索原文。

## 实施范围

| 建议 | 实现 |
| --- | --- |
| 快速状态与后台磁盘统计 | captures/blobs 事务计数器、逻辑存储账本；独立维护进程按分钟更新 physical snapshot/asOf，缺少快照时明确 pending |
| 隔离交互 | 独立 interactive agent/Harness 名额；降低并发不终止已运行工作；队列追踪记录 lane、单位和等待时间 |
| 避免概览原文回读 | memory_catalog + memory_scopes；页读取只含元数据；修改、删除和派生产物撤销通过同一事务失效 |
| 降低后台阻塞 | 原始片段聚合、物理目录扫描在 child process；小批次推进，15 秒稳定窗口，失败重启 |
| 降低状态写入成本 | 单 batch 查询与 750 ms 进度节流；事务计数器支撑 job 概览 |
| 查询路径 | context_at/context_end 索引、按需 COUNT、产物 FTS、来源 keyset 游标、查询向量 1.2 秒 deadline 与缓存/全文回退 |
| 对话 | turns 独立行，列表只读元数据，网页默认最近 20 轮并向前翻页；revision 检查防止删除与回复并发复活旧内容 |
| 分层执行 | L0 原始观察→L1 可核验文本→L2 精确片段/语义解释→L3 精选记忆→L4 整理；显式执行输入与 artifact provenance DAG 分离 |
| 有界记忆生成 | 语义模型每片段最多选 5 段、每段最多 1200 字符；抽取使用对应语义摘要和原文绝对范围；生成前后校验版本，引用必须精确匹配 |
| 渐进检索 | read-only context_index 跨层候选目录；常规查询默认 8 条、最多 12 条候选，单次最多展开 5 段原文；展开前检查预算；工具结果累计预算与上下文组成计量 |
| 客户端 #19 | 本地控制先更新；取消旧心跳/HTTP；准确待同步文案；仅忽略明确、窄边缘、非焦点 SystemUI 状态/导航栏，保留真实覆盖层检查 |

保留 SQLite 和单服务部署方式。维护子进程不是第二套服务；没有为 MVP 引入 PostgreSQL 或分布式任务基础设施。Harness 名额覆盖完整模型会话和工具循环，不声称等同于每个供应商 HTTP 请求；实际 token 用量仍按供应商返回的 usage 记录。上下文防护以 UTF-16 字符预算执行，不把它伪称为精确 tokenizer 计数。低频保留策略和显式删除仍可能产生同步数据库维护工作；按来源/时间过滤的精确 COUNT 也仍有扫描成本。

## 既有本机数据

2026-09-21，从正在运行的本机 0.0.58 中央节点取得一致性 SQLite 备份，复制本机归档附件到隔离目录。原始 captures 共 **117,467 条**；全表按 ID 顺序计算 id/json SHA-256，迁移前后一致。首次迁移约 44.7 秒，只在启动阶段发生。原始数据、凭据、摘要值、模型回答和测试副本均不入库。

旧版 HTTP 4 次样本；新版同一归档副本上的 HTTP 12 次样本。新版与后台维护并行，测试期间同机还有编译负载；端口、OS 页缓存和活动任务状态不同，不作严格实验室倍数承诺。

| HTTP 接口 | 旧版耗时 ms（全部样本） | 新版中位数 ms | 新版最大值 ms | 新版最大响应字节 |
| --- | --- | ---: | ---: | ---: |
| status | 9200 / 434 / 427 / 442 | 1.22 | 10.77 | 1327 |
| captures limit=20 | 1846 / 1577 / 1624 / 1617 | 104.12 | 869.67 | 28622 |
| memories limit=20 | 15 / 6 / 5 / 6 | 0.69 | 3.00 | 20981 |
| conversations limit=20 | 3 / 1 / 1 / 1 | 0.38 | 2.17 | 3396 |
| memory-jobs | 59 / 94 / 10 / 10 | 0.74 | 1.25 | 9454 |
| context/segments limit=20 | 无有效旧样本 | 0.42 | 4.06 | 12396 |

旧 memory-jobs 响应为 724,550 字节，新版约 9.5 KB。另有每项 30 次的存储层测试：状态 p95 0.35 ms、记忆概览 p95 1.67 ms、任务概览 p95 3.54 ms；这些不混作 HTTP 结果。记忆概览注入禁止原文读取的钩子，原文读取次数为 **0**。维护进程正常推进，观察到的失败次数为 0。

可使用 `node --import tsx scripts/benchmark-local-archive.ts PRIVATE_LOCAL_COPY OUTPUT_JSON` 重跑无模型的存储测试；必须传入包含 local-copy 的隔离路径。此脚本只输出计时、数量、响应大小和完整性布尔值。

## 真实模型与生成夹具分开记录

- 真实模型：使用现有中央模型配置，在上述本地副本的一段 15 分钟历史文本上完成问答，HTTP 200，约 147.6 秒、3 条引用；实际调用跨层目录、片段、时间线、活动、媒体及证据工具。回答明确区分离散抽样与连续计时、后台暂停与实际观看、第三方内容与本人事实。未调用图片工具。
- 真实分层处理：已有文本片段成功生成 1 个语义产物（约 33.1 秒），只选取 57 字符作为记忆证据；后续抽取/审核完成（约 58.5 秒），没有接受新记忆。这验证执行与约束，并不把“无新记忆”包装成记忆质量提升的统计结论。
- 生成夹具：TypeScript 类型检查、workspace 测试、读模型/并发隔离/撤销/分页回归、生成截图到中央归档的 E2E、媒体 E2E、MCP、更新与安全、profile/tunnel 测试。
- Mac 生成 UI：中英文切换、本地离线首绑/显式同步、设置应用、中央导航、对话恢复/分页兼容、模型配置均使用临时 profile。没有采集桌面个人内容。
- Android：单元测试、Lint、DEV 构建；模拟器测试的详细最终结果在发布验证后补记。没有实体 Android 设备检查，也没有真实小红书账号页面采集。SystemUI 规则以生成窗口描述验证；真实覆盖层依然拒绝。

## 发布与迁移

0.0.59 使用一次性迁移建立计数器、时间索引、记忆目录与逐轮对话。升级退役未完成的旧自动原文抽取工作并重放产物日志；原始记录、手动导入与已存储事实保留。MVP 不保证向旧程序降级读取新数据库；回滚使用升级前备份。发布工作流继续要求检查、Docker 集成、Mac 构建/UI 和 Android 构建通过后，才创建带两个 DEV 客户端附件的版本。
