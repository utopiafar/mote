# Agent 页面在部署重建后的恢复验证

2026-10-01 从最新主线复现并修复。旧首页延迟加载 Agent 页面时，上一构建的模块文件可能已被删除。之前服务端向该 `/assets/` 请求返回首页 HTML 和 200，浏览器拒绝模块 MIME 类型，React 页面边界显示通用的“专用视图暂不可用”，没有实际重试动作。

Agent 页面先前独立的生产模块约 19KB，gzip 约 6KB。现在该页面代码随首页加载，仍通过独立 Cordis 插件注册首页与页面。只有挂载页面或标签时才请求数据；无需新增刷新按钮、自动重载或保留无限的历史模块文件。缺失的 `/assets/` 请求返回 JSON 404 和 `Cache-Control: no-store`，合法的 SPA 深链接继续返回 HTML。已经运行旧版的标签页需要手动刷新一次以获得此修复。

`node_modules/.bin/electron scripts/test-agent-view-browser.cjs` 使用独立生成资料库与浏览器 session。在尚未加载 Agent 页的首页中，禁止所有 `/assets/` 请求，模拟部署移除旧模块；首页入口及四个标签必须继续工作，模块请求数保持零、navigation timeOrigin 不变，且不出现错误或恢复按钮。原有目录分页、正文展开、首次上下文、追踪和移动布局旅程同时覆盖。首页与 Agent 页各十次冷缓存首次导航包含认证、脚本、数据和两帧绘制等待；脚本要求两个页面的最慢时间均低于 500ms。

最终生产构建测试：首页最慢 87.7ms，Agent 页最慢 121.1ms，20 次全部通过。入口 JavaScript gzip 从约 437.39KB 增至 442.41KB，增加约 5KB。以上为本机 Electron Chromium、1360×1000 与回环生成资料库，不能作为任意网络或硬件上的延迟保证。

`node_modules/.bin/electron scripts/test-web-feature-packs.cjs` 的 26 个页面、Cordis 功能注册、生成 Coding 资料正文、Agent 正式资料读取、移动端布局与能力接口失败重试也全部通过，没有浏览器 console error。

完整检查 `VITEST_MAX_WORKERS=2 npm run check:local` 通过，包含国际化、共享包构建、全部工作区与脚本类型检查、工作区测试及中央运行器。默认并发的一次运行中，已有桌面端 400 条历史笔记上传测试达到 30 秒超时；该测试单独重跑通过，限制并发后的完整桌面套件 354 个测试全部通过。没有修改采集器行为或放宽测试超时。

本地运行中的 dev 中央通过只读浏览器诊断确认：新会话打开 Agent 页面及四个标签均可用。未采集个人截图、写入真实资料库或调用真实模型；未直接取得用户旧标签页的控制台，因此实际会话原因与相同症状的重建复现、新会话正常结果一致。
