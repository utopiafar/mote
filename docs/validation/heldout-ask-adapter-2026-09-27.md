# Paired Ask adapter (generated fixtures, no live model)

The adapter adds one paired ordinary Ask stage to the existing frozen experiment. Each arm gets a separate closed SQLite backup, app, conversation and provider session from the same canonical checkpoint. It preserves the existing experiment identity, production/runtime pins and cumulative 124-outer planning ceiling. A pair permits at most two outer admissions, 300 seconds each, under the separately frozen 720-second Ask supervisor. No failed or incomplete pair advances the evaluation cursor; query artifacts never become the archive head.

`stage-ask-freeze` consumes `MOTE_HELDOUT_ROOT_MANIFEST`, `MANIFEST`, `PARENT`, `LEDGER`, `VALIDATION`, `SUPERVISOR`, and `OUTPUT` with the common `MOTE_HELDOUT_` prefix. Optional `MOTE_HELDOUT_ASK_PLAN` must match the original sealed plan. The first plan fixes all eight questions' execution order and independent anonymous display labels. A separately fsynced, exclusive-create `ask-plan-commitment.json` binds its reference in the ledger directory. It is freeze metadata, **not** a new accounting ledger. Failed freeze, new output directory, or later executor cannot silently redraw the plan. All eight pairs must have exact boolean treatments (one true and one false), globally unique UUID slot IDs, and exactly the two anonymous response labels. These checks run before the first commitment and again before execution. A partial/corrupt commitment stops execution. Every phase manifest binds both the commitment hash and sealed plan reference.

`stage-ask-live` accepts only a heldout evaluation manifest. The supervisor remains external (`run-heldout-ask-supervised.py`, hash `a320b1bc0f707e2bbabcb127b7acf99239e03c4b2d5f68f12c5755f03219986d`). Existing generic stage-live and integration routes are unchanged. A stopped or interrupted ledger is rejected; this adapter implements no paid partial-pair recovery.

The request reconstructs only the literal question and Asia/Shanghai timezone. It supplies no rubric, expected facts, available evidence IDs, experiment prompt, previous conversation or skill. The host semantic clock drives both ordinary opening Memory and retrieval. Normal API trimming is checked before execution; it may not silently rewrite a frozen question. Static policy/tool code is identical across arms; opening Memory content is intentionally different.

Ablation removes the frozen Memory state and verifies all logical Memory tables and FTS are empty, while preserving source authorization, ordinary originals, Coding archive history, Material versions and deterministic source indexes. The 178-table column inventory was generated from an independent mechanical fixture and is pinned as an executor helper. Unknown schema, processors, contributions or unsupported nonempty derivatives stop before admission. This **text-only** experiment has no media/preprocessing lane: unexpected summary/perception content is stopped for classification, never deleted to improve one arm. This is not a general product rule that OCR or source summaries are Memory.

Checks distinguish SQL ablation, app initialization, and query-owned changes. Empty lifecycle cursors may be recreated on initialization. Subsequent memory_events must refer only to the new conversation; sequence counters must match those additions. B's preexisting state remains unchanged. Query/operation/usage additions are restricted to the current query IDs; source rows and external objects are protected. Storage accounting changes are restricted by the affected table name, not the entire ledger table. A late missing/running/conflicting receipt stops the pair after recording available terminal accounting. Usage records are projected to the accounting whitelist; original full receipts stay sealed.
