# 音频处理超时衔接

## 用户流程与问题

用户在文件处理设置中可配置 1 秒至 1 小时的超时，但受管理本地 ASR Worker 先前固定使用 600 秒。长录音提取实际出现约 601 秒超时；仅提高中央设置无法扩大 Worker 的预算。原件仍保留，失败不能记作转写完成。

中央现在为本地转写和分离发送经过既有配置 schema 约束的请求预算。Worker 校验请求头，并采用该预算与其独立运行上限的较小值。Native supervisor 和 Docker sidecar 显式使用与中央设置最大值一致的 3600 秒运行上限；默认中央预算仍为 600 秒。

## 责任与保留边界

- KEEP：中央负责整条流水线总预算、授权、检查点及配置指纹；Worker 负责隔离子进程的资源回收。默认实际处理预算、时长上限、离线模型、匿名说话人、原件和已完成文件均保持既有语义。
- CHANGE：本地请求携带配置预算；托管 Worker 不再以隐含 600 秒上限阻止已经配置的较长预算。
- REMOVE：把 Worker 固定默认值误当作中央所有合法配置的处理上限。
- EXCEPTION：手工部署的 `--timeout` 继续是独立上限；旧客户端没有请求头时继续沿用它。远端 ASR 不获得本地专用预算请求头。
- UNKNOWN：真实长录音在指定预算内完成的概率、识别准确度和听音质量。延长预算不是这些结果的验证。

## 生成夹具验证

`scripts/media-workers.test.mjs` 通过真实 Python HTTP 入口与隔离生成的模型函数验证：未认证请求拒绝、非法预算拒绝、较短请求超时、后续请求释放并复用处理槽、请求不能突破独立 Worker 上限、无请求头的旧调用保持默认行为。相同文件中的 supervisor 测试核对受管理 Worker 的实际启动参数。

`apps/server/test/file-processor-proxy.test.ts` 在独立进程的 HTTP/HTTPS 入口核对转写和分离收到显式 30 分钟配置，以及本地请求继续绕过环境代理、不泄露认证。OCR 和健康请求不携带音频预算。生成夹具不调用真实 ASR 或说话人模型，不证明语义质量、长录音性能或实体设备行为。
