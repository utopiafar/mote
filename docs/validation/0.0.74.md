# 0.0.74 validation

This DEV release fixes Android local synchronization scheduling and Web confirmation for file processing whose completion is unknown. Personal inputs, credentials, private experiment receipts and generated APKs remain outside Git. The complete multi-device Goal remains in progress.

## Android synchronization

Loopback central URLs and explicit synchronization can start without Android's validated-network WorkManager constraint. Automatic remote synchronization retains its configured connected/unmetered constraints. Runtime checks enforce the Wi-Fi, unmetered, battery and charging settings before each HTTP request, including source registration, bundles, capture reconciliation and attachment parts. A change in those conditions returns the work to waiting; failed conflict lookups do not swallow the condition exception.

The implementation passed 231 JVM tests across 51 suites, with 30 targeted tests repeated after the final exception handling change. An isolated Android emulator preserved six generated notes from the published 0.0.73 APK, including offline drafts and restart recovery, then synchronized them using the modified APK. Independent closed-record checks matched all original UUIDs, full text, timestamps and mood; the queue reached zero and duplicate acknowledgements retained six central captures. All native JUnit assertions passed. The controller separately reported failure because it expected a console marker absent from JUnit output; that failure remains preserved and is not counted as controller acceptance. These checks used no LLM or personal screenshots.

A fresh complete same-version emulator journey is still pending. The Wi-Fi-only enabled branch has JVM coverage; the actual recovery used Wi-Fi-only disabled. Physical devices, OEM behavior and native Mac capture are untested in this release.

## Unknown completion confirmation

An accessible in-app alert dialog replaces the browser's native confirmation. Cancel and Escape send no retry request; confirmation retains the selected processing stage, traps and restores focus, and switching central nodes clears the pending confirmation. The Web suite passed 183 tests, including those cases. The new translation is synchronized with the shared and Android English catalogs.

Normal interaction with the original warning was observed, but the updated dialog's native/browser journey remains pending. A locked Mac and an older browser confirmation prevented completion of that UI check. Component tests are not counted as native UI acceptance.

## Remaining semantic work

Generated bounded continuation tests passed seven independent cases; their stub provider calls are separate from live-model checks. Historical held-out continuation recovered one paired Ask and completed the first batch in wave three using the unchanged frozen experiment snapshot. Seven pairs and blind quality evaluation remain open; fees are unpriced where unavailable. Those historical live checks do not establish 0.0.74 Memory quality.

Three local requests on a generated six-turn audio fixture completed and cleaned up successfully. Small and turbo raw character error rates were 30.8% and 20.4%; meaningful number, uncertainty and tail errors remain. Automatic diarization returned three labels for two generated voices. The default model remains unchanged. This is a technical completion result, not an ASR or speaker-quality pass.

The full check reported 1,823 tests: 1,821 passed, two skipped, zero failures; this includes i18n synchronization, library builds, typechecking, all workspaces and the media/client scripts.
