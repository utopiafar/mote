# Heldout replay: limited first-stage adapter

The adapter now supports freezing a fresh wave-1 vault and running its first planned batch. It does **not** implement the later-wave, integration, or question A/B runner. No real model was called during this implementation, and neither source text nor questions/rubrics/answers were inspected by the implementation agent.

The live scope is one batch, at most two conservative outer admissions, Codex App Server `gpt-6-sol` / `max`, 300 seconds per outer, concurrency one, and zero outer automatic retries. The separately hashed supervisor enforces the 720-second process envelope, including closing time. The runner itself does not enforce that whole-process deadline; use the supervisor, which seals stdout/stderr. Empty generation does not spend unused capacity on another batch.

The guard pauses the original job once the selected batch enters the query boundary. Its review and commit may finish; later batches remain pending. Success requires a completed batch, no failed/running batch, and actual persisted chunk checkpoints. The public `realModelCalls` count means durable outer admissions, which can conservatively include a reservation before provider start. Observed `modelRunStarts` counts Codex turns, not underlying provider HTTP requests. Unknown usage/request counts remain unknown.

An external append-only, hash-chained ledger reserves each logical call before the provider boundary. The ledger survives vault cloning; inherited receipt IDs are excluded from each new stage's accounting. Receipts are read only after `app.close()`, matched individually to admissions, and retained even on failure. Host-rejected receipts are accounted separately. Missing/running receipts, terminal-status disagreement, interrupted admission, an unclosed stage, or an unreleased writer lock prevent automatic continuation. The adapter never reclaims a crashed lock or refunds an uncertain admission.

The stable experiment hash binds the initial closed seed, corpus/eval freezes, production source/dist and runtime skill files, workspace package manifests, model/strategy settings, the six-wave batch plan, and its 124-outer planning ceiling. Runner and supervisor versions are separately frozen. The narrow `bindExecutor` transition requires the preceding executor hash and an offline validation-report hash before appending a new executor version; it preserves the same ledger and paid calls. Future runner work must use this interface and the last successful closed snapshot, without regenerating completed batches. It is an internal technical review, not a new request for user authorization.

Generation drafts can persist across closing. Independent review cache/receipts are process-local until batch commit. A paid review followed by a crash or commit failure is not a reusable completed review checkpoint; this limited runner stops instead of retrying. General failed-draft recovery is outside its validated scope.
