# Model-selected image regions

`read_image` retains its existing `{id, attachmentId?}` original-image path. A query can now request `view: "metadata"` for a host-verified original SHA256, MIME, encoded raster dimensions, EXIF orientation and frame count without an image payload. A model-selected `region: {x,y,width,height}` requires that original's `expectedImageSha256`. Metadata is not a permission grant; every read rechecks the original, current source/attachment relationship and model privacy policy, including after decoding/cropping and reservation waits.

Coordinates are integer, top-left, half-open original encoded raster pixels. Each region side is at most 2048 and must fit inside the original. This matches the existing native OCR coordinate frame, which does not auto-orient EXIF images. Crops become sRGB PNGs without resize, padding or EXIF rotation. The original path returns unchanged original bytes. Multi-frame region reads fail explicitly, including APNG detected by a bounded PNG acTL/fcTL scan when libvips omits its page count; metadata and the original remain available. Originals remain bounded to 8 MiB / 40 million decoded pixels; output is independently bounded to 8 MiB. No OCR, semantic region selection, automatic tiling, original rewrite or persistent derivative is involved.

`imageView` preserves original and output hashes, geometry, transform version and a deterministic view identity. Current and first-disclosed selection metadata remain distinct even when different locations or raw/Material aliases yield identical pixels. Four unique output payloads per query remain the limit. Metadata and duplicate reads consume normal tool calls; metadata does not consume an image slot. Local delivery receipts retain failure recovery, expiry, cancellation and single-query lifetime. These receipts show local preparation, not remote model attention.

Both Codex and Harness render the image with `imageView`, `imageBudget` and `hostBudget`. Shared DSL compilation preserves the optional region object's required x/y/width/height fields and `additionalProperties: false`. The bridge still validates numerical and cross-field constraints itself. `ToolTrace.imageView` records metadata, pending/prepared/failed local delivery, or successful repeat disclosure without base64. Citations keep the existing source ID and can be joined to that view trace. There is no new independent crop citation or UI region highlight.

Generated checks cover exact crop boundary pixels, metadata without pixels, invalid/stale requests, EXIF, multiple frames, input and output limits, source version changes, raw/Material/direct selections, revocation, aliases, duplicate/concurrent reads, receipt failure, query restart and unchanged original bytes. Codex RPC and real Harness processes against fake OpenAI Completions/Responses, Anthropic and Google servers verify the nested tool schema, image payload and first-image budgets.

An isolated installed Codex 0.156.1 experiment also exercised SourceStore ingress, archived attachment linkage, EvidenceReader and the new public tool. A generated 1200×14825 PNG was queried as metadata, a 1200×1800 region, the same region again, then a 1200×1600 region. Actual loopback HTTP image counts were `[0,0,0,0,1,1,2]`; both native crops retained the host output byte hash and dimensions. The installed CLI represents tools under `input.additional_tools`, including code-mode declarations, rather than the fixture's conventional top-level JSON tools array. No real provider, private material, held-out data, OCR or ASR was used.

External diagnostic runs retain the initial probe's failed assertion about tool-schema placement; its image transport had completed. The corrected independent run inspects the installed protocol's model-visible declaration. This is structural validation, not a semantic vision score or proof that regions fix an earlier answer. Existing live-image harnesses that mandate exactly one original payload require an explicit accounting update before testing metadata/multiple regions; frozen questions, images and rubrics were not changed here.
