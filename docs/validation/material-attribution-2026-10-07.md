## 数据与评估方式

自动化数据全部生成，不使用真实个人截图。真实文本限用户已提供的分享对话及本轮明确指令，原件、隔离库、模型输出和报告保存在 Git 外的私有临时目录。没有读取生产资料库或扫描用户磁盘。

`scripts/test-material-attribution-live.ts` 使用真实 buildApp/listen、HTTP 来源接收、默认后台组织和 Memory 调度、问答、关闭/重启；不手工拼装内部提取路径。offline 模式以 stub 验证流程，不证明语义。live 模式使用本地 Codex Server，配对同一代码在无声明/有声明输入下的表现。按用户要求统一为 `gpt-6.1-sol / high / fast`，通过 HTTP 保存配置并选为各功能默认；单次 Agent 超时 900 秒。已完成的配对运行上限 32 个被记录的 `agent.query` 调用、90 分钟；后续 runner 上限调整到 48，恢复运行必须在报告记录预算变更。Runner 不自行重试请求；产品内部的委派、汇总和重试照常执行并计入记录。模型内部工具和用量按实际账本报告，不把被记录的调用数当供应商模型请求数。

指标分别审读：错误本人 Memory、本人的感受保留、第三方正文可检索、真实活动/结果/定位召回、精确引用、每臂延迟与用量。该样本用于发现回归，不是保留集、统计覆盖度或生产召回率证明。

### 本地模型回放

生成样本为未知日记、第三方第一人称文章、带转写请求和已述产物位置的混合记录；真实文本为用户问题、助手建议和带本轮执行要求的混合对话。每种三份资料分别运行无声明/有声明两臂，全部原件留在隔离库中。真实文本并非真实访谈转写，不据此声称验证过用户的采访资料。

模型回放先于最后三项边界修复完成；最终修复保持本批文本路径的模型指令不变，使用生成 fixture 和整体验证检查新增撤权、授权与回滚路径，不冒称重新执行过所有 live 调用。

生成配对运行执行通过，25 次被记录调用、12 分 14 秒；两臂各三次问题返回答案，关闭重启各六秒均无模型重放。原报告把六次 `AgentYieldError` 委派交接标为 failed，逐项核对它们全部对应同一时刻的 `query.yielded` trace，两臂均无 `query.failed`；用量账本按现有规则记为 completed。报告原件保留，后续 runner 将这种控制交接单独记为 yielded。正常返回调用由 CodexSession 校验后端返回 fast tier；交接调用的后端确认状态作为未知看待。用量账本的供应商请求数与费用不可得，不能将字段零值解释为免费或没有请求。

子 Agent 逐份核对全部 12 个答案、保存的 Memory/observation 和引文，根 Agent 复核契约及执行报告。未知日记的疲惫、开心与自豪感均可查询，无声明臂保留为 observation，显式声明 unknown 的臂进入精选 Memory，但仍保留叙述者归属不确定性。这体现本次样本的保留路径，不能推断声明提高了准入率。第三方偏好及定价理由能查到，没有变成用户本人的偏好；转写请求、已收到的产物和原有定位可查，未改写成用户亲自采访、已录音或采纳观点。真实对话能区分用户的问题/执行要求和助手的方案，也能区分计划与已完成事件。保存引文与原文一致，答案引用支持其陈述，部分答案引用当前派生产物而非 raw 原件。

真实配对运行执行通过，24 次被记录调用、14 分 35 秒；两臂各三次问题完成，关闭重启均无模型重放。其六次委派交接全部与 `query.yielded` trace 匹配，两臂均无 `query.failed`。本批样本未观察到错误本人归属或捏造已完成活动。真实有声明臂的观察简述省略本地 Codex Server 要求，但保存引文及问答都保留该要求；这不是完整指令捕获保证。长消息引用预览有截断，完整对应证据仍可读。

额外 `scripts/test-material-attribution-owner-live.ts` 在已关闭的生成有声明臂资料库的副本上，通过真实 HTTP 将日记单份声明改为 owner。旧推断 Memory 立即 stale，正文和原有接收授权不变；等待 12 秒，没有新增自动模型调用或任务。随后显式提交个人 v2 历史任务，2 次成功且确认 fast 的调用产出 1 条精选 Memory，归属 user。逐份审读确认它保留调试后的疲惫及家人首次试用时的开心/自豪，注明这是主观感受，不是原型质量证明或长期性格；保存引文仅含日记感受，未纳入 Mira 的黎明会议偏好。该校准未另跑问答，不修改原配对报告，不证明总体准入率。新增两次用量账本共报告 19,280 token；供应商请求数和费用未知。

### 已修复的验证问题与边界

早期 300 秒模型执行发生超时；已按用户要求增加到 900 秒并统一型号/fast。一次中途版本以高频完整队列轮询触发 HTTP 429，关闭过程又中断正在运行的模型；runner 改为五秒摘要轮询、完成后才读完整队列。旧型号和未完成运行保留失败报告，不能混入最终统一配置的通过结论。

独立审查发现并修复：只引用 raw capture/ASR/excerpt 的旧 Memory 未失效；按 OCR 阶段名字而非类型保留产物；纠正回滚误取消在途工作；来源先改声明但尚无 Material 时旧图像语义仍可复用；共享图像解读撤权后另一资料仍显示旧结论。最终复核另外修复：首次 Material 之前纠正未撤销通用语义 artifact；图像读取授权错误地用无归属 raw 指纹比较已含声明的授权；snapshot 图像在纠正事务回滚前被物理清理。通用产物删除沿原件/ASR/excerpt 及既有下游依赖传播；图像授权保持现有范围和 OCR 状态检查；临时像素只由已有 prepare 流程按提交后的成功状态清理。新增对应生成数据回归，59 项产物/图像授权及依赖检查、22 项完整 image-processing 检查通过，服务器 typecheck 通过。原件、OCR/ASR、历史收据与无关图像的处理授权继续保留。

Snapshot 像素仍按既有临时输入政策处理：失败纠正回滚保持字节；成功纠正保留 OCR/文本，撤销语义解读，并在下一次 prepare 按已提交状态释放临时像素，不承诺长期保存原件。显式重试与端侧重供沿用既有传输恢复/授权检查；本轮没有单独组合测试「纠正后重试再重供 snapshot 图像」，已有完成/过期/取消恢复回归不冒充该组合验收。
