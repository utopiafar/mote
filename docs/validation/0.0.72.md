# 0.0.72 validation

This DEV release includes the automatic Memory, retrieval and recovery changes since 0.0.71. The broader Goal remains active and incomplete. The user explicitly requested this release after the current repairs; publishing does not turn the remaining quality or device work into completed validation. Personal originals, model answers and private run artifacts remain outside Git.

## Product behavior

Reviewed Memory becomes effective after evidence and version validation, without a separate owner confirmation. Deletion intent survives recipe changes and reimports whose original identities can still be verified; a separate model comparison checks whether a candidate repeats a rejected conclusion and whether new evidence supports reconsideration. Query agents retain read-only context tools. Explicitly forgetting a source removes its related rules. Inputs without an original timestamp or stable source identity cannot be assumed to be recognizable copies. See [automatic Memory](automatic-memory-2026-09-27.md) and [deletion boundaries](../memory-updates.md).

Manual Memory recipes run when their own required inputs are ready. Unrelated waiting or failed inputs do not prevent completed results from being read. Original text and citations remain navigable. A valid extraction draft can be reused after review failure or restart; changed input, policy, configuration or cache availability can require extraction again. The retry UI now explains this boundary without adding confirmation.

Image tools expose bounded, model-selected original-pixel regions and reuse repeated image deliveries within a query. Material text pages account for the whole serialized tool response and retain the next read position. Historical semantic time is separate from wall-clock execution accounting. Immutable Coding retransmissions no longer rebuild the current material projection.

The host now labels its own deadlines with the Agent timeout type, preserves an earlier caller cancellation exactly and disposes timers/listeners. Existing late-result commit fences remain. Interrupted cumulative usage stays incomplete when its tail is unknown. See [host deadlines](host-agent-deadline-2026-09-27.md).

## Live models and remaining quality limits

The fixed generated automatic-Memory journey exercised extraction, independent review, automatic effectiveness, correction/history, deletion followed by reimport and genuinely new evidence. It used the specified Codex App Server model channel, not local inference. It does not establish stable benefit across natural personal material.

The most recent generated image Ask completed with five of six required quality items passing and one partial: an experience-scope qualification was omitted. Its 171,793 reported tokens are an observation, not proof of a stable reduction or a passed cost target. The earlier observations and failures remain. See [image result](generated-image-post-pagination-2026-09-27.md).

The sealed mixed-corpus replay remains stopped after the third batch of wave two failed during review. It has 20 admissions and receipts: 17 completed, three failed, and three incomplete or absent usage records. Reported usage of 788,204 tokens is a lower bound. The eight paired questions have not run; no held-out net-benefit result is claimed. Generated recovery-adapter validation does not itself authorize or complete that live replay.

Physical-device/OEM background behavior, the full private image/audio distribution, whole-input processing and scenario-specific Memory benefit remain open. Fixture, real-model, emulator and physical-device evidence are reported separately.

The new review-only replay adapter passed 13 focused generated tests and an independent final 13-case run, with 13 stub calls in each. It rejects extraction fallback before admission, permits one exact review and preserves failed closures and accounting. A separate 13-case generated E recovery regression also passed after its timer assertions were updated to distinguish host, runner and session deadlines from the local deletion-cleanup timer; independent read-only review confirmed the assertions still enforce 600 seconds. Original-418-pin applicability and actual recovery remain unperformed. See [recovery validation](heldout-normal-review-recovery-2026-09-27.md).
