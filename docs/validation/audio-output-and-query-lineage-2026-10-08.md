# 录音输出与问答依赖恢复

## 用户旅程与已确认故障

已归档的录音转写成功后，匿名分离输出超过 100 个标签会使分离失败；一个词级时间比所属句子多出 56 ms 也会使整份转写被拒绝。两种故障均用生成内容复现，修复保留原始模型文字、时间和标签，不通过合并标签、调整声学阈值或强制人数隐藏异常。

图片的显式“继续处理”曾只重置投影视图，却保留已过期执行窗口；现使用既有手动重试接口，为当前计划的未完成步骤重置预算，保留成功 OCR 与历史代次。自动执行器、租约和 Memory 一次尝试策略不变。

问答目录的依赖缺失则会使后台处理其他资料时保守清除历史回答。本次只补宿主证据收据，不放宽模型读取权限或隐私清除。

## 取代与保留

- KEEP：既有单一执行器、持久检查点、一次自动 Memory 尝试、手动恢复入口、来源与模型授权、原件和已完成文件。
- CHANGE：显式图片继续处理为当前未完成计划申请新预算；匿名标签不再受独立 100 个标签上限阻断，沿用有界区间预算；录音范围内的词与句时间差异可原样保存，整句对齐标记不确定。
- REMOVE：标签计数等于人数的假设，以及一个词级句界差异使整份合法录音失败的校验。
- EXCEPTION：试听和单次人工命名仍最多 16 个标签；非法时间、过量区间和异常媒体字节仍明确失败。旧输出和配方版本仍可用；新音频使用新版本，图片/文字版本不变。
- UNKNOWN：高碎片化的真实分离质量、其他尚未定位的录音失败、模型输出 schema 失败、截图上下文缺失与人工恢复后的全流程效果。

## 实际验证边界

访问限制解除后，全 workspace 构建（含 Desktop 原生构建）通过。顺序执行的完整 `npm run check:local` 通过；增加图片手动恢复回归后再次顺序运行完整检查并通过。图片处理相关 23 项通过。此前受 `EPERM` 阻止的 TCP / IPC 用例已实际执行，没有新增跳过规则。Python 音频原语 11 项通过。首次并行构建与检查曾造成两个产物竞争失败，稳定构建后相关 17 项复验及顺序全量检查通过。

真实录音、截图模型的修复后处理与实际产品恢复效果需在新提交部署后单独观察。生成测试及源码检查不等于真实整库处理完成。生产资料、凭据、原文与请求日志均在 Git 外的私有工作区。
