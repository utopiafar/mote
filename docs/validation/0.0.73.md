# 0.0.73 validation

This DEV release contains the cross-device reading, cancellation, recovery and request-isolation repairs since 0.0.72. Publishing is explicitly requested; the broader Goal remains incomplete. Personal inputs, transcripts, credentials and private experiment artifacts remain outside Git.

## Request isolation and failure messages

Generated regressions verify that background transport traffic cannot exhaust the foreground owner API budget. Both traffic classes retain bounded request limits, unauthenticated requests retain their shared IP limit, and expensive routes retain their stricter limits. The split follows fixed API routes, not a client-supplied lane header. Foreground actions that use the same upload/source-transport APIs still share the transport budget; this is not an unlimited or per-browser quota. Central API throttling uses `api_rate_limited`; provider throttling retains `rate_limited`. Web tests verify Chinese and English messages, request IDs and preserved authentication state.

## Cancellation and reading

The generated Android Chrome file-cancellation journey used one PNG and two controlled HTTP responses, with no actual OCR, ASR or LLM. Cancelling prevented the late result from publishing; the UI disabled retry until the existing request finished, then one explicit retry produced the expected text. Original-byte verification, full text, return navigation, narrow-screen layout and a 65-second quiet interval passed. The unknown-completion confirmation path has generated API/component coverage, but was not separately exercised through normal browser interaction.

Earlier generated Android journeys exercised imports, cancelled processing, Memory history and evidence navigation, manual integration, Insight reading, original images and backup/restore. They used recorded product revisions and are not claimed as fresh physical-device tests on the release tag.

## Real local media and mixed input

The fixed generated mixed run independently released 90 short text files, three images and three 129-second audio files over 90 seconds, plus one front-end note. A 15-second producer outage created a durable backlog. All 96 file jobs completed, the backlog drained naturally, and authenticated reads matched all 96 original sizes and SHA-256 values. Two actual local OCR requests and three actual local ASR requests ran; one duplicate image reused a valid result. No LLM, diarization or summary ran in this node.

Normal Android Chrome input overlapped the offline durable backlog. Two images' complete OCR and the audio's complete transcript matched the stored outputs; original-image access and actual audio play/pause were observed. The run also exposed 63 API 429 responses and the misleading model-throttling message, motivating this release's request isolation repair. Successful note save did not overlap recovered backlog, and recorded foreground actions did not overlap actual OCR/ASR request intervals. One fit-width image screenshot was blank and its follow-up was an operator mis-tap. The unchanged 720-second budget stopped the node with all owned processes gone; the overall mixed UI run remains partial. The later closed Python SQLite audit failed to open the database; this does not erase the earlier live readback evidence or count as a successful closed audit.

The 24-line generated H image retained all lines, with 16 literal matches and raw Unicode CER 17/530 (3.21%). The layout image omitted one character in its introductory sentence; OCR text does not establish arrow relationships. All three generated audio results were identical, with raw Unicode CER 159/583 (27.27%, preserving punctuation and mixed simplified/traditional script, without synthetic segment separators). Errors affected meaning, including the equivalents of “known” and “still unknown.” Processing completion is not a transcription-quality pass; generated speech does not establish private human-audio accuracy.
