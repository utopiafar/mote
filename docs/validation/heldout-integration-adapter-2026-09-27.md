# Single-window heldout integration adapter

`scripts/test-heldout-memory-replay-integration.ts` exports `freezeIntegration`, `validateIntegration` and `runIntegration`. The shared runner exposes explicit `stage-integration-freeze` and `stage-integration-live` modes; the live mode rejects mechanical manifests and unrelated task scopes before admission. The phase manifest references the unchanged experiment root, prior executor manifest, immutable canonical parent, append-only ledger head, phase-specific offline validation, a sealed complete selection plan, and a separately supplied supervisor fingerprint. Live execution additionally requires an explicit opt-in; this module does not validate or supply the separate 1320-second process supervisor.

Selection is a complete structural scan of the closed canonical snapshot at the frozen context time: published, current, non-stale, non-superseded, admission-layer Memory from both domains, including still-effective older consolidations. Observations, expired/future-valid cards, stale cards and superseded cards are counted as exclusions. Proposed, legacy admission and unknown shapes stop the phase. No text ranking, source filtering, truncation, automatic slicing or keyword routing is used. The frozen lifecycle maximum remains 30; the external ceiling is 50, so the current effective capacity is 30. An oversized complete set stops before a window or provider admission. Empty input completes without opening an app or creating a window.

One ordinary `requestMemoryIntegration` call creates one production window. Both nonempty domains run in production order, personal then coding, with at most four outer admissions, 300 seconds each, concurrency one and no outer retry. The declared phase process limit is 1320 seconds including closure time; an external supervisor must be independently frozen before live execution. A generated empty result naturally skips review. The module does not replace production generation, review, validation or atomic commit logic.

The admission guard reconstructs the expected domain solely from durable `completed[]`, fixed domain order, nonempty selected domains and the extract/review phase. It only compares the host card-ID array suffix for exact equality; prose never chooses a domain. Every admission verifies protected source/configuration tables, task scope, model and semantic clock, then durably reserves a unique window/domain/phase key tied to the running usage receipt. Model failure, timeout, unexpected scope, duplicate phase or a missing prior commit closes the circuit. In particular, successful generation and review receipts do not imply successful publication: a later extract with the previous domain still uncommitted is rejected before invoking the model.

Closure reads terminal usage only after the app closes, separates host-rejected receipts from admitted calls, preserves inherited cumulative accounting, checks SQLite and protected source hashes, and creates an immutable checkpoint. Public ledger receipts contain only the explicit id/status/tokens/estimatedCost/currency/durationMs allowlist; attribution, operation and unexpected future fields stay out. Only a successful integration closure advances the canonical archive head. Failed or unknown stages are not automatically resumed or refunded. Production can resume already committed domains, but an uncommitted integration draft/review is not cached; the adapter does not invent review-only recovery.

The generated test suite covers a full extraction-to-integration lineage, four-call publication, empty outputs, zero input/no window, first generation/review/deadline failure, successful paid review followed by transaction rollback, host rejection accounting, unknown ledger admissions, complete sets above 30, deterministic phase ordering despite misleading prose, old consolidation eligibility, proposed/unknown state rejection, protected table mutation, and injected extra receipt fields being excluded from both public receipt kinds without losing accounting. Test model usage, reviews and any validation-shape fixture are explicitly synthetic. Final suite reports identify their executor hashes and `validatedPhases: ["integration"]`; they are not semantic or live-model acceptance evidence. No heldout source text, cards, questions, answers, real media, OCR or ASR are read by these tests.

Run offline with an unused external output directory:

```sh
MOTE_HELDOUT_INTEGRATION_TEST_OUTPUT=/absolute/new/generated-run \
node --import tsx --test scripts/test-heldout-memory-replay-integration.test.ts
```

No production file, frozen execution tree or prior report is changed by this adapter work. Integration still needs independent review, final combined executor validation, and a separately frozen supervisor before a live phase is considered ready.
