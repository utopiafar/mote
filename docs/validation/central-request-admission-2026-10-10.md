# Central request admission validation

Date: 2026-10-10. Decision: [Central request admission](../adr-central-request-admission.md).

## Generated regression journeys

| Entry point and state | Verified result |
| --- | --- |
| Actual loopback HTTP: 220 capture writes interleaved with 220 status reads | All writes and reads succeed; no request-limit headers are emitted. A subsequent authored note also saves. |
| Actual loopback HTTP: 200 public health reads followed by an unauthenticated private read | Health remains available; the private read still returns 401. |
| Repeated query, query-run, import, model-test and Insight requests through registered APIs | Their existing input/configuration errors remain accurate above the former route quotas; no local limiter substitutes 429. |
| Registered login API: 130 tickets; login fixture: more than 100 pending requests | New handoffs remain admitted; expiry, verifier checks, parent revocation and single-use exchange remain enforced. |
| Browser upload APIs: 70 pending originals and 620 identical part requests | Part replay is idempotent; app close/reconstruction retains all sessions and acknowledged parts. Commit/readback returns the exact generated bytes. |
| File snapshot recovery API with 64 other unfinished uploads | The recovery is admitted as the 65th upload, verifies its generated original, and restores the same evidence identity. |
| Query API: 1001 pending independent queries | All return 202 while actual scripted-model execution stays within configured interactive concurrency. Replay retains identity, changed payload returns 409, and cancellation works. |
| Import store: 1001 retained jobs referencing a generated archived original | New jobs remain admitted, and the original remains readable and unchanged. |
| Distinct concurrent Insight API requests plus same-ID replay | Independent runs are admitted and complete; replay is deduplicated, changed payload still conflicts, and cancellation/deletion fences remain checked. |

The primary regressions are in `apps/server/test/request-admission.test.ts`.
Snapshot recovery, login, connections, diagnostics, imports and Insight suites
retain their integrity and authorization checks. Existing provider and client
transport tests continue to verify upstream 429 recovery.

## Final checks

`npm run check:affected` exited 0 on the final code and dependency state. The lockfile
change conservatively selected all consumers: `check:local` and Android
`:app:testDebugUnitTest`. The checks covered i18n synchronization, library builds,
workspace/script typechecking, workspace tests, release/worker/client tests and the
central process supervisor. Desktop passed 402 tests; Server passed 1382 with one
optional skip; Web passed 268; Agent passed 243 with one optional skip; Diagnostics
passed five; Shared passed 177. The root script suites passed 63 and four tests,
and the central-runner check also passed.

Android XML reports contain 281 tests across 60 suites with zero failures, errors
or skips. An explicit Android run executed the tests successfully; the final
affected-check invocation then reused the same successful Gradle outputs.
The local environment used Node 26.11.1 and a temporary Temurin JDK 21. Android
dependency fetching used the existing local network proxy; application and build
configuration were not changed to accommodate the environment. `git diff --check`
and changed-document link/format review also passed.

## Limits

All new inputs are generated and model responses are scripted. No personal
screenshots, real media, live model calls, physical devices or browser UI were
used. The original user's request ID and deployed revision were not captured;
these regressions exercise the known quota conditions rather than claim to replay
that exact incident. This work does not update a running node or establish
large-dataset throughput/latency measurements. Other unrelated product limits
are outside this decision and remain subjects for the separate design audit.
