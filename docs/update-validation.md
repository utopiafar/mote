# 0.5.1 发布与更新验证

本次验证针对版本发布、安装包真实性、客户端升级及中央节点升级/回退。自动化只使用生成的 App、APK、截图、笔记、配置与凭据；未采集个人屏幕，也未调用收费模型 API。AI 与来源接入的既有真实模型验证见 [来源验收记录](sources-validation.md)。

## 工作区回归

- TypeScript 全工作区与脚本类型检查通过。
- `npm test`：241 项通过（Mac 100、中央 76、Web 13、Agent 28、诊断 5、本地推理 13、共享协议 6）。最后两项 Mac 回归另行重跑该 workspace，100 项全通过。
- `npm run test:e2e`：生成的 Mac/Android 截图与心情笔记，经加密去重归档、真实 Harness + fixture 模型工具循环、证据读取及导出导入完成闭环。
- 隐私网关 22 项、真实 MCP SDK 的 stdio → HTTP 桥接、Tunnel 隔离进程回归及 Fact 归档 8 项通过。
- 中央管理界面在实际 Electron 中通过桌面/移动布局及诊断导出回归；更新状态只在访问配置页时读取，检查更新需主动点击。

## 更新信任链

共享协议使用临时测试 RSA 密钥覆盖清单篡改、错误版本/渠道/仓库、重复资产、错误镜像、公开 HTTPS 重定向边界与不发送中央凭据。下载覆盖截断、超长、错误散列、已存在文件和下载中出现的同名目标；失败不覆盖原文件，并清理自己创建的临时文件。

发布 workflow 经 YAML 与 actionlint 检查。私钥仅在 GitHub `release` 环境 Secrets 与本机受保护的恢复目录中；源码只含公钥和公开应用签名指纹。GitHub 环境的部署分支策略限定 `v*` 标签。正式发布前要求各平台构建、测试和产物身份检查均成功。

## 中央节点

HTTP 更新接口覆盖认证、请求合并、关闭取消、固定错误信息、旧部署不生成可执行命令，以及拒绝从请求传入命令/路径/仓库/凭据。接口不执行部署操作。

部署脚本验证签名中的镜像 digest、源码归档边界、当前运行版本、独立构建目录和 profile 隔离。真实本地隔离服务进程完成升级、健康检查、快照回退，验证生成的笔记、加密图片、原配置与访问凭据保持一致；回退保留当前连接授权与选择，并重置同步游标。

更新脚本 11 项通过（9 项单元/工具边界，2 项实际进程），覆盖备份失败后恢复原服务与原先停机保持停机。[GitHub Checks 34797367104](https://github.com/utopiafar/mote/actions/runs/34797367104) 已在 Linux 上通过完整回归与实际 Docker 私有连接器移交、权限、同 tag 镜像回退和 Tunnel 测试；本机未运行 Docker。

实际 macOS 原生助手对临时生成的 App 完成原子替换、相同 profile 重新启动、启动回执确认、无回执自动回滚、重新 ad-hoc 签名的篡改候选拒绝、其他 profile 阻止安装及中断事务恢复；15 份生成的设置/凭据占位/草稿/队列/模型文件逐字节保持一致。

0.5.0 arm64 打包通过，真实 ZIP 经安全目录检查，App 经 codesign、架构、版本与完整文件树验证。打包环境中的共享发布协议和更新模块能加载，千问对生成白图的实际 CPU 推理返回 `allow: true`，约 7.48 秒。独立 Electron profile 验证更新渠道 IPC、来源与随手记界面，采集保持停止。此轮没有把程序装进日常 App 路径。

40 项 JVM 测试通过。专用 API 35 模拟器使用项目同一签名身份，从正式源代码的 0.5.0 / code 6 经真实 PackageInstaller 会话和系统确认安装私有 code 7 测试包；PackageManager 读回 code 7。设置、deviceId、队列、草稿、模型在升级后逐项散列相同。

仪器测试覆盖 APK 安全校验、更新界面、安装前取消竞态、系统会话提交与升级后状态保持。此前本机 code 7 fixture 不上传到 GitHub；正式发布版本为 0.5.1 / code 7，产物由 GitHub CI 重新构建签名。模拟器对相同版本码必须拒绝重复覆盖。

## 验证边界

Mac 的 ad-hoc 分发无法证明 Apple Developer ID、公证或跨签名版本的系统授权连续性；正式签名流程必须在维护者提供有效 Apple 凭据后单独验收。Android 模拟器不能替代 K90 Pro Max / HyperOS 真机的安装提示、后台恢复和权限行为。应用数据不重置与操作系统可能要求重新授权分别处理。

本轮没有重启日常中央节点，也没有在用户日常客户端执行覆盖安装。生产环境更新应按 [更新说明](updating.md) 使用原 profile 和数据目录。
