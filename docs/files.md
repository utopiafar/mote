# 文件归档与中央处理

中央文件处理使用 Cordis，支持本地多人录音、说话人分离、导出和人工复核。部署与扩展说明见 [中央文件处理](file-processing.md)。

实现与扩展设计见 [文件同步设计](file-sync-design.md)，实测记录见 [文件同步验证](file-sync-validation.md)。

## 当前行为

- Android 使用系统文件选择器授权目录。录音原样上传，成功确认后仅清理 Mote 暂存（内容加密可选），保留手机原文件。
- 来源删除只记录“原位置已不可见”。中央保留已归档的原件、历史版本、转写和摘要。它不能证明原文件确实被人删除，也可能是移动或提供方变化。
- **原件归档**保存精确字节；**引用 / Shadow**只保存名称、路径、大小、时间等元信息，不打开正文，不计算原件散列，不生成内容摘要。
- 现有文本快照、日历、MCP 导入保持原协议。统一的来源与版本模型支持后续 NAS 常驻扫描器；当前尚未提供 NAS 二进制同步客户端。
- 原件独立于处理任务。未配置转写服务、格式不支持、模型失败时，归档成功仍然有效。

## 手机设置

打开“日历与文件”，选择“选择录音目录 · 原件归档”，用 Android 系统选择器授权录音目录。

每个来源可以设置扩展名、排除路径、扫描间隔、保存方式及首次同步范围：

| 配置 | 行为 |
| --- | --- |
| `all`，默认 | 分批导入所选范围的已有文件，然后同步新增及变化版本 |
| `new_only` | 第一次完整扫描只建立基线；只上传之后首次出现的文件，已接入的新文件仍跟踪变化 |
| 从 `new_only` 改为 `all` | 补归档基线中的旧文件；已经确认的版本不重复归档 |

“只同步新增”不是简单按文件修改日期截断。跨扫描页、重启仍保留基线。初次扫描期间新出现的文件可能进入基线；基线文件的后续修改也不会自动接入，需改为 `all`。

文件上传遵守 Mote 现有手动、实时、定时或批量同步策略，以及 Wi-Fi、充电和电量条件。每个文件需要连续 60 秒元数据稳定；暂存前后再次核对大小、修改时间和文件身份。Android 提供方若在字节变化时仍报告完全相同的元数据，无法据此保证录音已经结束。

### 首期容量边界

| 项目 | 边界 |
| --- | --- |
| 原件 | 每文件 512 MiB；超过上限可用 Shadow |
| 传输块 | 4 MiB；每次后台派发最多上传 2 块 |
| 手机文件暂存 | 合计 1 GiB；每来源同时暂存一个原件 |
| 扫描 | 每片 200 个条目，保存目录游标后续跑 |
| 清单 | 每来源 50,000 文件、深度 32、待遍历目录 10,000 |
| 来源数 | Android 现有上限 20 |
| 文字提取 | UTF-8 `text/*`，每文件 2 MiB；另有内置 PDF/DOCX/XLSX 文档解码，受各格式上限限制 |

待同步标记与当前上传项单独持久保存，计数和逐文件确认不会反复解密整个目录。权限或提供方异常不作为来源删除；源目录操作与中央遗忘是不同操作。手机强制停止应用后，后台恢复仍受 Android 系统规则约束。

## 中央处理设置

在中央网页“资料库 → 文件 → 中央文件处理设置”中配置：

- 是否启用中央文件处理；新上传录音默认在本地转写并分离匿名说话人，普通文件图片默认仅归档。
- 转写服务 URL；默认 `http://127.0.0.1:9009/transcribe`，表示中央机器本机服务。
- 可选服务密钥；只存在中央私有配置文件，读取设置不会返回密钥。
- 远端服务需明确启用并使用 HTTPS。更换地址时必须清除或替换已有密钥。
- 摘要与语义步骤按所选方案配置。严格本地多人录音不自动调用云端摘要或云端向量；其他方案可选择独立模型或继承中央模型，见 [类型策略](file-processing-policies.md)。
- 单文件音频最长默认 120 分钟，可在设置中改为 1–1440 分钟；不设每日音频时长限额。处理超时默认 10 分钟，可调整 `timeoutMs`。

配置保存在中央数据目录的 `file-processing.json`。配置修订会终止旧转写请求；旧结果不能写回新配置的任务。临时转写失败退避重试，最多 4 次；摘要可单独重试，无需重新上传原件。

### 可选本机 Whisper 服务

安装固定版本依赖、FFmpeg 并预先准备模型。最新启动命令、多人说话人分离、本地模型配置及持续运行的服务模板见 [中央文件处理](file-processing.md#在中央主机启动本地服务)。

仅英文 tiny.en 合成录音属于链路验收；中文、嘈杂环境、长录音仍需对应模型与样本验证。

### 自定义转写实现

中央向配置的 URL 发送 `POST`，正文为原始音频字节：

```text
Content-Type: application/octet-stream
Content-Length: <原件字节数>
X-Mote-Max-Audio-Ms: <本次剩余时长预算>
Authorization: Bearer <可选密钥>
```

返回严格 JSON：

```json
{
  "durationMs": 12774,
  "segments": [
    {"startMs": 2240, "endMs": 6000, "text": "示例转写", "speaker": "可选说话人"}
  ]
}
```

时间必须有效并有序，空 `segments` 表示识别未得到语音。最多 50,000 段，每段最多 8,000 字符，响应最多 32 MiB。服务应先测量音频实际时长并遵守预算；中央还会验证返回时长。也可实现服务器 `TranscriptionProvider` 接口，在自己的启动程序中注入。

## 分层、检索与使用

1. **原件 / 引用**：来源、不可变 revision、相对路径、散列及可用性。
2. **转写 / 提取**：独立 artifact 与 chunk UUID，音频片段带时间范围，保留原件不变。
3. **索引**：FTS 全文检索；配置现有 embedding 服务后，片段也进入向量索引。
4. **摘要**：以已读取的片段 ID 为依据的模型产物。
5. **记忆**：沿用现有“提议 → 查看证据 → 发布”流程，模型产物不当作独立原始事实。

Agent 和只读 MCP 可用 `file_chunks` / `mote_file_chunks` 逐页展开转写。模型必须先发现文件，引用必须来自本轮已读取、仍有效且在选定设备与时间范围内的片段。工具不会自动打开来源 URI 或临时拉取 Shadow 正文。

网页可按来源、文件名/相对目录及音频/文本类型查找。摘要引用可以打开对应片段；音频通过短期、限定到单个文件的 HttpOnly 凭证回听，支持 Range 请求和定位时间。浏览器不支持某编码时下载原件；自动生成播放转码副本尚未实现。

重新提取产生新的产物版本，旧索引不再参与当前检索。中央显式遗忘会删除该文件的全部归档版本与派生层，并阻止离线重试恢复；共享字节在其他文件仍引用时保留。旧问答、记忆和洞察使用现有保守的失效策略。物理无引用对象经回收宽限期移除。

## 协议与存储扩展

`/api/file-sync/v1/capabilities` 公布协议、大小与块限制。首次接入旧来源可读 `/head` 获取现有 revision 锚点；已暂存的 revision 不自动改写。

原件：创建 `/uploads` 会话，按服务返回的已确认块续传 `PUT /uploads/:id/parts/:part`，最后 `POST /uploads/:id/commit`。服务重算整文件 SHA-256 后，将原件引用、版本、处理任务与 ACK 一起提交。ACK 丢失时可重复提交；会话回收后，相同已归档 revision 也能直接得到确认。

Shadow 和来源消失：`PUT /revisions`。携带前驱 revision，中央拒绝乱序覆盖。来源授权、排除规则、去重、传输和保留使用确定性代码；正文含义交由模型判断。

私有文件对象存于 `files/objects/<sha256>/<part>`。显式开启内容加密后逐块 AES-GCM 加密；单独设置 `MOTE_DATA_KEY` 不会开启加密，见 [内容存储](content-storage.md)；数据库保存元数据、转写和索引，因此仍需要保护数据目录和磁盘。未完成上传 7 天过期；客户端保留暂存并可重新建会话。

## 备份与恢复

含文件归档的资料库不支持旧 JSON 全量导出，避免产生缺失原件和派生层的备份。先停止中央节点，使用：

```sh
npm run backup -- --data /absolute/data --out /absolute/new-backup-directory
```

备份包括 SQLite、引用中的图片及文件块、转写/摘要/记忆和校验清单；不包括密钥、连接令牌、ASR 服务配置及未完成暂存。恢复到空目录，重新配置服务与配对，并保留原加密数据密钥。恢复库清除未完成上传会话，手机会用自己的暂存重新开始传输。

## 自动验证入口

使用独立包 `dev.mote.collector.filefixture`，避免更新日常开发包。详细命令和已执行边界见 [验证记录](file-sync-validation.md)。

`scripts/file-sync-fixture-server.ts` 启动独立 loopback 中央节点；显式设置 `MOTE_FILE_TEST_MODEL_ENV` 才读取已有模型配置。`scripts/verify-file-sync.ts --live-model` 才启用真实模型调用。生成报告与凭据都置于忽略的 `.mote/` 目录，不能加入版本控制。
