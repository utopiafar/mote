# 文件归档与中央处理

文件先可靠接收，再分别整理、解析、索引和生成Memory。缺少模型或处理失败不影响已经归档的原件。[处理参考](processing.md)说明当前FunASR、OCR及插件组合；[资料参考](materials.md)说明版本和授权。

## 保存与首次范围

Central 新文件来源默认长期归档原件，不设资料总量配额，也不按天自动删除。已有来源的明确选择保持不变；仅保留解析内容和仅引用位于高级选项。本机默认与清理路径的剩余差距见[架构](architecture.zh-CN.md#产品方向与实现差距)。API 文本来源显式使用的快照层不等同于文件原件保留策略。

| 方式 | 实际发送与保留 |
| --- | --- |
| 原件归档 | 发送完整文件，保留精确字节与可选派生产物。 |
| 内容快照 | 仍发送完整文件供Central解析，长期保留获准内容；原始输入在处理成功或显式取消后释放；排队、进行中、失败或仅暂停来源时不因时长删除唯一输入。 |
| 引用 | 不读正文、不计算原件内容散列、不转写；保留标题、位置和实际可得元信息。 |

未完成上传持续保留，以便重启后续传；完成确认后只回收其传输副本。 手动导入的分块 ACK 同样只确认该块已持久保存，不代表整个文件或导入已完成；未完成输入不按 24 小时删除。`import-uploads` 在完整 `ArchivedFile` 和 `fileId` 回执持久保存后释放分块，后续导入消费该归档原件；创建导入失败或尚未交接时，回执与原件继续可重试。暂停来源保留已获准读取的解析正文，读取仍须通过当前来源和版本检查。磁盘或 SQLite 实际写入失败不会触发原件或待传输入淘汰。

同步先做单向归档。上游删除、移动或不可见不连带清除Mote副本；通用双向同步有实际需要再扩展。明确修改源内容仍需对应工具和授权。

所有者删除中央文件归档时，删除同一`sourceId/externalId`当时已归档的历史及撤回当时已接纳的在途版本，不删除采集端原件，也不暂停来源。已删除的不可变`revision`在重试、重启或旧设备队列恢复后仍拒绝归档；以后按原授权观察到的新`revision`可以继续保存。同字节的其他来源保有独立身份和资产引用，删除一处不会删除另一处仍引用的字节。

这与明确“遗忘该文件”的内部`forget`合同不同：明确遗忘还会屏蔽该文件未来版本，直到所有者`allowAgain`；允许以后接入也不会恢复已经删掉的旧版本。普通历史删除不写这种未来屏蔽标记。明确停止后续采集沿现有来源启停和授权范围控制；原件/Memory及对话依赖仍沿各删除入口原有的撤回方式处理。

文件夹默认持续检查选中范围；单文件默认一次导入，可明确选择跟踪后续修改。一次导入固定本机快照后，重启和重试继续同一版本。来源说明是版本化背景，作用于已有及未来资料，但不直接生成个人事实或自动重跑历史收费任务；单次Web导入说明只用于该批。

通用模型导入沿用本批已填写的命名、日期、来源主体和有效约束。例如已说明文件名前八位是日记日期时，可保留日期推断及其依据、主体、不确定性和可修订性；原文与原始时间戳保持分开。缺少精确钟点或时区不必阻塞日常低影响整理，`observedAt`仍是来源实际观测时间，未知时使用导入时间。固定Source Pack按其已选解析合同运行，导入说明仍作为该批资料的背景保留。

自动处理由解析方明确判断是否存在需要确认的关键缺口，并说明依据与后果。低后果、易纠正的解释可先保存，低置信度、非关键提醒或合法排除配置文件本身不强制确认；主体、内容或其他关键依据缺失时等待补充。显式选择预览始终等待确认。宿主仍检查授权、路径、原件、版本、格式、逐文件清点和有效产物；不完整或不支持的解析如实显示，零有效记录且无媒体处理任务不能发布成成功导入。

首次历史支持`all`和`new_only`。`all`分批纳入所选授权范围的已有文件；`new_only`先保存完整扫描基线，只接入之后首次出现的文件，并跟踪已接入文件的变化。它不是按修改日期截断。改为`all`可补归档基线旧文件，已确认版本不重复发送。

## 客户端同步

Android用系统选择器授权目录；Mac用原生文件/目录选择器。文件需要稳定后才暂存，读取前后复核大小、修改时间和身份。当前持续扫描的稳定等待为60秒；提供方在字节变化时仍返回相同元数据，不能据此保证录音结束。权限丢失、扫描失败或不完整结果不作为删除证据。

文件身份、不可变revision、内容散列、上传分片和确认收据共同支持幂等续传。原件归档不再设置512 MiB或普通文件64 MiB容量门槛；固定分片为4 MiB，每次请求和保存都只消费有限分块。协议的`sizeBytes`、分片编号及偏移必须是精确安全整数，`maxFileBytes = Number.MAX_SAFE_INTEGER`表示JSON/JavaScript的精确数值边界，不是新的产品容量配额。实际磁盘和文件系统能力仍决定能否写入，失败保留未确认输入。成功确认只释放对应Mote传输暂存，不删除手机原文件。

续传状态按最多256条分块收据分页，客户端逐页核对同一上传身份、顺序、散列、实际字节数和下一页游标；不会把整个文件或全部收据读入内存。Android新建文件来源的“单文件上限（MiB，0 为不限）”默认0，已有明确规则保持原值。端侧其余队列总量与清理差距仍见架构说明。

中央同步head会保留已删除归档的最后版本标识，作为新版本前驱，不授予读取旧正文的权限。没有可读旧文件的既有生产者也可用`previousRevision:null`提交未撤回的新版本；仅当前持久head确已删除时接纳，实际写入前复核同一前驱，普通活跃head和错误的非空前驱仍冲突。Mac二进制队列收到明确410时按该版本隔离并保留原输入，不伪造确认，也不阻塞后来的新版本；403、409、网络和取消结果不按已删版本处理。

上传会话在中央持久绑定当时的来源`syncScopeVersion`，每次续传和实际提交都复核。中央已知范围代次变化后，旧会话在重启或策略改回后仍不可写；当前授权重新接纳时创建新会话身份，旧的未确认输入继续保留。没有授权pin的旧会话不会被默认当作当前授权。这一边界只识别Central已知的范围代次；端侧本机路径选择的范围筛除仍由后续Mac/Android对齐单元处理。

整体进度区分等待稳定、排队、正在保存、正在上传、失败重试与需处理。分母只统计已清点且在发送范围的版本，扫描未完时说明仍会增长；旧版本回执不算新版本成功。正在上传来自实际进程，不能把重启后的暂存状态显示为仍在传输。Central接收、整理和索引另行显示。

统一的手动、实时、定时、批量策略及网络/电量限制见[采集与同步](collection-and-sync.md)。暂停来源保留待传版本；更换节点不能把绑定旧节点的内容静默改投。源端删除观察只表示原位置不可见，归档历史仍保留。

## 处理与阅读

中央设置的文件策略选择仅归档、本地转写或已配置处理器。新录音当前默认使用Fun-ASR-Nano-2512、FSMN、CAM++和CT-Punc；模型缺失时等待安装，没有自动云端回退。语音依赖、模型与Worker状态分别检查，见[媒体服务](media-setup.md)。普通文件图片与截图OCR有独立策略。

归档接收与解析能力独立。手动Web/Android导入先保存原件；后续预览因格式、展开、解析或模型预算拒绝时，保留实际`fileId`、失败说明和可读取原件，不把归档成功显示为处理完成。仅返回整块Buffer的读取仍有512 MiB内存预算，便携JSON原件总量仍为512 MiB；原件下载和范围读取使用流式接口，完整恢复使用离线备份。解析容器64 MiB、导入准备256 MiB及各模型/解码预算继续适用。

原件、原始转写、匿名分人、清理稿、人工修订、摘要和Memory分别保留来源和版本。匿名标签不代表真人；只读模型可按需读全文、精确片段或原件。解析完成不等于完整Memory评估，也不证明模型质量。修改配置不自动重做完成历史。

删除Memory只删除推导结果；删除原件或整次导入按对应依赖范围处理，保留其他来源/任务仍引用的资产。普通到期与明确彻底忘记的产品方向见[Memory](memory.md#publication-deletion-and-replacement)。完整恢复使用停止服务后的[备份](deployment.md#备份恢复和迁移)，不能把JSON导出当全部运行状态。

## CLI导入与环境

从仓库根目录先按[开发入口](development.zh-CN.md)安装依赖并构建所需库；预览`npm run import:files -- --help`，通过明确的来源、目录和连接参数导入。令牌放在私有配置，不直接写进命令历史或仓库。Dev/Test用隔离资料目录，CLI接收结果与Central处理结果分别核对。

具体传输字段见[协议](protocol.md)，实现入口包括[文件同步客户端](../packages/shared/src)与[服务端](../apps/server/src)。验证按[规范](testing.zh-CN.md)选择受影响路径；编译或生成夹具不能替代真实文件提供方和设备验收。
