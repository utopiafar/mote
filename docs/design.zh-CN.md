# 设计

[English](design.md) · **简体中文**

[产品](product.zh-CN.md)的体验与设计原则。当前实现见[架构](architecture.md)。

先呈现用户的内容和结果。页面安静、克制，交互自然、有温度。

## 交流与呈现

- 默认直接、简洁地回答。复杂任务按需要使用列表、表格或报告，不固定套用“结论、依据、下一步”。
- 来源与执行详情只提供非常轻量的查看入口。感兴趣的用户可以打开或继续追问，页面不默认铺开大量论据。
- 个人助理采用单一主对话，长任务不阻塞继续交谈；资料浏览、记录、采集和设置保留直接入口。用户不必先选择只读或行动模式。
- 处理中支持补充与纠正，优先调整相关工作。纯记录给轻回执，连接发起的「认识我」在聊天显示进度和结果。
- 已明确授权的操作保持连续。需要询问时，说清具体对象、缺少的信息或变化的后果。
- 后果轻且容易纠正时作合理判断，先给有用结果；确实影响当前目标的关键假设再轻量说明或澄清，避免机械的保守套话。
- 主动帮助由模型结合当前任务、用户指令和有效记忆判断，允许安静更新或没有新建议。静音、关闭通知及明确的“不再提醒”持续有效。

## 真实状态

接收、处理、索引、记忆与行动完成分别表达。结果未知时如实说明，不把请求已接收或草稿已生成当作执行成功。缺少观察不当作没有发生，历史内容不冒充当前状态。

## 界面与组件

沿用既有暖石墨、紫强调与浅色／深色／跟随系统的视觉体系。复用现有导航、用词、组件和共享样式定义，具体数值以代码为准。

跨端保持信息与操作语义一致，输入、文件选择、权限和触控等交互遵循平台习惯。此页说明现行设计原则，具体布局和数值以代码为准。

### 导航

日常入口依次是聊天、动态、点子、目标、资料库。记忆、技能、连接和设置归在管理组。Web 和 Mac 主窗口使用侧栏，Android 底部放五个日常入口，管理组收在「m」菜单。默认进入聊天，搜索与操作放在各自的内容旁。

MVP的Android保留原生常用媒体阅读、回听和文字纠正；高级说话人复核、原稿对照和模型准备通过轻入口直达同一Central的Web，保留当前对象和授权。这是已定范围，当前入口覆盖见[架构](architecture.zh-CN.md)。

## 界面文字

- 页面不放副标题、引导段落和解释边界的句子。需要文字才能看懂，就改布局。
- 正常状态不显示。异常时写「对象 + 状态」，最多带一个操作。
- 禁用句式：不是…而是、不代表、不等于、只表示、并不意味着。
- 长度上限：按钮 6 字；标签和筛选 8 字；状态 16 字；空状态一句 12 字；错误 24 字，加一个操作。
- 删除、外发、付费这类承诺文案保持原意；要缩短的逐条经所有者确认。
- 服务端只返回状态码和数据，不返回给人看的说明；文字由客户端用短标签呈现。
- 测试断言状态和可用操作，不逐字断言说明文案。

`npm run check:ui-copy` 全量检查词条的禁用句式、超过 24 个汉字、单独的「请」和结尾箭头，也检查 Web 和 Mac 隐藏标记中的单字符图标以及中央源码中未通过 `moteText` 的中文。检查按文件、声明及完整内容识别一条已核准的内部模型示例。各类控件的长度由评审和截图核对。承诺文案的长度例外列在 `scripts/ui-copy-promises.json`。

## 展示扩展

主题包提供精确版本的角色数据，布局描述平台支持的导航与详情偏好，由可信平台renderer通过共享展示宿主绑定。缺失供应方回到固定内置选择并说明原因，不按安装顺序选实现。新renderer随可信平台构建发布，不执行任意远端UI代码。

展示变更保留内容节点、草稿、选区和导航；注册的生命周期作用域在挂载中途失败时也释放事件和定时器。浅色/深色/跟随系统是浏览器、profile或安装本地选择，不改变采集、模型或来源授权。具体合同见[共享宿主](../packages/shared/src/ui-presentation.ts)与[插件贡献面](plugin-surfaces.md)。
