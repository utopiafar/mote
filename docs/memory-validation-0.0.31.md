# Memory 生命周期验收（0.0.31）

验收日期：2026-09-17。只使用生成数据，未读取或上传个人截图，未进行 Android 真机采集检查。

## 数据与成本边界

主样本为 480 条虚构原始记录，覆盖 180 天、4 个设备、3 位人物和 4 个项目；另有 24 次修订、12 次重复上传和 8 次隐私删除，最终现行原文 472 条。包含偏好变更、跨月决策、计划取消、未知结果、他人引述、矛盾陈述、迟到上传、提示注入与 Unicode。没有运行 3 万条模型测试。

全部 472 条现行原文通过 fixture 模型回放；真实模型只检查关键子集。另有 502 条短文本的纯本地 FTS 边界回归，用于验证旧的 500 候选截断漏洞，不调用模型。

## 确定性验证

- 合并最新主分支（含 0.0.30 的 Coding Agent 与日历动作功能）后，`npm test` 676 项通过：Desktop 217、Server 286、Web 49、Agent 76、Diagnostics 5、Local inference 13、Shared 30。
- `npm run typecheck`、共享库构建、Server/Web 构建通过。
- `test:e2e`、`test:media-e2e`、`test:privacy` 通过；前两项经过真实 DeepSeek Harness 与 fixture provider，隐私网关含 22 项生成样例。
- 实际 Electron renderer 运行网页导航、设置保存、持久对话及重启/失败恢复、日历动作审阅、桌面/移动宽度测试并生成截图，通过。没有对个人屏幕进行截图。
- 新增回归覆盖 AND 门槛、重启、并发到达、失败窗口重试、单次执行、分页、旧记录的范围检索、中文短词组合、原文修订与删除、摘要失效、引用位置和派生依赖。
- Coding Agent 上传纳入统一生命周期，不再停写 60 秒便独立启动模型。按明确来源元数据保留 session/project/profile 分批；混合长期整理按领域保留适用条件、验证状态和原始引用，部分失败只重试未完成领域。
- 本地原生桌面打包因尚未准备固定版本 llama.cpp 源码而未完成；平台打包、原生辅助程序和签名资产由 Release CI 执行。物理设备采集没有在本轮验证。

## 真实模型验收

本地 Codex App Server 实际列出并使用 `gpt-5.6-luna`、`max`。临时 loopback adapter 仅提供推理，检索由 DeepSeek Harness 的只读工具执行。隔离临时配置与会话，复用已有登录认证，禁止 Codex 原生工具；记录中原生工具调用为 0。该 adapter 不是新增生产 provider。

| 场景 | 结果 |
| --- | --- |
| 4 条关键原文的事件提取 | 3 条有效候选；项目变更、程序步骤、取消安排均保留不确定性和原始引用 |
| 长期整理 | 3 条待确认候选；没有把单项目数据库选择泛化为通用偏好，没有覆盖原记忆 |
| 跨月 FTS 问答 | 找到 3 月 SQLite → 8 月 PostgreSQL 的变更；取消不能视为完成；林岚的清晨偏好不能归给陈禾 |
| 工作摘要 | 18 轮对话压缩保留“仅合成数据、480 条、模型调用预算”等变更，近期轮次继续逐条披露 |
| 增量洞察 | 先读取 12 条增量，再检索历史；正确区分到达/发生时间、采样时长/全天工作量、流程/实际执行、冲突陈述/事实 |
| 删除传播 | 原文删除后依赖记忆、洞察和工作摘要清除 |

最终成功轮耗时 632 秒，新增 13 次 provider 调用，App Server 汇总 token 为 519,844（包含每次请求重发的上下文，**不是价格或整个调试过程的总费用**）。其中提取和整理复用先前已实际生成并验证的输出，避免重复推理；其余问答、工作摘要和洞察在该轮新生成。之前为排错进行过失败调用，不包含在这 13 次之内。单轮限制为 20 次 provider 尝试和 15 分钟，不能据此声称全过程只调用 20 次。

合并最新代码后，将已保存的真实输出通过当前提取管线、长期整理调度器、摘要与洞察持久化重新回放，六个阶段均通过，新增模型调用 0 次。这是离线回归，不是另一轮真实模型生成；新合入的编码领域整理使用 fixture 验证，未追加编码场景的 luna 真实调用。

## 排错记录和边界

1. 配置允许长推理时，底层流读取仍在 30 秒空闲后失败。现已尊重模型超时配置；对真实输出进行 35 秒延迟的 Harness 重放通过。
2. 模型曾只反复搜索记忆，遗漏尚未提取的原文。已在工具返回与指令中明确记忆索引的覆盖边界，并引导回退原始 FTS。
3. 连续中文中的多个短词（如“林岚 清晨”）曾漏检。已统一原始记录与文件块的逐词 AND 检索，长词走 FTS，短词支持字面匹配；重测能找到原文。
4. 发布前复现已有浏览器回归：查询失败提示缺少 alert 语义，检查无法识别失败状态。已修复告警角色，持久对话完整 smoke 重跑通过。
5. 合并主分支时发现新加入的独立编码记忆队列会绕过统一频率配置，已移除该自动入口，并回归旧队列原文仍可从持久增量日志处理。

这些样例证明本轮具体场景通过，不代表任意数据或所有模型都会作出相同语义判断。记忆保持待确认；文本原文、引用与不确定性可逐层展开。当前规范存储为 SQLite 中可读文本与来源元数据，FTS 为可重建索引，每条可导出 Markdown；没有第二份独立可编辑的 Markdown 目录。

## 复现

```sh
npm run build:libs
npm test
npm run typecheck
node --import tsx scripts/memory-live-eval.mjs
```

真实测试默认将生成数据报告写到 `/private/tmp/mote-memory-live-report.json`，临时库和隔离 App Server 会在结束后清理。`MOTE_MEMORY_REPLAY_EXTRACTION`、`MOTE_MEMORY_REPLAY_CONSOLIDATION` 可指定先前保存的生成结果；同时设置 `MOTE_MEMORY_REPLAY_ALL` 为成功轮报告路径时，所有阶段仅离线重放。用 `MOTE_MEMORY_REPORT` 指定单独的回放报告位置，避免覆盖真实报告。报告与认证材料不进入源码。
