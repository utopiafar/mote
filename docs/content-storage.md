# 当前内容存储

当前中央资料库使用 `backend_epoch=7`，Android 与 Desktop 本机格式为 4。MVP 阶段仅支持当前格式，不自动迁移旧格式，也不会自动清空旧资料；未来面向长期使用时，需要提供保留资料的升级处理。当前旧库处置见 [MVP 基线 ADR](product.md)。

## 客户端

Android 与 Desktop 的采集内容、图片、队列和来源索引按原始字节保存在应用私有目录；旧内容加密开关、AES 内容包装读取及批量解密迁移已删除。Desktop 连接凭据仍由系统 safeStorage 保护；Android 凭据及单独的中央私有草稿/ledger 继续使用 SecretBox。不要把这些当前凭据保护当作退役的内容格式兼容。

Mac现有事件／图片存储同时保留正式采集内容及每条真实ACK的原Central身份；待发送投影只选择未确认记录。会议音频保留在独立目录，不随ACK删除。文件来源的分块仍是待传暂存，准确整件ACK后释放；本机策略隔离的未确认输入持续保留。Mac取消资料总量与条数配额，JSON备份及每请求资源预算独立保留。

所有者可在Mac内容详情中明确清理已获准确ACK的本机副本。现有事件／会议存储保留时间、来源、设备、接收时间、实际原Central及必要IDs，移除正文、OCR、内容元数据、截图或应用专有会议目录；不清未确认、复核／策略隔离输入和用户源文件。仍持有输入或无法解释的采集阶段checkpoint会阻止清理。已上传会议还必须有完整匹配的原ACK凭据（含SHA-256和字节数）；缺少凭据时保留本机原件，拒绝清理与另存，不推断或迁移补证。中途失败保留可重试的清理意图，不能冒充完成；重启不自动清理，也不把轻量记录重新上传。

轻量记录按当前连接许可经原Central现有归档API回读。不同节点不发送旧记录读取请求；断网、删除或撤权明确说明本机已无原件，同时保留时间、来源和接收凭据。会议原件经原生保存对话框流式另存，校验原回执身份、长度及已保存的散列；会话／节点／凭据及作用域代次变化阻止迟到正文和后续请求。当前JSON worker备份／恢复保留清理状态且不包含已清正文或图片，旧完整备份不能覆盖同ID已清记录；用户此前另存的备份属于独立副本。

已有非格式 4 本机数据会被明确拒绝，原文件保留。备份并确认未上传内容的处置后，由用户显式选择新目录或重置应用存储；启动不会清空旧队列，也不重新导入旧内容。

## 中央

中央内容加密策略由主 `mote.yaml` 的 `storage.contentEncryptionEnabled` 控制，默认 `false`。所有者开发者页面与手改文件通过 ConfigService 保存同一字段和全局 revision，提交成功后立即影响后续写入。旧 SQLite 当前设置和普通环境变量不再覆盖 YAML。单独设置 `storage.dataKey` 不会启用加密；显式启用时使用该 64 位十六进制密钥，未配置则生成权限受限的 `content-key` 文件。历史密文与密钥身份仍保留，转换配置格式不会转换或删除内容。

当前对象必须有 `.plain` 或 `.aes` 格式后缀。后续写入按策略选择格式；切换设置不会重写已有对象。当前 `.aes` 对象缺少正确密钥时拒绝读取并保留文件。所有者页面仍可在关闭后续加密后，对当前格式对象执行受控的批量解密；这是当前存储策略操作，支持进度、取消和再次运行。每个对象先读取校验，再原子替换，失败不会删除原件，全部成功前仍需保留密钥。

加密范围是截图和文件内容，SQLite 中的事件文本、索引及解析工作产物仍需依赖宿主目录权限与磁盘保护。HTTPS、访问授权、原件哈希校验和用户配置的隐私过滤继续生效。

原件以固定4 MiB分块保存，大小和偏移使用精确安全整数，不以512 MiB限制归档。上传确认状态分页读取，资产校验和工作元数据逐行消费；临时元数据在发布前删除，不改变当前持久分块格式。下载与范围读取流式消费，整Buffer读取及便携JSON仍有各自内存/格式预算，见[文件](files.md)。离线备份按块复制并流式计算校验和，恢复同时检查数据库引用、规范分块路径和完整清单；既有16 MiB备份清单读取预算仍适用，不是单原件容量配额。
