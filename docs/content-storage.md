# 当前内容存储

本次 MVP 断代使用中央 `backend_epoch=3` 与客户端本机格式 3。旧格式、旧密文包装和无格式后缀对象不自动转换；升级操作见 [兼容清理实施记录](audits/compatibility-cleanup-2026-10-04.md)。

## 客户端

Android 与 Desktop 的采集内容、图片、队列和来源索引按原始字节保存在应用私有目录；旧内容加密开关、AES 内容包装读取及批量解密迁移已删除。Desktop 连接凭据仍由系统 safeStorage 保护；Android 凭据及单独的中央私有草稿/ledger 继续使用 SecretBox。不要把这些当前凭据保护当作退役的内容格式兼容。

已有非格式 3 本机数据会被明确拒绝，原文件保留。备份并确认未上传内容的处置后，由用户显式选择新目录或重置应用存储；启动不会清空旧队列，也不重新导入旧内容。

## 中央

中央节点仍支持当前内容加密策略，`MOTE_CONTENT_ENCRYPTION` 默认 `0`，所有者开发者页面保存的选择优先于启动配置。单独设置 `MOTE_DATA_KEY` 不会启用加密。显式启用时使用该 64 位十六进制密钥，未配置则生成权限受限的 `content-key` 文件。

当前对象必须有 `.plain` 或 `.aes` 格式后缀。后续写入按策略选择格式；切换设置不会重写已有对象。当前 `.aes` 对象缺少正确密钥时拒绝读取并保留文件。所有者页面仍可在关闭后续加密后，对当前格式对象执行受控的批量解密；这是当前存储策略操作，支持进度、取消和再次运行。每个对象先读取校验，再原子替换，失败不会删除原件，全部成功前仍需保留密钥。

加密范围是截图和文件内容，SQLite 中的事件文本、索引及解析工作产物仍需依赖宿主目录权限与磁盘保护。HTTPS、访问授权、原件哈希校验和用户配置的隐私过滤继续生效。
