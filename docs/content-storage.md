# 内容存储与一次性批量解密

从 0.0.25 起，Android、Desktop 和中央服务端的内容加密都是可选项，默认关闭。客户端被视为用户信任的本地环境。开关控制后续写入，不会为了切换设置而阻塞整库重写；同一资料库允许明文和密文共存。

## 开关与转换入口

- Android：开发者设置中的本地内容加密，默认关闭。关闭并保存后，可启动一次性批量解密，覆盖采集区、待决定区、索引与缩略图、笔记草稿、来源内容、文件归档队列及去重报告。
- Desktop：设置中的本地内容加密，默认关闭。开发者页面可启动一次性批量解密，任务会关闭后续内容加密并临时暂停采集与同步，完成或取消后恢复原有运行选择。
- 中央网页：设置 → 开发者 → 内容存储。关闭加密后可启动一次性批量解密，处理截图、归档原件、已提交对象和未完成上传分块。网页本身不保存独立的资料库副本。

批量解密显示进度、成功与失败数量，支持取消和再次运行。每个文件先读取并校验，再写入临时文件并原子替换；读取失败不会把密文当作明文，也不会删除原件。取消在文件之间生效，已完成的转换保留。打开应用不会自动启动整库解密。

开启加密不会追溯加密原有明文；界面会明确提示只影响后续写入。

## 密钥与兼容性

Android 使用原安装的 Keystore 密钥读取旧内容。Desktop 显式开启加密时创建独立内容密钥，并使用系统安全存储保护密钥。默认关闭时不会为了明文内容创建新密钥。二者的访问令牌始终保留既有系统保护，不纳入批量解密。

中央节点 `MOTE_CONTENT_ENCRYPTION` 默认 `0`，开发者页面保存的选择优先于启动配置。仅设置 `MOTE_DATA_KEY` 不会开启内容加密。显式开启时可使用该 64 位十六进制密钥；未配置则在资料库中生成权限受限的 `content-key` 文件。已有密文且密钥缺失或不匹配时会拒绝读取，保留原文件。转换全部成功后才能解除旧密钥依赖；未完成或失败时仍需保留原密钥。

中央加密范围是截图与文件内容，SQLite 中的事件文本、索引等元数据一直以明文保存。此开关不表示数据库整库加密。所有端的 HTTPS、访问授权、应用目录权限和用户配置的隐私过滤继续生效。

旧 Android 文件名可能保留 `.enc` 等扩展名，不能仅凭扩展名判断内容是否加密。中央新文件分块使用 `.plain` 或 `.aes` 明确区分格式，旧格式继续兼容读取。升级和批量解密不改变记录 ID、内容哈希或资料所属位置。
