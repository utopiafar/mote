# ADR：Memory 按需读取原件上下文

> **状态：历史。** 本文记录当时的决定与验证范围，不再描述当前实现；当前设计见 [Memory 当前设计](memory-current-design.md)。

日期：2026-10-13。状态：采纳，所有者已确认实施。个人 v4 保留固定定义；当前个人 v5 的范围评估组合见[范围评估 ADR](adr-memory-range-evaluation.md)。

2026-10-14 的[简化决定](adr-ask-evidence-quality-and-simple-context.md) 取代下文的宿主字符阅读额度、初始证据数量裁剪与容量二分描述。当前提取和审核保留全部合法目标及已披露原句，按授权范围补读；实际资源失败保留原范围，明确临时故障有界恢复。

## 问题与决定

少量历史日记 Memory 在导入说明已经到达正式资料和覆盖成员时，仍将连续日记叙述者保留为身份未知。容量拆分后的末级目标没有原件开头的回顾年份，也截断了动作续文。独立审核使用同样的目标范围；授权目录只提供元信息，提取工具不能补读目录中的其他正文。引文坐标正确证明引用忠实，不证明主体、事件年份或结果完整。

不能仅以固定开头或邻接窗口代替模型对解释缺口的判断。新 Memory 任务保留原有目标范围与覆盖契约，另外固定同一任务原件中可供解释的只读范围。模型在提取和独立审核中，可用 `context_evidence` 按具体缺口读取这些原件；正文、声明及草稿仍是不可信证据。宿主检查权限、确切范围、版本和预算，不按关键词判断身份、年份、主题或完成状态，也不开放整库读取。

## 目标与读取范围

- `evidenceRanges` 仍是本批必须完整评估的目标，模型按固定策略决定候选。旧契约的容量拆分及新契约的资源拆分都保留目标覆盖、成功兄弟范围和旧检查点。
- `evidenceReadRanges` 是宿主冻结的解释范围；目录本身不表示正文已读，也不给未读范围引用资格。它只包含同一任务已经授权的原件，不能凭声明、模型输出或派生记忆扩大授权。只读工具返回实际披露的精确范围，未成功读取的目录项不成为本批上下文依赖。
- 同一原件可以同时参与不同配方。目标与读取目录保留创建时授权该范围的配方、审核策略和精确 Material 输入指纹；反馈重组仍沿用这些固定对应。共享原件 ID 或覆盖键不能把另一配方的输入要求附到本批，也不能替换其上下文。完整 Material 所需摘要失效时，独立就绪的正文配方仍可补读自己的正文范围；失效配方保留可见的失败状态。
- 模型选择能解决角色、年份、指代、纠正、计划状态或续文缺口的原件范围，重复使用已读正文。它不必读取全部目录，也不能因另一批已安排或未安排就宣称整份原文完整。
- 上下文原句可支持目标候选并被精确引用；单纯上下文不能产生独立候选、覆盖行或完成检查点。每个候选仍须有本批目标的直接支持。
- 提取实际读过的原句通常重新作为初始证据提供给独立审核。合并后的原句超过现有初始证据预算时，审核以原目标开始，并保留相同读取许可；模型通过 `context_evidence` 补读支持候选所需的原句。草稿中的引文和提取已经读取的事实，不证明审核也读过原件。审核可自行补读同一许可目录，不以提取草稿或其上下文选择为通过条件。宿主只接受运行器提供的实际披露范围收据，不接受模型在答案 JSON 中自报的读取权限；目标与这些读过的范围共同限定引文资格，不能填补未读间隙。
- 在保存私有提取草稿之前，以及独立审核完成后，宿主登记实际读取原件的批次依赖。删除这些原件会清除包含它们的可复用私有草稿；候选本身使用的原件证据进入 Memory 的纠正、删除及发布依赖。实际读取的版本、声明与权限仍在验证和提交时检查。只在目录里可读、实际未读取的另一份原件发生纠正或删除，不使本批独立目标失效；该原件作为自身目标时仍按原有规则处理。
- 沿用现有输入、工具结果、整次查询和输出预算。预算耗尽不代表没有材料；真正不能解决的依赖保留为具体缺口，不能反复请求未变范围来制造本人对应。
- 生成缓存对读取许可中的范围与原件指纹作确定性排序后计算哈希。相同固定许可仅因目录顺序变化时仍可复用；原件、权限、模型或策略发生相关变化时，仍须重新验证或生成。排序只用于缓存身份，不改变模型收到的目标、上下文或目录顺序，也不扩大旧任务的许可。

首次创建的新任务固定 `contextReadVersion: 1`，恢复、重启和拆分沿用该标记及原件读取范围。该标记与 `workContract` 分别固定：按需读取不会把旧配方升级为范围评估契约，范围评估也不会为没有读取标记的旧任务新增解释许可。既有任务没有此标记时保持原来的读取边界；安装新能力不为旧任务新增读取资格、不重放成功任务、不改写历史 Memory。手工任务的新读取范围仍由创建时已经选择和授权的原件限定，不能顺带检索整个个人库。

## 个人策略版本与解释

新增 `mote.personal-memory@4`，组合 `mote.personal-extraction@2` 与 `mote.personal-review@4`。保留个人 v2/v3、个人提取 v1、个人审核 v2/v3 和录音 v1/v2 的固定定义、指纹及历史产物。

新的个人策略结合宿主导入说明或来源说明与连续原文解释主叙述者。`unknown/default` 表示没有类别默认，不否定适用的文字声明。主要为本人日记、少量通话/咨询的说明，可在正文支持其日记范围时建立该日记主叙述者对应，不新增逐份身份确认或声纹要求。它不能把咨询另一方、引用、转述、被描述的人、助手文字或背景声音一并归给主人。导入说明仍只作用于冻结的新增原件及其谱系；来源说明的已有和未来范围不被借用。明确来源或单份纠正优先，真正不明或冲突的对应继续用有限观察表达。

事件年份可以由已读原件中明确的回顾区间与连续叙事共同支持。需要同时保留时间框架原句和局部事件原句，检查跨年、例外及纠正。录制或作者日期、回顾年份、事件时间和导入日期分别解释；照片回顾进度不把此前事件全部设为进度日期。有年份依据而月日不明时，不能为填写 `validFrom` 或 `validUntil` 补出完整时间戳。续文可补完或纠正动作；计划、猜测、转述与未见结果的边界保持。

## 默认与历史边界

上下文读取的具名 `context-reading-personal@4` 升级保留固定目标：仅替换精确匹配内置个人 v3 的普通默认，以及个人 v3＋日常事件 v1 的采集默认，作用于未来接收。范围评估组合随后将这些精确 v4 默认升为个人 v5，匹配采集默认中的日常事件 v1 升为 v2；完整顺序为 v2→v3→v4→v5。当前新库普通默认选择个人 v5，首次建立采集默认复制当时普通选择并追加日常事件 v2。已有来源覆盖和自定义组合不变。详见[范围评估 ADR](adr-memory-range-evaluation.md#versioned-policies-defaults-and-saved-work)。

既有 `bounded-personal@3` 迁移仍明确以 v3 为目标，不能因最新常量变化重定义旧迁移。未经历该迁移的旧内置 v2 默认依次升级，并保留 v2/v3/v4 已授权旧范围的执行资格；不创建新历史授权。迁移标记持久化，用户后来明确选回旧版本，重启不再次升级。显式默认或来源选择沿用原事务撤权和旧范围排除规则。历史重做仍需所有者明确发起；安装与合并不等于部署。

## 取代检查

| 类别 | 决定 |
| --- | --- |
| KEEP | 原件与 Material 版本、逐角色模型解释、冻结声明、精确引用、独立审核、目标覆盖、成功兄弟范围、授权撤权、隐私、预算、收费历史重做与提问/延后生命周期。 |
| CHANGE | 新任务把目标范围与解释读取范围分开；提取和审核按需补读同一任务的已授权原件；个人 v4 的叙述者与时间框架解释；具名未来默认升级。 |
| REMOVE | 新任务只能反复读取局部目标的限制；把片段缺少年份当成整份原件没有年份；仅因 default unknown 或声明包含少量其他材料而要求每段日记再次确认身份。 |
| EXCEPTION | 没有新标记的旧任务保持旧读取边界；旧配方与来源覆盖固定；多方发言、第三方转述、计划、猜测、模糊 ASR 及明确纠正继续逐项限定。 |
| UNKNOWN | 模型仍可能漏读或误解上下文；宿主声明不验证现实声音身份；有限样本不证明全库语义召回、ASR准确性、真机交互或未执行的模型质量。 |

本决定细化[批次上下文 ADR](adr-memory-batch-context.md)、[上下文与引用 ADR](adr-memory-context-and-canonical-evidence.md)、[有限个人 Memory ADR](adr-bounded-personal-memory.md)和[录音本人对应 ADR](adr-recording-coverage-and-owner-context.md)。旧任务与旧配方语义保留；只取代上表明确标为 CHANGE/REMOVE 的新任务行为。影响面包括任务持久化、拆分与恢复、Agent 只读工具及输入、引文校验、缓存与发布依赖、默认选择、策略版本、生成回归和当前行为文档。

## 验证

生成回归需通过正式 Material 与 Memory 入口覆盖目标/读取范围分离、主动补读与精确引文、上下文无独立覆盖、越界/失效/撤权拒绝、提取与审核独立补读、容量拆分、旧任务恢复、新版本默认和重启不重放。完整矩阵及运行证据记录在[验证文档](https://github.com/utopiafar/mote/blob/9c9a36e25355b1251aedbec2d5da89a63d8926de/docs/memory-context-reading-validation.md)。Fixture 只证明传输和生命周期，不证明身份与年份解释质量。

本轮实际模型旅程只使用生成原件、临时库及本地 Codex Server `gpt-6.1-sol`。所有者亦授权以中央资料副本作可选补充复验，但本轮未执行私人资料复验；它不是生成旅程完成的前提。实际调用、引文、逐条语义审读与最终宿主 fixture 的不同验证边界见验证文档。测试不修改中央成功 Memory、来源设置、保留或隐私设置；正文、运行记录和凭据保存在私有测试目录，不进入 Git。真实音频、ASR、声纹和物理设备检查另行报告。
